# Локальные артефакты Krasterisk v4

Сборки проверок, кэши, записи, снимки экрана, архивы и сырые результаты запусков хранятся вне checkout.
По умолчанию: `~/Documents/DevArtifacts/krasterisk_v4`. Переменная `ARTIFACTS_ROOT` задаёт другой **абсолютный внешний каталог**.
Пути внутри checkout, пути к его родительским каталогам и ссылки внутрь checkout отклоняются.

Канонические планы, SPEC/ADR, EXECUTION и короткие отчёты находятся в `docs/`; поддерживаемые проверки — `tools/` и `harness/`, синтетические входы — `tests/fixtures/`. В `.planning/` сохранены только локальные рабочие материалы. Подробные журналы переносов, исходные bytes и хеши лежат во внешнем `migration/`.

## Новые генераторы

Node.js:

```js
const { outputPath } = require('../../tools/artifacts/paths.cjs');
const fs = require('node:fs');
const path = require('node:path');
const run = outputPath('runs', 'my-check', new Date().toISOString().replaceAll(':', '-'));
fs.mkdirSync(run, { recursive: true });
fs.writeFileSync(path.join(run, 'result.json'), JSON.stringify({ ok: true }));
```

Python (запуск из корня проекта как модуля либо с корнем проекта в `PYTHONPATH`):

```python
from tools.artifacts.paths import output_path
run = output_path('runs', 'my-check', '2026-10-21-run-001')
run.mkdir(parents=True, exist_ok=False)
(run / 'result.json').write_text('{"ok": true}', encoding='utf-8')
```

В PowerShell можно загрузить `tools/artifacts/paths.ps1` и вызвать `Get-ArtifactsRoot`.
`artifactPath` / `artifact_path` предназначены для точечного перевода прежних путей ввода/вывода; политика — `policy.json`.
Они не подменяют глобальные filesystem API и не управляют размещением документов/исходников. После структурной миграции новые канонические пути задаются напрямую; удалённые пути `/opt/...` не перенаправляются.

## Перенесённые результаты

Старые результаты сохраняют структуру: `ARTIFACTS_ROOT/legacy/<путь-в-репозитории>`.
Игнорируемая `.artifacts` — ссылка на внешнее хранилище, чтобы относительные ссылки в Markdown открывались.
У перенесённых каталогов сборок/кэшей сохраняются игнорируемые совместимые ссылки на прежних местах: исторические читатели и команды сборки работают с теми же путями, физические данные находятся снаружи.
Зависимости внешних legacy-сборок доступны через отдельную ссылку `legacy/node_modules` на зависимости checkout.

Совместимые ссылки привязаны к хранилищу миграции. Переопределение `ARTIFACTS_ROOT` направляет новые генераторы в другое место и не переносит старые результаты автоматически.
238 legacy-генераторов переведены AST-проверенной адаптацией путей; ещё девять изменены точечно. Для остальных исторических потребителей сохранены совместимые ссылки. Сценарии с SQL/SSH/API/звонками для этой миграции не запускались.
CDR перенесён по явно подтверждённому пользователем списку: отдельные artifact routes и пять переданных генераторов. Произвольные CDR JSON не перенаправляются; authored fixtures, UI и source-snapshot деревья сохраняются. Два открытых r7o5 frontend лога остаются на месте.

## Команды и проверки

```powershell
npm run artifacts:root
npm run artifacts:setup
$env:ARTIFACTS_ROOT = 'C:\DevArtifacts\krasterisk_v4'
npm run artifacts:root
npm run test:artifacts
```

Для межъязыкового теста задайте `ARTIFACTS_PYTHON` абсолютным путём к Python 3.
`migrate.ps1 -Plan <manifest.json>` проверяет план без изменений; `-Apply` переносит перечисленные каталоги native PowerShell-командами, не перезаписывает существующие цели, сравнивает SHA-256 и оставляет журнал.
Обычный `npm run build` продолжает использовать штатные игнорируемые `packages/*/dist`: это текущий runtime приложения, его перенос не входит в миграцию экспериментальных сборок.

Сроки хранения пока не автоматизированы: миграция ничего не удаляет по возрасту.

Для отдельных перенесённых результатов на прежних местах остаются игнорируемые файловые символические ссылки. Они обеспечивают совместимость старых читателей и генераторов без массового изменения логики исторических сценариев. Новые генераторы должны использовать outputPath/output_path; ссылки привязаны к хранилищу миграции.

CLI для shell: `node tools/artifacts/paths.cjs --output runs <initiative> <run-id>` печатает проверенный внешний путь. Сам CLI не создаёт каталог; вызывающий инструмент создаёт его перед записью.
