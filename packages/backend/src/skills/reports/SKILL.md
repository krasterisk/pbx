# Журнал звонков

Одна запись — логический звонок компании, объединяющий доступные телефонные события. Чтение всегда ограничено текущей организацией, правами пользователя, доступными страницами и участниками. Знание ID не даёт доступ к карточке. Инструменты отчётности не изменяют журнал, маршруты и звонки клиентов.

## Выбери инструмент по задаче

- `search_calls`: поиск по реквизитам, телефону, имени сотрудника или отделу. Структурные фильтры направления, исхода, обработки, наличия записи и статуса анализа. OR внутри employees/departments/companyNumbers и AND между группами.
- `get_call`: карточка разрешённого звонка, понятная история и доступные материалы. Используй возвращённую ссылку `url`, не выдумывай URL из телефонного uniqueid.
- `summarize_calls`: агрегаты того же cohort, предыдущий интервал равной длительности, нагрузка по календарю организации и участие сотрудников/отделов/номеров. Период не более366 дней.
- `list_unreturned_missed`: пропуски и голосовые без подтверждённого обратного контакта, включая случаи с недостаточными данными. Период не более31 дня. Окно `policy.windowHours` настраивается организацией, по умолчанию24 часа; не подставляй24, если инструмент вернул другое значение.
- `find_cdr_calls` / `get_cdr_summary` — переходные алиасы search_calls / summarize_calls с той же новой моделью; поля старой сырой CDR-сводки не ожидаются.
- `resolve_call_employees`: разрешить имя/фамилию в любом порядке в подтверждённые идентификаторы сотрудников доступной истории. Однофамильцев не выбирать молча; not_found не доказывает нулевую активность сотрудника.
- `summarize_employee_calls`: точные счётчики и summary.totalConnectedSec всей выборки. «Сколько звонков сделала Мария Иванова и общая длительность» → employeeName="Мария Иванова", relationship="initiator", direction="out". employees/focusEmployee — участие; callerEmployee — инициатор. Длительность всего логического звонка, включая переводы, не выдавать за индивидуальное время сотрудника; unknown длительность не заменять нулём и не вычислять сумму из округлённого среднего.
- `summarize_call_conversations`: «общая сводка вчерашних разговоров Петрова Ивана» → employeeName="Петров Иван", period="yesterday", relationship="participant". Читать доступные саммари/метрики проекта, указывать coverage: содержимое ограничено20 новейшими звонками при полных счётчиках. Неполную подборку не объявлять полным анализом всех разговоров.
- `search_call_content`: «найди номер и с кем я разговаривал на прошлой неделе по поводу башенного крана» → phrase="башенный кран", period="last_week", mine=true, mode="semantic". Контакты, участники и ссылка/таймкод — из проверенной выдачи CDR. mine=true берёт номер текущего пользователя из доверенного контекста. При self_unmapped спросить сотрудника/номер, не расширять поиск на компанию. Ошибку/indеxing/недоступность не заменять «ничего не найдено».
- `get_call_analysis`: саммари и бизнес-метрики одного разрешённого звонка; текущие права аналитики и проекта обязательны. not_applicable и insufficient_evidence — явные состояния, не оценка0 или100.

## Как объяснять результат руководителю

- Направление: `in`, `out`, `internal`, `external`. Исход: `human`, `robot`, `voicemail`, `menu`, `missed`, `error`, `unknown`, `active`. Голосовое меню, робот и голосовая почта не равны разговору с сотрудником. Соединение само по себе не доказывает решение вопроса клиента.
- Время соединения и общая длительность — разные показатели. Сырой ANSWERED не является доказательством человеческого ответа; не восстанавливай такую метрику из disposition/billsec и не называй ASR качеством обслуживания.
- Разрезы показывают участие в целом звонке. Один звонок может попасть нескольким сотрудникам и отделам; суммы строк не складываются и не являются персональным рейтингом ответа.
- Связь обратных контактов по полному номеру клиента и номеру компании вероятная. Исходящая попытка, исходящее соединение и самостоятельный возврат клиента различаются. При ограниченной истории отсутствие найденного контакта не доказывает отсутствие реакции всей компании; unknown сообщай явно.
- Укажи период, часовой пояс, размер выборки, состояние источника и ограничения. При source unavailable не отвечай «звонков0». При неполноте/устаревании показывай оговорку рядом с числом.
- Календарные интервалы могут длиться23/25 часов; повторяющиеся часы различаются UTC-смещением и точными from/to. Предыдущее сравнение имеет равную фактическую длительность, а не обязательно равное число календарных суток.
- Для провала в журнал сохрани исходные фильтры; focusEmployee/focusDepartment/focusCompanyNumber/focusOutcome дополнительно пересекаются с ними. Используй возвращённые ссылки и доказательства, не домысливай скрытых участников.

## Поиск ограничен

Для сводки разговоров дочитывай страницы `summarize_call_conversations`: при непустом `nextAnalysisOffset` повтори запрос с `analysisOffset` из ответа и теми же фильтрами. Объединяй по `callId` без повторов. Продолжение покрывает доступные разборы среди20 последних звонков; полный счётчик выборки не означает, что содержание всех разговоров прочитано.

`search_calls` отдаёт не больше50 строк (по умолчанию20). Если результат обрезан, сузь период/фильтры либо отправь пользователя в журнал. Не перечисляй неполную выдачу как весь архив.

Без дат выбран текущий день организации; dateFrom/dateTo — включительно, from/to — точный полуоткрытый ISO-интервал со смещением. Пустые dateFrom/dateTo означают всю историю только для журнала, не для ограниченного обзора/внимания.

Эти инструменты не предоставляют расшифровки целиком. Поиск по тексту/смыслу использует тот же сервис и права, что журнал; сырые найденные фрагменты не передаются в chat LLM, только ссылка и таймкод. Для сводки используй доступные саммари проекта, без нового разбора старых текстов в чате. Не выдумывай цитаты, тональность и содержание разговора. Статус analyzed означает наличие результата анализа, не разрешение читать его текст. Отсутствие распознанных звонков ограничивает охват темы; это не доказательство отсутствия разговоров.

Относительные периоды задавай серверным period: today/yesterday/this_week/last_week/last_7_days/all_history. last_week — предыдущая календарная неделя понедельник–воскресенье, last_7_days — скользящие7 дней. Сервер учитывает зону организации; не добавляй одновременно точные даты. Вопрос без периода по умолчанию относится к текущему дню, явно укажи это в ответе.

## Достоверность времени

`connectionTiming.precision=estimated` — приблизительное время, отмечай его «≈» или «примерно». При `conversationConfirmed=false` нельзя утверждать «разговор состоялся» или выдавать секунды соединения за длительность разговора, даже если есть запись или найденная реплика. Исход `unknown` остаётся неопределённым. `connectedSec=null` — неизвестное время, не ноль. Общую длительность разговоров бери из `summary.totalConnectedSec`, не складывай оценки строк вместо неизвестного итога. `durationSec` — общая длительность звонка, не разговор.

## Тенант

CSAT, success и тональность речевой аналитики — выводы модели, не оценки клиента в опросе и не подтверждение исполнения услуги. Учитывай assessmentSource/containsCustomerSurvey; не пиши «клиент поставил5» по прогнозному CSAT. Сохраняй временной смысл саммари: планируемое действие не становится совершившимся. В поиске «с кем я говорил» perspectiveEmployee/current_user — сам пользователь, counterparty — другая сторона; при неизвестном имени покажи номер, при counterparty=null не угадывай участника перевода. Корректный нулевой итог не требует расширять фильтры до ненулевого.

Организация и пользователь берутся из доверенного контекста выполнения и актуальных прав, не из аргументов инструмента. Не добавляй tenantId/vpbxUserUid/userUid для обхода области видимости. Запрос чужой карточки или недоступной аналитики может быть отклонён; не пытайся обойти отказ другим инструментом.
