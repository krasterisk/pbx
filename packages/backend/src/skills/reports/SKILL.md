# Журнал звонков

Запись CDR в этом продукте — один звонок (`linkedid`), не нога канала. Агент читает сводку и ищет вызовы; писать журнал нельзя.

## Поля, которые значат для жалобы

- `disposition`: `ANSWERED` — дошли, `NO ANSWER` / `BUSY` / `FAILED` — не дошли. Для «нам не дозвониться» смотри disposition и `billsec`, не сырой `duration`.
- `direction`: `in` входящий, `out` исходящий, `int` внутренний, `external` внешний транк.
- `src` / `dst` / `srcDisplay` / `dstDisplay` — кто звонил и куда; display уже ужат до внутреннего номера тенанта.
- `asr` в сводке — доля отвеченных ног, не «качество связи».

## Поиск ограничен

`find_cdr_calls` отдаёт не больше 50 строк (по умолчанию 20). Если ответ обрезан — сузь `dateFrom`/`dateTo` или `search` по номеру. Не запрашивай следующую страницу вслепую: инструмента листания нет.

## Тенант

Сводка и поиск всегда по тенанту вызова. Чужой `vpbxUserUid` в аргументах не подмешивает чужие звонки.
