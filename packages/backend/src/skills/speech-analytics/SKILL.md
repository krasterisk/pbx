# Речевая аналитика

Модуль разбирает записи разговоров: распознавание, метрики качества, журнал и дашборд. Настройки модуля и проекты живут в кабинете; чат меняет их только через карточку подтверждения.

## Что агент делает

Читает контекст кабинета и предлагает:

- `pause_speech_analytics` — пауза или снятие паузы новых авторазборов (D-19). Ручная загрузка и «Получить аналитику» во время паузы работают.
- `edit_speech_analytics_project` — правка всего проекта (метрики, темы, вебхуки, дайджест, алерты, бюджет). Подтверждение **публикует**, когда меняются метрики (D-27).
- Если в сообщении есть `project_id` и произвольное описание проекта, по этому описанию заполни `systemPrompt`, `metrics` и `callTaxonomy` и вызови `edit_speech_analytics_project`. Не публикуй в обход карточки. Метрики — критерии оценки звонка (`boolean`, `number`, `enum`, `string`). Темы — о чём звонок, с `aliases`. Имена и описания по-русски.
- `issue_speech_analytics_token` — выпуск API-токена, привязанного к одному проекту. Секрет показывается в карточке один раз и в историю чата не пишется (D-33).

## Чего агент не делает

- Не списывает баланс и не вызывает settleShadow / BillingBalanceService.
- Не подставляет чужой `project_id` в тело загрузки API: проект берётся из токена.
- Не меняет модели STT/оценок без права тенанта (D-38): суперадмин всегда может; кабинетный админ — только если суперадмин включил право; супервизор и чат без права — нет. Выключение права уже выбранную замену не сбрасывает.
- Не создаёт DashboardBuilder, отдельную страницу Reports, роль analyst.

## UID тенанта

Всегда из JWT/dispatch. Аргументы `vpbx_user_uid` / `tenantId` из модели отбрасываются.
