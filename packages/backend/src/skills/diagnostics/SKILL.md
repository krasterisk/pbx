# Диагностика маршрута

Этот скил — процедура, не теория телефонии. Жалоба «почему звонок ушёл туда» закрывается уликами из инструментов этого продукта. Конфигурация без живого состояния — догадка.

## Порядок улик

Не называй причину, пока не пройдены шаги по порядку.

1. **Идентифицируй номер или extension** из вопроса (`7495…`, `201`, маска). Без этого следующие чтения бессмысленны.
2. **`describe_number`** — решённое назначение (очередь, абонент, IVR) или `unrouted`. Не собирай маршрут руками из `list_routes`.
3. **`evaluate_time_group`** на **заявленное** время, не «сейчас сервера». Пояс — тенанта.
4. **`get_compiled_dialplan`** для контекста этого номера. Правила в ответе — порядок оценки. Чужой контекст инструмент отвергнет.
5. **`get_recent_call_events`** или `find_cdr_calls` по конкретному вызову (номер, uniqueid, окно времени). `get_live_channels` — только если жалоба про текущий звонок.
6. **Только после этого** сформулируй причину.

## Причина из улики (D-13)

Каждый вывод именует tool output, на котором стоит: «`describe_number` вернул unrouted», «`evaluate_time_group` — outside в 19:10», «в скомпилированном диалплане `_X.` стоит выше DID». Без такой ссылки это не диагноз.

Обратное так же обязательно: **отсутствие записи — не причина**. Если события или CDR не нашли вызов, напиши, чего не нашёл и в каком окне, а не «значит оператор сбросил» или «значит транк виноват». Пустой список после усечения тоже не отсутствие вызова.

## Усечение

`get_live_channels` и `get_recent_call_events` режут список и ставят `truncated`. Не заключай «канала нет» / «события не было» по обрезанному хвосту. Сузь вопрос: номер, uniqueid, более короткое окно, один контекст.

## Чего здесь нет

Произвольных команд свитча нет. Hangup, reload, originate недоступны. Чужие каналы и чужой диалплан отфильтрованы на сервисе — не пытайся обойти это аргументом тенанта.
