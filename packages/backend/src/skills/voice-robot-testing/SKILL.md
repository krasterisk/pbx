# Проверка и инструкции пользователю

Каждый итоговый ответ содержит нумерованные действия «куда зайти → что нажать/ввести → что ожидается → что делать при ошибке». Адаптируй к сценарию и реальным UID/названиям. Дай конкретные реплики и результаты. Не выдумывай номер звонка.

Без MCP:
1. Сохранить scenario.json в UTF-8; только объект JSON, без markdown, комментариев и инструкций.
2. Для mpbx войти администратором в действующий интерфейс, затем открыть https://mpbx.krasterisk.ru/modules/voice-robots/standalone.html#/voice-robots. Создать и Сохранить отдельного тестового робота до импорта. STT/TTS выбрать во вкладке Основные; провайдеры на #/settings/stt-engines и #/settings/tts-engines. Ключи вводить в формы, не в чат. При отсутствии провайдеров импорт можно проверить, но live gate pending.
3. Сохранённый робот → Диалог → Импорт JSON → выбрать scenario.json. Дождаться уведомления о группах/сценариях/справочниках; указать ожидаемые числа из файла. Импорт сам сохраняет данные. Не жать повторный импорт при неясном результате: перечитать список/экспорт. В UI нет атомарного отката при ошибке; возможна частичная запись.
4. Проверить Основные (приветствие, стартовая группа, STT/TTS), Диалог → Дерево сценариев, Предпросмотр карточек и Справочники. Сохранить и повторно открыть. Для теста ограничить шаги/повторы под длину сценария.
5. Тест → Текст (имитация STT) → конкретная реплика → Тест. Сверить ключевую фразу, matched и метод. Вкладка ищет во ВСЕХ активных группах, не поддерживает состояние диалога и не проигрывает голос. Предпросмотр/дерево — визуальные представления.
6. Справочники → Тест поиска: пример запроса и «Вернуть поле». Ожидаемый ответ брать из rows. Успех поиска в UI не подтверждает аудио или последовательность реплик.

С MCP: не проси вручную импортировать уже записанный сценарий. После создания/изменения используй get_voice_robot_configuration, export_voice_robot_scenario, check_voice_robot_readiness, test_voice_robot_match; справочник — test_voice_robot_data_list. Дай ссылку на настроенного робота и оставшиеся шаги. В основной версии дождись подтверждения карточки; proposal не означает запись.

Реальный звонок:
1. Проверить активность и выбранные STT/TTS. На mpbx доступны Yandex STT/TTS и custom HTTP STT. Credentials не проверены реальным облачным запросом, пока не выполнен звонок.
2. Если тестовый номер/маршрут неизвестен, написать «номер пока не настроен» и дать администратору задание подключить выделенный тестовый маршрут к этому UID. Standalone entry: доверенный VPBX_USER_UID фактического кабинета и Stasis(mpbx_voice_robots,robot_uid). Это административный контракт, не команда перезапустить Asterisk. Рабочий номер/маршруты не менять без отдельного поручения. В основной версии посмотреть entry_points; standalone каталог v3 не перечисляет.
3. Один звонок на подтверждённый тестовый номер. Говорить после вопроса, с паузой; каждую ветку повторить отдельным звонком. Дать таблицу: шаг/реплика клиента/ожидаемый ответ/переход/критерий pass. Проверить неизвестную фразу, повтор, завершение, silence; slots/webhook/search — только если включены.
4. Журнал звонков (#/voice-robots/cdr): найти по времени, роботу и клиенту, открыть детализацию, проверить распознанные реплики, matched keyword/group, ответы, tags и итог. MCP: list_voice_robot_calls/get_voice_robot_call. Проверить отсутствие неожиданных повторов/переводов.
5. Сообщить отдельно: JSON/import pass; matching pass; directory pass; реальные STT/TTS/FSM/webhook/transfer pending или pass с данными. Максимум mpbx pilot — 3 сессии; нагрузочный тест не является шагом настройки.

Диагностика: 401 — вход в v3/ключ MCP/срок; read credential — JSON fallback или получение configure ключа администратором; UI import error — проверить format/version/ссылки и перечитать возможную частичную запись; нет групп — сохранить робота перед импортом; wrong match — поправить synonyms/пересечения, помнить ограничение отрицаний; тишина — describe/check readiness и движки, затем фактическая STT/TTS ошибка в журнале; нет CDR — проверить маршрут/tenant/активность. Причину без evidence не объявлять. Не рекомендовать restart/reload Asterisk, Apache или всех PM2 приложений.
