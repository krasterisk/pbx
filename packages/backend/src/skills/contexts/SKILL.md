# Контексты

Контекст — именованный контейнер маршрутов одного тенанта. Это не общий диалплан Asterisk и не теория телефонии: агент задаёт маршруты и область их доступности через включения.

## Именование и uid

`list_contexts` возвращает `uid`, `name`, `comment`, `include_uids` и признаки основного назначения. Для `create_route` нужен `uid` из этого списка, не угаданное имя. В Asterisk к имени добавляется суффикс тенанта; агент не конструирует это имя сам и не подставляет чужой `uid`.

## Тенант

Список всегда принадлежит тенанту вызова. Аргумент модели с чужим `vpbxUserUid` или `tenantId` не меняет выборку. Контекст тенанта A не бывает в ответе тенанта B.

## Связь с маршрутами

`include_uids` — упорядоченный список UID включённых контекстов этого кабинета в create_context/update_context.
Читай актуальный список через list_contexts; передай весь желаемый порядок. Сначала ищутся собственные
маршруты, затем включения сверху вниз с обходом вложений в глубину. Порядок не задаёт резервирование
транков. Дубликаты, чужие UID и циклы запрещены. Контекст абонента задаёт область обычного набора;
не обещай автоматическое ограничение прямого Dial/Goto в цепочке. Подтверждённые изменения применяются
в АТС. При ошибке применения сообщи о сохранённом состоянии и необходимости повторного применения.
Route Type (permissions) больше не настраивается.

Маршрут живёт в одном контексте. Сначала `list_contexts`, затем создание или правка маршрута в выбранном `uid`. Подтверждение изменения применяет диалплан; для повторного применения есть подтверждаемый apply_context.

## Основные контексты

list_contexts возвращает is_default_for_endpoints и is_default_for_trunks. create_context/update_context позволяют назначить эти признаки. На кабинет один основной каждого вида; один контекст может иметь оба признака. Если основной уже назначен, сначала отдельным шагом update_context сними нужный признак у него, затем зависимым шагом назначь новый. Сервер запрещает перезаписать занятый выбор. В интерфейсе признаки выбираются в модалке: занятые другим контекстом скрыты; таблица отображает только выбранные назначения. Изменение основного касается только новых абонентов/транков, существующие назначения не меняются. Контекст обязателен. Без назначенного основного уточни выбор.

## Упорядоченные контексты и применение

1. Прочитай list_contexts, текущий контекст через get_endpoint_configuration / get_trunk_configuration, затем get_context_configuration(uid). Последний показывает имена прямых включений и порядок обхода в глубину из БД; он не симулирует вызов и не доказывает применённое состояние АТС.
2. Прочитай list_routes / describe_route_chain достижимых контекстов. Передай в update_context весь желаемый include_uids, сохранив прочие включения и порядок; [] удаляет включения, отсутствие поля сохраняет их. Свои правила всегда раньше включений. Чужие UID, повторы, самовключения и транзитивные циклы запрещены.
3. Карточка показывает имена включений до/после. Объясни, каким абонентам открывается направление. Для «внутренние + межгород» создай контексты направлений, включи их в контекст доступа и назначь его нужным абонентам. Отсутствие правила во всём графе блокирует обычный набор; прямой Dial/Goto требует отдельной проверки.
4. Сначала подтверждай создание контекстов и получай реальные UID, затем следующим планом создавай маршруты/включения и назначай контексты. Не угадывай UID будущих шагов.
5. При switch_failed повтори подтверждение той же карточки: повторяется применение, а не запись. Если БД уже сохранена после иной ошибки, перечитай состояние и предложи подтверждаемый apply_context(uid). Он повторяет применение без создания и без изменения БД. Не повторяй create.
Контекст абонента задаёт исходящий обычный поиск; контекст транка — входящий. Include не является резервированием транков. Route Type (permissions) не используется.

## Формат идентификатора

name — технический идентификатор 1–64 символа: строчная латинская буква в начале, затем строчная латиница и цифры; одиночные дефисы/подчёркивания только между частями. Без пробелов, кириллицы и иных символов. Примеры: from-internal, access_national. Понятное название на русском сохраняй в comment. Не переименовывай существующие контексты автоматически.
