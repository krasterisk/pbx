# Голосовые меню

Меню — карта цифр. Каждая цифра (`1`–`9`, `0`, `*`, `#`) ведёт звонящего в одно назначение. Смена цифры меняет маршрутизацию входящих, даже если старый флаг называл это «безопасной» правкой.

## Рецепт

1. **Что прочитать.** `read_skill` для `ivrs`, `endpoints` и `call-groups`, если в запросе есть абоненты или группа на таймаут. Затем `list_endpoints` по названным номерам (например `101-103`). Не утверждай «абонентов нет» по sample снимка `get_pbx_state`.
2. **Чеклист из слов пользователя.** Бери факты из **любой** реплики треда, не только из последней. Короткое «да, создай IVR» не отменяет исходный текст и карту цифр. Только то, что назвали: абоненты → одна группа на таймаут → меню. Не три группы и не 702/703/704, если пользователь назвал 101–103.
3. **Висит карточка.** Попроси подтвердить и назови, что осталось в чеклисте. Не закрывай ход молча.
4. **Когда остановиться.** Спрашивать можно только то, чего нет ни в одной реплике треда: свободный `exten` группы или TTS-движок. Уже названные имя, текст приветствия и цифры клади в `create_ivr` как есть — не переспрашивай. Полный ТЗ не закрывай меню «что настроить: IVR / группа / абоненты» — сразу `read_skill` и чеклист.

Исполняемый чеклист для «IVR Продажи, 1→101, 2→102, 3→103, таймаут → группа 101–103»:

Если не хватает и абонентов, и группы, и меню — это один `propose_plan` из трёх шагов (`create_endpoints_bulk` → `create_call_group` → `create_ivr`), а не три хода.

1. `list_endpoints` с фильтром `101-103`. Если номеров нет — одна карточка `create_endpoints_bulk` `101-103`, попроси подтвердить, чеклист: группа → меню.
2. `list_call_groups`. Одна группа с членами 101–103. Если `exten` группы не назван — один вопрос (не выдумывай 702/703/704).
3. `list_tts_engines`. Затем `create_ivr` с текстом приветствия в `prompts` (`kind: tts`, `text`, `engine_uid`) и цифрой `t` → `{ kind: group, target: <uid группы> }`. Это `togroup` с `target.fixed`, не `extension`. Цифра → абонент — `kind: extension` (persist `toexten`, не `dial`).
4. Если движок не назван — один вопрос, какой движок. Без движка меню всё равно предложи, текст оставь в карточке и скажи: фразу повесьте на экране меню.

Цифра → абонент — это `extension` → действие `toexten` с публичным номером (`101`, не `e101_0` и не `dial`). Не отдельная группа на каждую цифру. Текст приветствия не клади в `description` — у меню такого поля нет.

## Допустимые назначения

Цифра указывает на сущность **этого** тенанта:

- `context` — контекст маршрутизации
- `extension` — внутренний абонент
- `queue` — очередь
- `menu` — другое голосовое меню
- `group` — группа вызова (`togroup`). Таймаут (`t`) / «ничего не нажали» → эта группа.

Назначение, которого нет у тенанта, отвергается до подтверждения: в отказе названы цифра и отсутствующая цель. Не оставляй цифру «в никуда» — звонящий услышит тишину после нажатия. Не мапь группу на `extension`.

## Таймаут и неверный ввод

- `t` — таймаут (абонент ничего не нажал)
- `i` — неверный ввод

Это договорённость меню, не отдельные сущности. Обе цифры тоже должны вести в существующее назначение или в явное завершение (`hangup`), иначе звонящий зависнет.

## Откуда звонящий попадает в меню

Меню почти всегда достигается со **входящего маршрута** (`toivr`). Перед правкой прочитай маршруты тенанта: какая линия и какой шаблон ведут сюда. Не предлагай менять меню, не зная, кто в него входит.

Не подставляй чужой `vpbxUserUid`. Не применяй смену цифры без карточки before/after.
