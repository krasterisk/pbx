# Автообзвон

Автообзвон — исходящий диалер: система сама набирает номера из клиентской базы, а ответившего абонента отдаёт сценарию — чаще всего в очередь операторов.

## Из чего состоит

**Клиентская база** — набор контактов с пользовательской схемой полей. Схему задаёт тенант: обязательным является хотя бы одно поле-телефон, остальные (`string`, `number`, `date`, `money`, `enum`, `boolean`) свободные. У каждого поля есть `var_name` — имя канальной переменной, под которым значение доходит до сценария, так что озвучить в TTS сумму долга или имя клиента можно без отдельной интеграции.

Контакт может иметь несколько номеров; каждый номер набирается своей задачей.

**Кампания** — база + сценарий + пейсинг + повторы + расписание. Живёт в статусах `draft`, `scheduled`, `running`, `paused`, `stopped`, `completed`.

**Задача** — одна строка на пару (контакт, номер). Задачи создаются при запуске кампании: берутся все номера базы, кроме уже имеющих задачу и кроме попавших в стоп-лист.

**Попытка** — один набор. У попытки есть диспозиция и, если абонент ответил, время разговора.

## Режимы набора

- **Progressive** — один звонок на одного свободного оператора. Абонент почти никогда не ждёт, но операторы простаивают между звонками.
- **Power** — N звонков на свободного оператора (`power_ratio`). Простой меньше, но часть ответивших ждёт освобождения оператора; за этим следит abandon rate.
- **Agentless** — робот или IVR без операторов. Сценарий такой кампании не должен содержать шаг `toqueue` — система это отвергает.

**Predictive** — пейсинг под целевой abandon rate: диалер сам подбирает коэффициент перебора (`overDial`) по живой статистике ответов и брошенных, не выше `max_over_dial`. Нужен провайдер `queue_agents`, иначе перебирать не от чего.

## Пейсинг

Число одновременных звонков — минимум по всем включённым провайдерам ёмкости:

- `static` — фиксированный потолок.
- `queue_agents` — свободные (READY) операторы выбранных очередей, для Power умноженные на ratio.
- `trunk_channels` — свободные каналы транков кампании. Лимит: `max_channels` строки кампании, иначе лимит карточки транка (`device_state_busy_at`). Занятость считается по `CoreShowChannels`.
- `tenant_cap` — общий предохранитель на арендатора.

Расписание, часы абонента и стоп-лист — это не ёмкость, а фильтры выборки задач.

Пейсер не набирает, пока не поднято соединение с Asterisk по ARI, и первые полминуты после перезапуска backend не доверяет счётчику свободных операторов: без событий диалер не отличит гудок от снятой трубки.

## Диспозиции и повторы

`success` (ответили и говорили дольше `success_min_sec`), `answered_short` (ответили, но короче порога), `no_answer`, `busy`, `congestion`, `failed`, `amd_machine`, `voicemail`, `invalid_number`, `dnc`, `max_attempts`, `callback_scheduled`, `cancelled`, `excluded`.

Интервал до следующей попытки задаётся отдельно на каждую диспозицию: занято — перезвонить через минуты, не ответили — через час. Исчерпав `max_attempts`, задача закрывается диспозицией `max_attempts`, а не последней транзиентной причиной — в отчёте видно «сдались», а не «было занято».

Терминальные диспозиции (`success`, `max_attempts`, `dnc`, `invalid_number`, `cancelled`, `excluded`) сами не повторяются никогда.

**Повторный обзвон делается выборкой по прежним диспозициям при запуске той же кампании, а не созданием новой.** Например «обзвонить всех, кто не ответил» — это запуск с выборкой `no_answer`, `busy`, `congestion`.

## Комплаенс

Стоп-лист (DNC) действует на трёх уровнях: глобально по тенанту, на кампанию, на базу. Запись может иметь срок действия. Номер из стоп-листа не попадает в задачи при генерации и не набирается.

Разрешённые часы считаются в поясе абонента (`tz_offset_min` номера, зафиксированный при импорте), а не в поясе сервера. Календарь кампании — в явно указанной таймзоне.

AMD (детект автоответчика) опционален. `MACHINE` даёт диспозицию `amd_machine`; неуверенный результат считается человеком, чтобы не терять живых абонентов.

## KPI

`contact rate` = ответившие / наборы. `RPC` = успешные / наборы. `AHT` — среднее время разговора по ответившим, `ACD` — по всем наборам. `abandon rate` = отвалившиеся / ответившие — контрольный сигнал для Power. `list penetration` — доля базы, до которой дошли. Плюс наборов в час и наборов на достигнутый контакт.

Живой монитор считает по текущему дню из памяти; отчёты за закрытые дни читают ночной rollup, поэтому длинная история не сканирует таблицу попыток.

## Что агент делает и чего не делает

Читает: `list_autodial_campaigns`, `get_autodial_campaign`, `list_autodial_bases`, `get_autodial_stats`.

Предлагает: `create_autodial_campaign` (черновик), `update_autodial_campaign` (пейсинг, повторы, транки, CID, AMD, сценарий, расписание, таймауты), `pause_autodial_campaign` (пауза), `add_autodial_dnc` (номер в стоп-лист).

Перед правкой читай `get_autodial_campaign` и меняй только запрошенные поля. Ревизию карточка берёт сама — модель её не угадывает.

**Запуск кампании агенту недоступен.** Это реальные звонки реальным людям — кнопку «Запустить» нажимает человек. Просьбу «запусти обзвон» отрабатывай подготовкой: проверь базу, сценарий и пейсинг, затем скажи, что осталось нажать запуск.

Остановить набор одного номера — стоп-лист, а не пауза всей кампании.

## Какие вопросы отвечает автообзвон

- Сколько задач в кампании обработано и сколько осталось
- Почему кампания не набирает: пауза, расписание, нет свободных операторов, нет свободных каналов транка
- Сколько дозвонов, ответов и успешных контактов за период, с contact rate и AHT
- Кого перезвонить: выборка по прежним диспозициям
- Как данные клиента попадают в озвучку сценария
