# Абоненты

Абонент в этом продукте — внутренний номер (`extension`) в контексте маршрутизации тенанта. SIP ID собирается как `e{extension}_{tenant}`; агент не конструирует его сам.

## Рецепт

1. **Что прочитать.** Сначала `list_endpoints` (фильтр `101-103`, если номера названы). Снимок `get_pbx_state` — только счётчик, не доказательство «номера нет».
2. **Чеклист из слов пользователя.** Бери факты из **любой** реплики треда, не только из последней. Если пользователь **назвал** номера — создавай именно их одной карточкой `create_endpoints_bulk`. Не подставляй 702+.
3. **Висит карточка.** Попроси подтвердить и назови, что осталось. Не закрывай ход молча.
4. **Когда остановиться.** Спрашивать можно только то, чего нет ни в одной реплике треда (контекст или имя, без которых нельзя продолжить). Уже названные номера не переспрашивай. Полный ТЗ не закрывай меню «что настроить».

## Extension и контекст

`create_endpoint` без номера берёт следующий свободный extension из уже существующих абонентов этого тенанта. Контекст по умолчанию — тот, которым уже пользуются эти абоненты, не общий Asterisk-контекст и не догадка по имени компании.

Если пользователь **назвал** номера (101, 102, 103) — создавай именно их, не подставляй 702+. Имя отображения (`name` / `displayName`) спроси, только если его нет; роль из запроса («Продажи») можно взять как имя. Не угадывай кодеки, NAT-профиль и отдел.

## Пароль

Пароль генерирует сервис абонентов в момент подтверждения карточки. В proposal, в ответе инструмента и в переписке пароля нет. Скажи пользователю, что учётные данные смотрят на экране абонента.

## Чего не делать

`create_endpoints_bulk` принимает паттерн (`200-220`) или `startExtension`+`count` и возвращает **одну** карточку на всю пачку. Потолок — 50. Больше — отказ с этим числом, без proposal.

`delete_endpoint` деструктивен: в карточке имя и номер, поиск только в тенанте вызова. Чужой SIP ID — «не найден».

Не подставляй чужой `vpbxUserUid`. Не создавай пачку через `create_endpoint` по одному. Не обещай пароль в чате.
