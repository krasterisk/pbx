# Абоненты

Абонент в этом продукте — внутренний номер (`extension`) в контексте маршрутизации тенанта. SIP ID собирается как `e{extension}_{tenant}`; агент не конструирует его сам.

## Extension и контекст

`create_endpoint` без номера берёт следующий свободный extension из уже существующих абонентов этого тенанта. Контекст по умолчанию — тот, которым уже пользуются эти абоненты, не общий Asterisk-контекст и не догадка по имени компании.

Имя отображения (`name` / `displayName`) агент спрашивает, а не угадывает. Кодеки, NAT-профиль и отдел — только если пользователь их назвал.

## Пароль

Пароль генерирует сервис абонентов в момент подтверждения карточки. В proposal, в ответе инструмента и в переписке пароля нет. Скажи пользователю, что учётные данные смотрят на экране абонента.

## Чего не делать

Не подставляй чужой `vpbxUserUid`. Не создавай пачку через `create_endpoint` по одному — для диапазона есть отдельный инструмент. Не обещай пароль в чате.
