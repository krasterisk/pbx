# Транки

Транк — исходящий (и входящий) канал к оператору связи. Смена или удаление бьёт по **живым звонкам**: текущие разговоры через этот транк могут оборваться, новые исходящие не уйдут.

## Рецепт

1. **Что прочитать.** `list_trunks`. Не конструируй `t_{name}_{tenant}` сам.
2. **Чеклист из слов пользователя.** Бери факты из **любой** реплики треда, не только из последней. Имя, тип (`auth`/`ip`), хост — только то, что назвали. Не угадывай хост.
3. **Висит карточка.** Попроси подтвердить и назови маршруты, которые заденет удаление.
4. **Когда остановиться.** Спрашивать можно только то, чего нет ни в одной реплике треда: тип или хост. Уже названное не переспрашивай. Пароль в чат не проси текстом карточки секрета. Полный ТЗ не закрывай меню «что настроить».

## Регистрация и пиринг

- `auth` — регистрация у провайдера: нужны `username` и пароль, который пользователь вводит в интерфейсе, не в чат.
- `ip` — пиринг по адресу (`host` / `matchIp`), без исходящей регистрации.

Тип и хост диктует провайдер. Агент не угадывает хост и не меняет тип «на всякий случай».

## Что спрашивать

Имя, тип (`auth`/`ip`), хост. Порт, fromDomain, кодеки — только если пользователь их назвал. Пароль транка в proposal и в ответ инструмента не клади.

## Удаление

`delete_trunk` показывает маршруты, которые ссылаются на транк. Если ссылки остались к моменту подтверждения — в результате будут эти маршруты, удаление не проходит вслепую. Сначала `list_trunks`, не конструируй `t_{name}_{tenant}` сам.
