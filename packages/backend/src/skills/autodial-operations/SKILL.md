# Операции автообзвона

На вопрос о простое вызови `get_autodial_diagnosis`, назвав UID/имя нужной кампании.
Сообщай фактический код причины и время следующей попытки из ответа. Не выводи причину из нулевой плитки.
Если инструмент не смог проверить состояние — скажи, какой факт неизвестен.

Для готовности — `get_autodial_preflight`: fail блокирует запуск, warning объясняет ожидание
(например, время вне расписания или отсутствие READY-агентов). IP-транк не обязан регистрироваться.
`get_autodial_monitor` получает сохранённые дневные счётчики и живые каналы. После рестарта нули памяти
не означают отсутствия звонков за день. Проценты уже выражены в 0–100.

Просьба перезвонить группе результатов означает подготовить параметры перенабора той же кампании.
Не вызывай запуск автоматически. Пауза предлагается карточкой; текущие вызовы продолжаются.
Для одного нежелательного номера используй DNC с подходящей областью, а не общую паузу.

change_autodial_contact_task предлагает исключение контакта из текущего тура или перенос pending-повтора
на будущее время ISO с часовым поясом. Завершённые задачи не возобновляет и активный вызов не прерывает.
Для массового запрета — add_autodial_dnc_bulk: до 100 номеров, область и срок, затем подтверждение карточки.
Для разрезов отчёта — get_autodial_report_breakdown; сегменты и операторы маскируются по политике ПДн.
get_autodial_report_selection считает уникальных клиентов, create_autodial_base_from_report предлагает копию
с сохранением DNC. Эти действия не запускают звонки. CRM/MCP используют scoped API-ключи;
применение входящих карточек — только после входа с паролем и явного подтверждения в интерфейсе.
