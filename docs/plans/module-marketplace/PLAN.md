# Навигация, маркетплейс и активация модулей — оценка и план

Ревизия: **v1.1, 2026-10-17**. Статус: **ready**, решения OD1–OD8 приняты (§5), исполнитель не назначен. Режим: `codex-direct`. Состояние координации: [EXECUTION](EXECUTION.md).

Точка зрения: senior React / тимлид / продуктовый дизайнер. Цель оценки — простой и понятный путь «вижу, где работаю → понимаю, чего нет → подключаю → работаю».

---

## 0. Связь с `mobile-navigation` и сохраняемый контракт

Навигационный chrome (ModuleShell, ModuleNavigation, MobileBottomBar, MobileModuleMenu, Hub) построен инициативой [mobile-navigation](../mobile-navigation/PLAN.md) N5–N21 по прямым уточнениям пользователя. Её координатор в состоянии idle, активных writers нет. Этот план **не переоткрывает** её решения, кроме принятого владельцем OD2.

Сохраняется без изменений:

- Desktop: глобальный раскрывающийся sidebar с изменяемой шириной, compact rail с flyout (N15, N21). **В шапке после логотипа навигации нет, хлебные крошки удалены пользователем (N15)** и не возвращаются.
- Phone: левый Sheet разделов без поиска; «Модули» последним пунктом; снизу название раздела и страницы с горизонтальной прокруткой, кнопка «Раздел ▾» открывает все страницы раздела (N7, N13, N17, N18).
- Один источник навигационных данных — `useHubModules` после каталога, видимости, лицензий и RBAC; один resolver текущей страницы (N5).
- Hub: адресный переход `/modules?module=<code>` с фокусом строки, без автоматической покупки или включения (N9). Избранное сортирует только Hub (N9).
- ~~Недоступные модули в навигации отдельной группой (N9 решение 6).~~ **Заменено решением владельца OD2 (2026-10-17):** в навигации (desktop sidebar, compact rail, левый Sheet телефона) только активные модули; не подключённые и выключенные — только в Hub.

Единственное переоткрытое решение — OD2 (см. ниже и §5). Перед задачами, которые пишут в общие пути навигации, координатор сверяет, что у `mobile-navigation` нет активного writer, и записывает приём владения в [EXECUTION](EXECUTION.md).

## 1. Критерии

1. **Навигация показывает, где я работаю.** Активные модули и разрешённые страницы; недоступное не шумит и не ведёт в тупик.
2. **Один словарь.** Один статус называется одинаково на всех экранах.
3. **Предложение по роли.** Купить или включить предлагают только тому, кто может это сделать; остальным объясняют, к кому идти.
4. **Без тупиков.** Глубокая ссылка на недоступный модуль объясняет причину на месте и предлагает действие; после подключения — «Открыть модуль».
5. **Одно место про модули.** Узнать, подключить, включить, выключить — в одном интерфейсе.
6. **Одна правда о доступе.** Меню, поиск, Hub и охранник маршрута решают одной функцией.

## 2. Оценка

### 2.1 Что сделано хорошо (сохранить)

- Статус лицензии считает сервер (`ModulesRegistryService.getHubCatalogForTenant` → `computeLicenseStatus`); клиент не придумывает `active` для market-модулей без каталога (`licenseStatusFromCatalog`).
- Глобальный sidebar-аккордеон с compact flyout удобнее для администратора АТС, чем переход через Hub на каждый модуль.
- Защита глубоких ссылок, стартовая страница по роли с fallback (N19), восстановление последней страницы раздела (N10), глобальный поиск Ctrl+K (N8).
- Хорошая доступность и покрытие тестами навигации, Hub и мобильных меню.
- Покупка на сервере: цена с сервера, идемпотентное списание, компенсация при ошибке (`PurchaseModuleService`).

## 3. Целевая модель

### 3.1 Словарь (предложение для OD1)

- **Модуль** — единица продукта; **страница** — пункт внутри модуля. Слово «раздел» в интерфейсе не использовать.
- Статусы:
  - `active` — «Активен»;
  - `disabled` — «Выключен» (в Hub и карточке: «Выключен администратором»);
  - `locked` — «Не подключён».
  - «Заблокировано» и «Отключено» не используются.
- Hub: «Модули» → секции «Мои модули» и «Можно подключить».
- Группы недоступных модулей в навигации нет (OD2).
- Тип: «В комплекте» / «Дополнительный».

### 3.2 Матрица доступа

Одна чистая функция в `features/modules/lib`:

```ts
type ModuleAccess =
  | { state: 'ok'; accessUntil?: string }
  | { state: 'loading' }
  | { state: 'locked'; canBuy: boolean }
  | { state: 'disabled'; canEnable: boolean }
  | { state: 'forbidden' }   // страница не разрешена уровнем/ролью
  | { state: 'hidden' };     // off / tenant-hidden / ownModels: модуля «нет»

resolveModuleAccess(row, page, { level, grants, catalogState }): ModuleAccess
```

| Статус | ADMIN | Остальные |
|---|---|---|
| `active` | меню, поиск, страница | то же, по уровню и правам роли |
| `active`, доступ истекает ≤ 7 дней | метка «до DD.MM» в Hub и карточке | без метки |
| `disabled` | в навигации нет; Hub «Мои модули» со статусом «Выключен администратором» + «Включить»; глубокая ссылка → экран с «Включить» | в навигации нет; глубокая ссылка → «Модуль выключен администратором» |
| `locked` | в навигации нет; Hub «Можно подключить» + «Подключить»; глубокая ссылка → экран с описанием, ценой и «Подключить» | в навигации нет; в Hub без кнопки, текст «Подключает администратор»; глубокая ссылка → тот же текст |
| `hidden` | нигде; глубокая ссылка → доступная стартовая страница (как сейчас) | то же |
| каталог загружается или ошибка | не перенаправлять, не объявлять доступным; навигация в состоянии загрузки | то же |

Экран на месте страницы (`ModuleAccessScreen`) заменяет редирект для известного модуля в `locked`/`disabled`. Редирект остаётся для `/`, `hidden` и неизвестных путей. Автоматической покупки и включения нет (N9).

### 3.3 Подключение

1. Hub → карточка модуля (Sheet справа на desktop, снизу на телефоне): название, описание, страницы модуля, цена и период, статус, `accessUntil`, действия по роли.
2. «Подключить» → один экран: что входит, цена и период, баланс сейчас и после списания (если API доступен, OD5), галочка «Включить сразу» (по умолчанию включена, в том числе для AI-SKU), кнопка «Подключить за X ₽/мес».
3. Нехватка средств: недостающая сумма и реальный путь пополнения (OD5), без ссылки по кругу.
4. Успех: основная кнопка «Открыть модуль» (первая разрешённая страница), кэш каталога патчится сразу (`updateQueryData`) и затем инвалидируется. Деньги не обновляются оптимистично.
5. Новый модуль в навигации получает метку «Новый» до первого захода (хранение по пользователю и тенанту, как в N10).

### 3.4 Архитектура

- `ModuleNavProvider` в shell считает строки каталога один раз; `useHubModules` становится тонким чтением контекста; избранное — одно состояние.
- `useModuleActions(code)` — общий хук «купить / включить / выключить» для карточки Hub, экрана доступа и System→Modules.
- Позже (OD7): манифесты модулей `defineModule({ code, labelKey, icon, pages: [{ id, path, matchPaths?, element: lazy(...), access }] })` в слое `app` (ссылаются на lazy-страницы), типы и чистые функции в `entities/module`. Маршруты и меню генерируются из манифестов; `matchPaths` убирает частный случай `/speech-analytics`.

### 3.5 Не делаем

- Не возвращаем хлебные крошки и навигацию в шапку (N15).
- Не меняем нижнюю панель телефона и левый Sheet (N7, N13, N17, N18).
- Не покупаем и не включаем автоматически по ссылке (N9).
- Не добавляем закреплённые страницы; избранное остаётся в Hub (N9).
