## 2. Целевая модель

### 2.1 Строка отчёта = человек

Ключ строки — `agent_user_uid`. Строки без пользователя (старые записи, чужие устройства) — отдельной строкой по интерфейсу с пометкой «без учётной записи». Сервер отдаёт `agentUserUid`, `agentName` (из `users`, правило `operatorDisplayName`), `agentExtens[]` (все номера за период). Фильтр — `agentUserUid` (несколько), старый `agentInterface` принимается и разрешается в пользователя.

### 2.2 Учёт времени — только по журналу состояний

Для каждой сессии, пересекающей период, строятся сегменты журнала, обрезанные по `[from, min(to, сейчас, logout)]`. Сохранённые итоги сессии (`total_*`) отчёты больше не читают.

| Категория | Состояния журнала |
|---|---|
| `readySec` — готов к приёму | READY |
| `busySec` — занят работой | IN_CALL, HOLD, WRAPUP, ACW, DIALING, CONSULT (OD3) |
| `pausePaidSec` / `pauseUnpaidSec` | PAUSED, по `cc_pause_reasons.is_paid`; причина вне справочника — «неизвестно» (отдельно) |
| `loggedInSec` | пересечение сессии с периодом |

**Инвариант** (проверяется в модульных, интеграционных и живых тестах): `ready + busy + pausePaid + pauseUnpaid + pauseUnknown = loggedIn` с допуском ±1 с на сегмент.

### 2.3 Словарь метрик оператора

Звонковые метрики фильтруются очередью, временны́е — нет (OD-фильтр в 2.4).

| Ключ | Формула | Источник |
|---|---|---|
| `callsHandled` | answered + transferred, входящие и личные | `cc_queue_calls` |
| `rnaCount` | пропуски вызова | `cc_agent_offers` |
| `offeredCount` | handled + rna | — |
| `answerRatePct` | handled / offered | — |
| `ahtSec` | (talk + wrapup) / handled — без изменений (A1) | `cc_queue_calls` |
| `avgTalkSec`, `avgHoldSec`, `avgWrapupSec` | сумма / handled | `cc_queue_calls` |
| `transferredCalls`, `transferPct` | transferred; transferred / handled | `cc_queue_calls` |
| `shortCalls`, `shortCallPct` | handled с `talk_time < short_call_sec` (по умолчанию 10, OD5) | `cc_queue_calls` |
| `outboundCalls`, `outboundAnswered`, `outboundTalkSec` | исходящие оператора (OD4) | `cc_queue_calls` `direction='outbound'` |
| `occupancyPct` | busy / (busy + ready) | журнал |
| `utilizationPct` | busy / loggedIn | журнал |
| `pauseSharePct` | (paid + unpaid + unknown) / loggedIn | журнал |
| `callsPerHour` | handled / (loggedIn / 3600); скрывается при фильтре очереди | смешанная |
| `sessions`, `firstLoginAt`, `lastLogoutAt` | количество смен, первый вход и последний выход в периоде (TZ тенанта) | `cc_agent_sessions` |

Формулы-отношения добавляются в `packages/shared/src/callcenter-metrics/formulas.ts`, чтобы карточка оператора у супервизора, дашборд и отчёт считали одинаково.

### 2.4 Семантика фильтров

- **Очередь**: звонки и RNA — только выбранных очередей. Оператор попадает в список, если у него есть звонки или RNA в этих очередях **или** его сессия в периоде содержала выбранную очередь (`queues_snapshot`). Временны́е колонки помечаются в метаданных `scope: 'operator'` и в заголовке «по всем очередям»; `callsPerHour` скрывается.
- **Зона видимости** (OD2): SUPERVISOR видит операторов `scope.operators` и очереди `scope.queues`; явный фильтр вне зоны → 403; ADMIN — без ограничений. То же для экспорта, дашборда и расписаний.
- **Период**: усечение до 366 дней возвращается флагом `periodClamped` и показывается в интерфейсе.

## 5. Живые тесты

### 5.1 Стенд и правила

- Стенд `ipbx.krasterisk.ru` (Asterisk certified-22.8, AMI, `transport-wss`), БД стенда из `.env`, тенант 0, локальный backend `:5010` и Vite `:3010` — как в cc-analytics (п. 39, 45–51). Стенд предназначен для тестов (поручение пользователя 2026-10-15); перед каждым прогоном координатор сверяет, что стенд не занят другим прогоном (autodial-ux-audit тоже использует стенд).
- Миграция 0047 на стенде применяется штатным `db:migrate` после `db:migrate:status` и отдельного подтверждения пользователя.
- Все сверки — **по дельтам** относительно снимка до сценария, поэтому прогон повторяем. Ожидаемые значения берутся из журнала фактических моментов сценария (события AMI и строки БД), а не из заданных пауз; допуск ±2 с на длительность, счётчики — точно.
- Тестовые сущности создаются с префиксом `oprpt-` и удаляются в конце. Строки звонков остаются в данных стенда (как в cc-analytics), их номера абонентов `55502xx` и диапазоны `uid` записываются в отчёт прогона.

### 5.3 Драйвер оператора

Три контекста Playwright Chromium с `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`. Каждый оператор входит в `/callcenter/agent`, начинает смену через интерфейс и выбирает очереди. Так сессия, журнал и регистрация софтфона создаются настоящим путём панели. Паузы, удержание, постобработка, перевод и исходящий выполняются **кликами в панели**; API используется только для чтения.

Запасной путь, если L0 покажет, что headless WebRTC не регистрируется: смены и паузы — через API панели (`agent/login`, `agent/pause`), звонки — участником `Local/` без сессии, как в cc-analytics. Это сужает покрытие: RNA и время разговора реального оператора не проверяются. Отклонение записывается, гейты G1–G2 остаются частично открытыми.
