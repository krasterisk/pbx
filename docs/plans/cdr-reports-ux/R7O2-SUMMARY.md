# R7O2 — рабочий телефон из CDR

Статус: **реализован, автоматические проверки выполнены; браузерная и живая телефонная приёмка открыты. Внедрение не выполнено.**

В оболочку добавлен виджет рабочего телефона. Обычный пользователь выбирает свободный номер и SIP-телефон либо WebRTC. Меню номеров в журнале, карточке, маршруте, поиске и обращениях использует активную сессию. Выбор принадлежит сессии, отдельная настройка в профиле не создавалась.

Сервер проверяет организацию, актуальную роль, владельца вкладки, открытые смены и занятость телефона. SIP и его WebRTC-пара используют общую блокировку строки endpoint; вход КЦ участвует в той же сериализации. Истечение сессии не позволяет забрать активный разговор. Повторный набор до появления канала AMI ограничен. Обычная сессия не создаёт смену, не меняет очереди и показатели КЦ.

SIP.js-транспорт перенесён в shared без изменения содержимого (проверено побайтово); прежние импорты КЦ сохранены. SIP-пароли не записываются в browser storage; временный ответ RTK очищается после подключения. Кэш списка телефонов разделён по организации и пользователю. При активной SIP-смене используется существующий API КЦ с его проверкой прав; WebRTC КЦ открывает прежнюю панель и не создаёт второй транспорт.

Общий click-to-call dialplan теперь принимает префиксы `+`, `*`, `#`, сохраняя проверку полного номера в API. Основание синтаксиса — [документация Asterisk](https://docs.asterisk.org/Configuration/Dialplan/Pattern-Matching/). Изменение подпрограмм на АТС ещё не применялось.

В финале закрыта гонка выхода: отложенный ответ с credentials и результат запроса набора не запускают WebRTC после размонтирования владельца; если подключение уже началось, его завершение проверяет актуальность владельца и отключает старый транспорт. Воспроизведение с отложенным ответом включено в последние13 тестов. Shared SIP.js при этом не менялся.

## Что осталось

1. Браузер: desktop/mobile, светлая/тёмная тема, меню номера, восстановление и ошибка подключения. Открытие вкладки трижды получило timeout; штатное открытие вернуло queued для скрытой задачи. Ожидается возможность показать текущую задачу в окне Codex. Подготовленный UI-стенд использует только авторские номера и не заменяет живую АТС.
2. Настоящие внутренние SIP/WebRTC-звонки: ответ/неответ, занятость, два окна, истечение/перезагрузка/выход. Сверить записи, маршрут, итог и автора в CDR/aiChat, в том числе при смене рабочего номера. Не подменять этот gate SQL-тестами или HTTP-фикстурой.
3. Внедрение: миграция0055, обновление backend/frontend и штатное применение generated dialplan subroutines; проверить `+`/служебные коды на контролируемых маршрутах. Рабочая БД/АТС в этом срезе не менялись.
4. Отдельный оставшийся CDR-план: сводка всех доступных саммари вместо2/6,11 спорных смысловых совпадений и итоговая приёмка полного приложения. Сохранённые13 SA не нужно распознавать и анализировать повторно без нового доказанного дефекта.

Роботы и общие провайдеры не менялись. Межчатовых согласований, агентов и новых модельных запросов не было.
