# A14 — карта ресурсов

Run `a14-cloud-20261028`. Коэффициенты модели из §11 ТЗ **не калибровались**: нет независимых уровней панелей и звонков, нет трёх повторов, нет holdout. Формулу как прогноз не выдавать. Ниже одна наблюдённая точка и статус остальных строк.

Единицы CPU — доля хоста, 100% = все 4 ядра заняты, а не одно ядро. Память — `MemAvailable` и RSS процессов.

## Наблюдённая точка

Хост: 4 vCPU, 16 ГБ, PostgreSQL 16, Asterisk 20.6, Vite, клиенты на том же сервере.

| | |
|---|---|
| Панели | 6 операторских Chromium, 0 супервизоров. Дальше упёрлись в RAM |
| Вызовы | около 149 активных, из них 49 в разговоре и около 100 в ожидании, 5 минут, не 30 |
| CPU хоста на удержании | p50 27%, пик набора 100% |
| RAM | `MemAvailable` проваливался до 133 МБ, Chrome убит cgroup OOM. RSS backend 0,53–0,56 ГБ, Asterisk около 0,22 ГБ |
| Клиент | около 7,7 ГБ RSS на 6 headless-страниц Vite |
| Сеть / диск / pool | потери RTP и IOPS не снимались. Соединений PostgreSQL в середине было 11. Записи не было |

Этой точки недостаточно, чтобы назвать vCPU, RAM или полосу для 50 панелей и 150 звонков. `C_max` не вычисляется: ограничение корректности и памяти клиента наступило раньше устойчивого SLO.
