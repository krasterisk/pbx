# AI Chat UX v2 — единая лента, скрытые размышления, батч-подтверждение, тестовый стенд, redesign, видимость тредов

## Цель

Панель AI-ассистента перестаёт быть «двумя чатами» (live-стрим + история из БД) и становится одной лентой,
которая одинаково выглядит во время хода и после перезагрузки. Технические данные (uuid, `q701_0`, JSON
tool-результатов, internal reasoning) исчезают из DOM. Несколько мутаций за один запрос сходятся в одну
карточку плана. Всё это закрывается Playwright-сценариями на стенде с OpenAI-совместимым stub-LLM, поэтому
регрессии ловятся в CI без живого провайдера. Панель переезжает на модель «dock + workspace». Треды
получают read-only видимость по существующему механизму списков доступа.

## Зафиксированные решения

1. **`closeKind` у assistant-элемента ∈ `question | wait_confirm | complete`.** `incomplete` больше не порождает
   assistant-элемент вообще: ход просто не закрывается. Текст такого шага пишется в БД с `visibility='internal'`,
   в ленту не попадает. Достижение лимита шагов и `forcedTurnStatus` перестают быть сообщением ассистента —
   это терминальный `error`-эвент, который UI показывает баннером (`aiChat.ceiling` уже есть).
2. **Одна мутация — по-прежнему `DiffConfirmCard`.** `propose_plan` агрегирует только множественные мутации в
   один `WorkflowPlanCard`.
3. **Правило в промпте: ≥3 мутации → `propose_plan`.** Плюс жёсткий гард в loop: **вторая** мутирующая
   tool-call за ход отклоняется с инструкцией вызвать `propose_plan`. Гард намеренно строже промпта — при ровно
   двух мутациях модель получит отказ и всё равно построит план. Это ожидаемое поведение, а не баг.
4. **Workspace не модальный.** Панель в режиме `workspace` занимает область `main` шелла (топбар и сайдбар
   остаются кликабельными), `aria-modal` не выставляется, focus-trap и backdrop выключены, уход на `/ivrs`
   панель не закрывает. Отдельного route нет — состояние живёт в `ModuleShell`.
5. **Обратной совместимости для старых элементов нет.** `buildTimeline` мапит существующие строки как есть,
   backfill не делаем, из старых `assistant.content` планировочную прозу не вычищаем.
6. **SSE-формат ломаем без версионирования.** Единственный потребитель — `useAgentStream.ts`, который
   удаляется. `GET /threads/:uid` перестаёт отдавать `messages` одновременно с фронтом.
7. **Видимость тредов (Стадия F):** только чтение (composer скрыт, Apply/Reject недоступны, виден владелец);
   источник прав — вкладка «AI-чат» в списке доступа `NumberList` (`numbers.aiThreads.userIds`) + привязка
   `users.numbers_id`; тенантная галка «видеть все треды» в настройках AI-чата действует только на
   `UserLevel.ADMIN`; суперадмин смотрит треды тенантов на отдельной странице `pages/platform`, read-only.
   Чужие треды показываются отдельной вкладкой, а не в общем списке со своими.

## Глобальные ограничения

- **Порядок стадий обязателен.** A → B (B ломается без A), затем C, затем D (сценарии D проверяют A–C),
  затем E, затем F. F технически независима от B, но её UI садится на компоненты из B.
- **Каждая задача — один коммит.** Сообщение на русском, императив, без упоминания моделей и агентов.
- **TDD.** В каждой задаче: сначала падающий тест (RED, зафиксировать вывод), потом реализация (GREEN).
  Нельзя писать реализацию раньше теста.
- **Гейт перед «готово» (AGENTS.md):** `npm run lint && npm run test:backend && npm run test:frontend`.
  После стадии D добавляется `npm run harness`.
- **Никаких заглушек.** Если по ходу выясняется, что шаг невыполним как описан — остановиться и написать
  об этом, а не оставлять TODO/`any`/пустой обработчик.
- **Тенант и автор только из JWT.** `rejectBodyIdentity` в `AiChatController` запрещает ключи
  `tenantUid|authorUid|role|tenant|author|vpbxUserUid|vpbx_user_uid|user_uid` в body — новые эндпоинты
  передают тенант параметром пути/запроса (конвенция `cloud-admin`, T-08-04).
- **`packages/shared` требует сборки для бэкенда** (`require` → `dist`), фронтенд алиасится на `src`.
  После правки shared-типов запускать `npm run build -w @krasterisk/shared` перед `npm run test:backend`.
- **Фронтенд-тесты:** vitest, `css: false` (класс-модули не резолвятся — стили проверяются чтением
  `.module.scss` через `readFileSync`), общего `renderWithProviders` нет — локальный `configureStore` +
  `vi.mock('react-i18next')` с identity-`t` в каждом файле.
- **Бэкенд-тесты:** jest, `testRegex: .*\.spec\.ts$`, модели мокаются рукописными объектами с `jest.fn()`,
  `findByPk` в моках бросает исключение — сохранять этот приём.

/** Чем ассистент закрыл ход. `incomplete` элементом не становится — ход не закрывается. */
export type AgentTurnCloseKind = 'question' | 'wait_confirm' | 'complete';

/** Видимость строки истории. `internal` не попадает в ленту и не уходит в браузер. */
export type AgentItemVisibility = 'public' | 'internal';

export interface AgentTimelineUserItem {
  kind: 'user';
  /** Стабильный id для React-ключа и upsert в кэш. Для строк БД — `m<uid>`. */
  id: string;
  text: string;
  createdAt: string;
}

export interface AgentTimelineAssistantItem {
  kind: 'assistant';
  id: string;
  text: string;
  closeKind: AgentTurnCloseKind;
  /** true, пока ход не закрыт: пузырь дописывается чанками. */
  streaming?: boolean;
  createdAt: string;
}

/** Один шаг работы: человеческая формулировка, без имени инструмента и аргументов. */
export interface AgentTimelineStepItem {
  kind: 'step';
  id: string;
  /** Ключ локали, например `aiChat.progress.tools.list_queues`. Текст выбирает фронтенд. */
  labelKey: string;
  /** Готовый текст на случай отсутствия ключа в локали. */
  labelFallback: string;
  done: boolean;
  createdAt: string;
}

export interface AgentTimelineProposalItem {
  kind: 'proposal';
  id: string;
  /** `single` — DiffConfirmCard, `workflow` — WorkflowPlanCard. */
  card: 'single' | 'workflow';
  createdAt: string;
}

export type AgentTimelineItem =
  | AgentTimelineUserItem
  | AgentTimelineAssistantItem
  | AgentTimelineStepItem
  | AgentTimelineProposalItem;

export const AGENT_TIMELINE_KINDS = ['user', 'assistant', 'step', 'proposal'] as const;
```

Осознанные решения по типу:
- у `proposal`-элемента **нет** ни `proposalId`, ни `workflowId`: идентификатор живёт в отдельной мапе
  ответа (`proposals` / `workflows`), поэтому в разметку ленты uuid не попадает;
- `step` несёт ключ локали, а не готовую русскую строку — иначе локаль сервера протекает в UI;
- `AgentTimelineItem.id` — строка, потому что live-элементы нумеруются до записи в БД.

// packages/backend/src/modules/ai-chat/agent-timeline.util.ts
import type { AgentTimelineItem, AgentTurnCloseKind } from '@krasterisk/shared';

export interface TimelineSourceRow {
  uid: number;
  role: 'user' | 'assistant' | 'tool' | 'system';
  content: string | null;
  tool_name?: string | null;
  proposal_id?: string | null;
  close_kind?: AgentTurnCloseKind | null;
  visibility?: string | null;
  created_at: Date | string;
}

export interface TimelineProposalRef {
  proposalId: string;
  card: 'single' | 'workflow';
}

export interface BuildTimelineOptions {
  /** proposal_id → вид карточки. Строка без записи в мапе элементом не станет. */
  proposals: Map<string, TimelineProposalRef>;
}

export function progressLabelKey(toolName: string): string;
export function buildTimeline(rows: TimelineSourceRow[], opts: BuildTimelineOptions): AgentTimelineItem[];
```

Правила, которые обязан реализовать `buildTimeline`:
- `role === 'user'` → `user`-элемент, `id = 'm' + uid`;
- `role === 'assistant'` при `visibility === 'internal'` → **пропуск**;
- `role === 'assistant'` с непустым `content` → `assistant`-элемент, `closeKind = close_kind ?? 'complete'`,
  `streaming` не выставляется;
- `role === 'assistant'` с пустым/пробельным `content` → пропуск (это строка-носитель `tool_calls`);
- `role === 'tool'` → `step`-элемент с `labelKey = progressLabelKey(tool_name)` и
  `labelFallback = tool_name`, `done: true`; **содержимое `content` не используется** (там JSON);
- `role === 'tool'` с `tool_name === 'read_skill'` → пропуск (шум, а не работа);
- `role === 'system'` → пропуск;
- строка с `proposal_id`, для которого есть запись в `opts.proposals`, добавляет **после** своего
  `step`-элемента `proposal`-элемент с `id = 'p' + uid`;
- порядок результата — строго порядок входных строк (они приходят `ORDER BY uid ASC`);
- `createdAt` — ISO-строка.

`progressLabelKey(tool)` возвращает `` `aiChat.progress.tools.${tool}` `` — те же ключи, что уже есть в
локалях (`ru.ts` секция `aiChat.progress.tools`).

export function isWorkflowPlanView(value: unknown): value is { workflowId: string; steps: unknown[] } {
  return (
    !!value && typeof value === 'object' && !Array.isArray(value) &&

    Array.isArray((value as { steps?: unknown }).steps)

}

Поведение сервера:
- `POST /v1/chat/completions` — единственный маршрут (`resolveChatCompletionsUrl` в
  `packages/backend/src/modules/voicemail/llm-summary.service.ts:16` приклеивает `/v1/chat/completions`
  к `provider.endpoint`, поэтому провайдер будет создан с `endpoint = handle.url`);
- отвечает `Content-Type: text/event-stream`, отдаёт чанки в формате OpenAI:
  `data: {"choices":[{"delta":{"content":"..."}}]}` и для инструментов
  `data: {"choices":[{"index":0,"delta":{"tool_calls":[{"index":0,"id":"call_1","function":{"name":"...","arguments":"{...}"}}]}}]}`,
  затем `data: {"choices":[{"finish_reason":"tool_calls"}],"usage":{"prompt_tokens":10,"completion_tokens":5}}`
  и `data: [DONE]`;
- `reasoning` отдаётся отдельным чанком в `delta.reasoning_content` — это и проверяет A4 сквозняком;
- курсор ходов инкрементируется на каждый запрос; когда ходы кончились, повторяется последний
  (как `FixtureModelClient`);
- `GET /__stub/health` → `200 {"ok":true}` для `wait-on`;
- `POST /__stub/scenario` с телом `{"id":"..."}` → переключение сценария из вне процесса Playwright
  (нужно, потому что стенд и бэкенд — разные процессы; сценарий выбирает spec, а читает — сервер).

Логика `resolve` (копирует приём `CallCenterAccessListService.resolveScope` и
`CdrService.resolveCdrAccess`, но возвращает user-id, а не extensions):
1. `UserLevel.SUPERADMIN` → чужие треды **не** через этот путь: у суперадмина отдельная страница (F4),

2. если роль `ADMIN` и `settings.getSeeAllThreads(tenantUid)` → `{ readableAuthors: null, allTenantThreads: true }`;
