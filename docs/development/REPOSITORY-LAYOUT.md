# Структура репозитория и работа агентов

| Материал | Каноническое место | Git |
|---|---|---|
| Продуктовый код и пакетные тесты | `packages/` | Да |
| Правила работы | корневой `AGENTS.md` | Да |
| Архитектура, требования, решения | `docs/`, индекс `docs/CANONICAL_REFS.md` | Да |
| Назначенные планы, ограничения, короткие итоги | `docs/plans/<initiative>/` | Да |
| Исторические фазовые документы | `docs/archive/gsd/` | Да, как архив |
| Поддерживаемые проверочные инструменты | `tools/`, `harness/` | Да |
| Только синтетические входы/эталоны | `tests/fixtures/` или пакетные fixtures | Да |
| Состояние сессий, черновики, одноразовые скрипты, приватные данные | `.planning/` | Нет |
| Сборки проверок, логи, скриншоты, записи, сырые результаты | внешний `ARTIFACTS_ROOT/runs/<initiative>/<run-id>/` | Нет |

Новый clone должен читать канонические документы и выполнять поддерживаемые локальные проверки без `.planning/`. Не добавлять эту папку через `git add -f`, не возвращать поимённые правила в `.gitignore`. Штатные `packages/*/dist` — игнорируемые runtime outputs.

Имена `FIXTURES`, `baseline`, `candidate` не доказывают происхождение данных. Для promotion нужны проверка синтетического происхождения, отсутствие секретов, назначение владельца и сохранённые bytes/encoding. Частный CDR-корпус и generated CSV/JSON exports не являются общими fixtures.

GSD может требовать собственную локальную `.planning/`. Перед его запуском координатор связывает runner с одним каноническим PLAN; после — переносит принятые решения и краткий результат в `docs/`, не зеркалит всю рабочую область и не создаёт два источника управления. Snapshot кодовой базы не становится архитектурой. Новая команда или неудачная попытка не требуют отдельного постоянного документа.

Старые manifests, receipts, source hashes и snapshot paths сохраняются как исторические факты. Навигация обновляется отдельно; перенос не делает старый результат актуальной проверкой новой версии. Локальные доказательства не нужны для запуска приложения; доступные только локально ссылки помечены этой общей политикой, отсутствовавшие до миграции цели перечислены в отчёте.

Для новых outputs использовать `outputPath/output_path`, не legacy `artifactPath` adapter. API: [tools/artifacts](../../tools/artifacts/README.md). Рабочую область не публиковать целиком; promotion выполняется выборочно после проверки diff. Для параллельной работы соблюдать [владение](HYBRID-WORKFLOW.md); структурный перенос не меняет координаторов продуктовых инициатив.
