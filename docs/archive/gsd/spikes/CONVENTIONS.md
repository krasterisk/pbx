# Spike Conventions

Паттерны, сложившиеся за сессии спайков. Новые спайки следуют им, если вопрос не требует иного.

## Stack

- **Node.js CommonJS без сборки и без зависимостей сверх корневых `node_modules`.** Спайки запускаются
  как `node .planning/spikes/NNN-name/script.js` из корня репозитория. Ни package.json, ни tsconfig,
  ни ts-node в каталоге спайка.
- Клиентские страницы — статический HTML + один файл `app.js`, без фреймворков и бандлеров. Если
  нужна библиотека из `node_modules` (например `sip.js`), она собирается на лету через уже
  установленный `esbuild` в IIFE-бандл при первом старте сервера.

## Structure

```
.planning/spikes/NNN-name/
  README.md         # frontmatter, Research, Investigation Trail, Results
  <step>.js         # по файлу на шаг: provision / probe / teardown / peek
  public/           # если спайку нужна страница
  results/          # JSON-отчёты прогонов, коммитятся как доказательства
```

- Порядок файлов отражает порядок действий: `check-*` → `provision` → `probe-*` → `teardown`.
- Каждый спайк, который что-то меняет на сервере, **обязан** иметь `teardown.js`, идемпотентный
  и безопасный для повторного запуска.
- Локальный сервер перебирает список портов-кандидатов: Windows держит зарезервированные диапазоны,
  и первый выбранный порт регулярно отдаёт `EACCES`.

## Patterns

- **Доступы читаются из корневого `.env`** крошечным парсером внутри скрипта. Никаких dotenv,
  никаких собственных конфигов, никаких секретов в коде страниц — браузер получает их через `/config`.
- **Живой Asterisk опрашивается обоими каналами**: ARI (REST) для моделей и объектов, AMI `Command`
  для CLI-вывода. Доступность каждого — сама по себе факт для R-ENGINE.
- **AMI-обёртка повторяет боевую `AmiService.action`**, включая особенность `asterisk-manager`:
  успешный ответ на часть действий приходит в аргументе `err` с `response === 'Success'`.
- **Диалплан пишется тем же путём, что в проде**: `CreateConfig` → `UpdateConfig` (DelCat → NewCat →
  Append) → `dialplan reload`, со сплитом строки по первому `=>` на `Var` и `"> value"`.
- **Каждый прогон оставляет JSON в `results/`** с меткой времени. Это доказательная база вердикта,
  она коммитится вместе с README.
- **Здоровая статистика не означает работающую картинку.** В спайке 002 `framesDecoded` рос, пока
  элемент показывал чёрное: библиотека остановила трек. Проверять надо тот показатель, который
  соответствует цели (`videoWidth`, `currentTime` у элемента), а не соседний.
- **Не доверять клиентскому состоянию.** В спайке 002 `sip.js` рапортовал `Registered`, пока сервер
  не видел контакта. Когда две стороны расходятся, ставится перехват на проводе (обёртка над
  `WebSocket`), а не добавляются логи в прикладной код.
- **Синтетический источник медиа вместо камеры**: канва с подписью и часами + тон из `AudioContext`.
  Снимает зависимость от вебкамеры, даёт визуально различимых участников и позволяет открыть
  столько вкладок, сколько нужно. Часы на плитке заодно служат доказательством: отставание
  удалённой плитки от локальной измеряется прямо на скриншоте.
- **Сначала самый дешёвый опыт, способный опровергнуть.** В спайке 003 «телефон» сперва изображался
  уже работающим браузерным клиентом с урезанным бюджетом потоков — минута работы вместо
  собственного SIP-стека, и он снял половину вопроса до того, как стек понадобился.
- **Два участника не доказывают сетку.** При двух «один входящий поток» и «все остальные»
  неразличимы. Любое утверждение вида «каждый видит каждого» проверяется минимум на трёх.
- **Собственный минимальный клиент протокола — законный инструмент.** `sip-probe.js` (SIP/RTP на
  встроенных модулях Node) даёт то, чего не даёт ни браузер, ни `confbridge list`: счёт пакетов по
  SSRC на отдельных портах, то есть пришедшее, а не согласованное.

## Tools & Libraries

- `asterisk-manager` — AMI, лежит в корневых `node_modules` (используется бэкендом)
- `mysql2/promise` — realtime-схема PJSIP (`ps_endpoints`, `ps_auths`, `ps_aors`)
- `sip.js@0.21.2` — ровно та версия, что в продукте; брать из `node_modules`, не с CDN
- `esbuild` из `node_modules/.bin` — разовая сборка браузерного бандла
- Встроенные `node:http`/`node:https` вместо `fetch`: тестовая АТС может отдавать самоподписанный
  сертификат, а `rejectUnauthorized: false` через них задаётся без плясок с undici
