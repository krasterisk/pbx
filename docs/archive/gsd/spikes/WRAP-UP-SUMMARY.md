## Key Findings

**Ворота ресёрча.** R-ENGINE и R-VIDEO закрыты: ConfBridge с нативным `video_mode=sfu`. Внешний SFU
не нужен, запасной вариант D-22 не задействуется. Собственный ARI-бридж отпадает — ConfBridge сам
раздаёт сетку, обслуживает классические телефоны, транскодирует аудио и ведёт переговоры о потоках.
Зависимые решения **D-02, D-10, D-34, D-38** можно фиксировать на ConfBridge.

R-CAPACITY остаётся открытым, но получил единицу учёта: **поток, а не участник**. Комната на N
человек с видео — это N·(N−1) исходящих потоков.

**Правило бюджета.** Участник видит N собеседников только при `max_video_streams >= N + 1`: один
слот всегда занят его собственным потоком. Дефолт равен 1, поэтому любой сегодняшний абонент
видео-слеп по построению. Это же число — потолок плиток, то есть оно связано с «Максимальное число
участников: N» из D-20.

**Поправка к D-02.** `video_mode` динамике не поддаётся. Платформа держит статический bridge-профиль
в `confbridge.conf` (перезагружается `module reload app_confbridge.so`), тенантные настройки едут
поверх через `Set(CONFBRIDGE(bridge,template)=…)` — это проверено и работает.

**Поправка к D-23.** Видео аппарату определяет не совпадение кодека, а бюджет потоков — параметр
провижининга, а не свойство телефона.

**Клиентский блокер.** Стоковый `sip.js` останавливает предыдущий удалённый видеотрек при каждом
новом, до вызова делегата. Без подмены `setRemoteTrack` сетка невозможна в принципе, и выглядит это
обманчиво здорово: сессия установлена, кодеки согласованы, `framesDecoded` растёт, экран чёрный.

**Эксплуатационный блокер.** Канал без `BYE` остаётся участником и держит слот SFU; накопление таких
каналов лишает живых участников видео раньше, чем упрётся `max_members`. Нужна серверная чистка.

**Снятое ограничение.** Ранний вывод спайка 002 о том, что единый кодек (D-25) — условие
работоспособности звонка, оказался следствием собственной ошибки: клиенту не нужно заранее
предлагать несколько recvonly-слотов. С одним видео-m-line INVITE укладывается в 7.4 КБ даже с
полным списком кодеков. D-25 возвращается в разряд решений о совместимости.
