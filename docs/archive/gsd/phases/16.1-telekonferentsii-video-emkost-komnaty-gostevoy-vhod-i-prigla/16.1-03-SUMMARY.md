# Phase 16.1 Plan 03: WebRTC video provisioning Summary

**NAT_PROFILES.webrtc + companion fallback get `max_video_streams=16` and VP8; existing `ew*` are backfilled on boot; guests read the same ICE/WSS config by opaque token.**

## Performance

- **Duration:** 6 min
- **Started:** 2026-09-16T07:19:42Z
- **Completed:** 2026-09-16T07:25:24Z
- **Tasks:** 2
- **Files modified:** 7

## Accomplishments

- `NAT_PROFILES.webrtc.max_video_streams` is 16; `createCompanionTriple` fallback allow is `CONFERENCE_PLATFORM_CODECS.join(',')` (`opus,ulaw,vp8`).
- Primary `e*` / `NAT_PROFILES.nat` stay audio-only; an explicit `primary.allow` is not rewritten.
- `EndpointsService.backfillWebrtcVideo()` selects `id LIKE 'ew%'`, lifts streams to 16, appends `vp8` when missing, and is idempotent.
- `GET /conferences/guest/:token/webrtc-config` returns `{ wssUrl, iceServers }` under `ConferenceGuestTokenGuard` (401 without a live token). No SIP password.

## Decisions Made

- Named exports `WEBRTC_ENDPOINT_DEFAULTS` and `NAT_ENDPOINT_DEFAULTS` so specs assert `max_video_streams` without reflecting the private `NAT_PROFILES` table.
- Backfill runs every boot from `ConfbridgeStaticProfileService.onApplicationBootstrap` `finally`, including the early-return path when the static profile is already present.
- Guest webrtc-config is a separate controller sharing `conferences/guest`; payload is copied from `CallCenterWebrtcController` and never includes SIP credentials.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Backfill on every boot, not only after a profile write**
- **Found during:** Task 2 GREEN
- **Issue:** Calling backfill only after a successful static-profile write would skip existing installs whose `krsk_conf_sfu` is already loaded.
- **Fix:** `backfillWebrtcVideo()` runs in `finally` after the profile step (success, no-op, or write failure).
- **Files modified:** `confbridge-static-profile.service.ts`
- **Verification:** `confbridge-static-profile.service.spec.ts` still green; backfill is mocked and invoked
- **Committed in:** `1e4be0e` (Task 2 GREEN)

**2. [Rule 3 - Blocking] Constructor inject instead of ModuleRef.get**
- **Found during:** Task 2 GREEN
- **Issue:** Plan allowed `ModuleRef.get(EndpointsService)` or a factory; constructor injection is the existing Nest style and required a third argument on the static-profile spec.
- **Fix:** Inject `EndpointsService` directly; pass a `backfillWebrtcVideo` mock in the spec.
- **Files modified:** `confbridge-static-profile.service.ts`, `confbridge-static-profile.service.spec.ts`
- **Verification:** static-profile suite 7 passed
- **Committed in:** `1e4be0e` (Task 2 GREEN)
