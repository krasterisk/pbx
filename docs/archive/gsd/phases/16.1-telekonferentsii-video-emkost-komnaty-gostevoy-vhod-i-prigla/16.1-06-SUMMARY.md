# Phase 16.1 Plan 06: Overlay имён и ingest телеметрии Summary

**Гость хранит display_name на токене (64 графемы), staff — только in-memory overlay; телеметрия принимает три поля через ingest allow-list, мусор глотает и отвечает 200, ключ комнаты из JWT path / guest token.**

## Accomplishments

- Guest join writes truncated `display_name` on the token and `rememberDisplayName` so AMI Join copies it into `ConferenceParticipantState.displayName`.
- Empty/whitespace guest name without a saved token name is `400 CONFERENCE_DISPLAY_NAME_REQUIRED` and does not create an ephemeral endpoint.
- Staff `POST /conferences/:room_uid/me/display-name` and guest `POST /conferences/guest/:token/me/display-name` never update `ps_endpoints` / users / phonebooks.
- Empty room clears `rememberedNames` next to one-shot grants; the next staff join has no leftover overlay.
- `toConferenceParticipantDto` prefers `state.displayName` over `callerIdName` / `callerIdNum` / `Participant`.
- `ConferenceTelemetryService.ingest` allow-lists `qualityLimitationReason` ∈ none|cpu|bandwidth|other and finite ≥0 `packetsLost` / `totalFreezesDuration`; unknown keys dropped; TTL 60s; no meetings write.
- JWT `POST /conferences/:uid/telemetry` and guest `POST /conferences/guest/:token/telemetry` are `@SkipThrottle`; body.roomUid is ignored.

- JWT telemetry `ForbiddenException` when `resolveCallerRef` is null, same wording as moderation.
