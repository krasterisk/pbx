### T-16.1-06 — closed (was open 2026-09-16)

Ожидалось: stamp + `ConfbridgeKick` + destroy в одном `revoke()`; `join` не минтит triple, если `revoked_at` / `expires_at` уже сработали.

Факт (re-audit L1):

1. `admitLocked` (`conference-guest.service.ts:220-223`) — `findByPk` с `Transaction.LOCK.UPDATE` при живом Sequelize, затем `assertTokenLive`: `revoked_at` → `CONFERENCE_GUEST_TOKEN_REVOKED`, `expires_at` в прошлом → `_EXPIRED`. Тесты: «refuses join when the token was revoked/expired after the guard», «locks the token row before create».
2. `revoke()` (`conference-guest.service.ts:133-145`) — stamp, затем `resolveGuestChannels`: snapshot fast-path, иначе `getActiveChannels()` на `PJSIP/${sipId}-*`, затем `kickGuestChannels` (Kick, Hangup fallback), затем destroy. Тест: «looks up CoreShowChannels and kicks when snapshot has no channel»; пустой lookup всё равно destroy.

**Residual:** если AMI недоступен, Kick пропускается и остаётся только destroy PJSIP (канал уже в мосту может дожить до hangup). То же семейство, что T-16-01-05.
