# Phase 16.1 Plan 05: AMI Originate invite Summary

**Internal JWT invite originates PJSIP/e or ew into `krsk-conf-{uid}`; external Local/{digits}@from-internal{vpbx} is gated by `invite_external_scope`.**

## Accomplishments

- `POST /conferences/:uid/invite` (JWT) calls `assertLiveRoomAccess`, then `AmiService.originate` into `krsk-conf-{uid}` exten `s` priority `1`, HTTP 202 `{ accepted: true }`.
- Internal target is a digit extension: primary `PJSIP/e{ext}_{vpbx}`, companion `PJSIP/ew{ext}_{vpbx}` if primary is missing; both missing → 404 and no Originate; `gst*` → 400.
- External target is sanitized `(target||'').replace(/[^\d+*#]/g,'')`; channel is `Local/${digits}@from-internal${vpbx}` (A2). Empty after strip → 400 `Target is required`.
- External originate requires `invite_external_scope`: owner-only, owner|moderator, or anyone after live-room access. Moderator under owner-scope → 403 `CONFERENCE_INVITE_EXTERNAL_FORBIDDEN`, not «номер не найден».
- AMI throw → `CONFERENCE_INVITE_FAILED`. Audit `conference.invite.internal` / `conference.invite.external`.
