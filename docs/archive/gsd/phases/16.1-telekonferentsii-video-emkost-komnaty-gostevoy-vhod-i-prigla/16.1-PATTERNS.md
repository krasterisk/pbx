## Pattern Assignments

### `guards/conference-guest-token.guard.ts` (guard)

**Аналог:** `packages/backend/src/modules/callcenter/guards/display-token.guard.ts` (полностью прочитан, 57 строк) — структура копируется буквально, три проверки в фиксированном порядке (missing → invalid → revoked → expired):

```typescript
// packages/backend/src/modules/callcenter/guards/display-token.guard.ts:28-51
async canActivate(context: ExecutionContext): Promise<boolean> {
  const req = context.switchToHttp().getRequest<Request & { user?: any }>();
  const token = req.query?.token;

  if (!token || typeof token !== 'string') {
    throw new UnauthorizedException('Display token required');
  }

  const row = await this.displayTokenModel.findOne({ where: { token } });
  if (!row) {
    throw new UnauthorizedException('Display token invalid');
  }
  if (row.revoked_at != null) {
    throw new UnauthorizedException('Display token revoked');
  }
  if (row.expires_at != null && row.expires_at < new Date()) {
    throw new UnauthorizedException('Display token expired');
  }

  // Intentionally omit level/sub — display tokens must never impersonate a user
  req.user = {
    vpbx_user_uid: row.user_uid,
    isDisplayToken: true,
  };

  // Fire-and-forget audit stamp — do not await SSE connect
  row.update({ last_used_at: new Date() }).catch(() => undefined);

  return true;
}
```

**Отличия для `ConferenceGuestTokenGuard` (зафиксированы RESEARCH.md Pattern 2, Pitfall 5, Pitfall 6):**
- Токен приходит из **route param** `:token` (`req.params.token`), не `?token=` — гостевая ссылка `/conf/:token` короче и не режется прокси-логами query-строки.
- `row` ищется в `ConferenceGuestToken` (модель уже существует, см. правку модели ниже), `findOne({ where: { token } })` без доп. фильтра по тенанту — тенант достаётся через FK `room_uid → conference_rooms.vpbx_user_uid` **после** находки строки (нужен second lookup комнаты, как у `ConferenceStateService.registerRoom`).
- `req.user` **шире** аналога (RESEARCH.md, Code Examples → Guest guard):
  ```typescript
  req.user = {
    isGuest: true,
    roomUid: row.room_uid,
    guestTokenUid: row.uid,
    tokenKind: row.kind,
    inviteName: row.invite_name,
    guestVpbxUserUid: room.user_uid,
  };
  ```
  Поле называется `isGuest`, **не** `isDisplayToken` (RESEARCH.md прямо предписывает новое имя, не копировать смысловое поле аналога). **Никогда** `sub`/`level` — это единственное неизменное правило обоих прецедентов (Pitfall 5).
- Гвард регистрируется **на конкретных методах** нового `ConferenceGuestController`, не на классе — по образцу `@UseGuards(DisplayTokenGuard)` на одном методе `events()` в `CallCenterWallboardController` (см. следующий раздел), а не class-level `@UseGuards(JwtAuthGuard)`, который стоит на `ConferenceRoomsController` (строка 20) и «съел» бы `guest` в `ParseIntPipe` (Pitfall 6 — маршрут `GET conferences/:uid` перехватывает `/conferences/guest/...`, поэтому у нового контроллера **отдельный** `@Controller('conferences/guest')`, зарегистрированный в `conferences.module.ts` до/независимо от `ConferenceRoomsController`).
- `last_used_at` fire-and-forget паттерн копируется буквально: `row.update({ last_used_at: new Date() }).catch(() => undefined);`.

### `conference-guest.controller.ts` (controller, request-response + SSE)

**Аналог (форма «один класс — два гарда на разных методах»):** `packages/backend/src/modules/callcenter/callcenter-wallboard.controller.ts` (полностью прочитан, 116 строк) — это **тот же самый** прецедент, что уже задокументирован в 16-PATTERNS.md для `conference-sse.controller.ts`, но здесь он переиспользуется **зеркально**: не «SSE для гостя + CRUD для JWT в одном классе», а «join/leave/telemetry для гостя», причём **живой поток гость получает не отсюда**, а через тот же `ConferenceStateService.getEventStream(roomUid)`, что и `ConferenceSseController` (D-36 — единый поток, единый DTO-маппер `toConferenceRoomStateDto`).

```typescript
// packages/backend/src/modules/conferences/conference-sse.controller.ts:39-63 (уже отгружено Phase 16)
@UseGuards(JwtAuthGuard)
@Sse(':room_uid/events')
events(

  @Param('room_uid', ParseIntPipe) roomUid: number,

  return from(this.roomsService.assertLiveRoomAccess(roomUid, req.user)).pipe(

        startWith({ type: 'fullSnapshot', roomUid, data: snapshot }),
        map((event) => ({
          data: JSON.stringify(toConferenceRoomStateDto(event.data)),
          type: event.type,
          id: String(Date.now()),
        })),
      );
      // ...heartbeat + closed$ takeUntil...
    }),
  );
}
```

**Guest SSE-метод** (`GET conferences/guest/:token/events`) — тот же блок кода, но `@UseGuards(ConferenceGuestTokenGuard)` вместо `JwtAuthGuard`, `roomUid` берётся из `req.user.roomUid` (гвард уже резолвил токен → комнату), не из `@Param`. **Не дублировать** SSE-логику в новом файле — либо переиспользовать приватный метод `ConferenceSseController` через экспорт, либо (проще, раз RESEARCH.md Architecture Diagram рисует отдельный `GET /conferences/guest/:token/events`) скопировать тело метода 1:1 в `ConferenceGuestController`, потому что `@Sse` — декоратор метода конкретного класса, шарить его между контроллерами Nest не даёт.

**Прочие методы контроллера** (`GET /conferences/guest/:token`, `POST /conferences/guest/:token/join`, `POST /conferences/guest/:token/leave`, `POST /conferences/guest/:token/telemetry`) — форма метода `generate`/`revoke` в `CallCenterWallboardController` (JWT-часть того же файла, строки 391-410, не процитирована в 16-PATTERNS.md построчно, но видна по сигнатуре): `@UseGuards(ConferenceGuestTokenGuard)` на каждом, `@Req() req: Request & { user: any }`, делегирование в сервис одной строкой. `join`/`leave` вызывают `conference-guest.service.ts` (создание/удаление ephemeral endpoint + `ConferenceStateService`), `telemetry` — `conference-telemetry.service.ts`.

**SkipThrottle** (Pitfall 8 RESEARCH.md — глобальный throttler 60/мин душит heartbeat): применить `@SkipThrottle({ default: true, global: true })` на SSE-методе, по образцу уже используемого в проекте синтаксиса:

```typescript
// packages/backend/src/modules/ai-chat/ai-chat.controller.ts:112
@SkipThrottle({ default: true, global: true })
@Get('threads')
```
Тот же декоратор — на `POST .../telemetry` (частый ingest от браузера). `join`/`leave` **оставить** под общим лимитом (60/мин из `ThrottlerModule.forRoot([{ name: 'global', ttl: 60000, limit: 60 }])`, [VERIFIED: `packages/backend/src/app.module.ts:217-219`] — token brute-force защита из Security Domain).

### `conference-guest.service.ts` (service, ephemeral orchestration)

**Нет единого файла-аналога — композиция трёх прочитанных прецедентов:**

**1. Создание ephemeral-триплета** — `EndpointsService.createCompanionTriple` (полностью прочитан, `packages/backend/src/modules/endpoints/endpoints.service.ts:159-213`):

```typescript
private async createCompanionTriple(
  vpbxUserUid: number,
  extension: string,
  primary: { context: string; callerid: string | null; department?: string | null; language?: string | null; allow?: string | null; },
  transaction: Transaction,
): Promise<string> {
  const webrtcId = buildWebrtcSipId(vpbxUserUid, extension);
  const existing = await this.endpointModel.findByPk(webrtcId, { transaction });
  if (existing) return webrtcId;

  const password = this.generatePassword();
  await this.authModel.create({ id: webrtcId, auth_type: 'userpass', username: webrtcId, password }, { transaction });
  await this.aorModel.create({ id: webrtcId, max_contacts: 1, qualify_frequency: 60, remove_existing: 'yes' }, { transaction });
  await this.endpointModel.create(
    {
      id: webrtcId, tenantid: String(vpbxUserUid), auth: webrtcId, aors: webrtcId,
      context: primary.context, callerid: primary.callerid, disallow: 'all',
      allow: primary.allow || 'ulaw,alaw,g722,opus', transport: 'transport-wss',
      dtmf_mode: 'auto', language: primary.language || 'ru', department: primary.department || '',
      ...(NAT_PROFILES.webrtc as any),
    },
    { transaction },
  );
  return webrtcId;
}

private async destroyEndpointTriple(sipId: string, transaction: Transaction): Promise<void> {
  await this.contactModel.destroy({ where: { endpoint: sipId }, transaction });
  await this.endpointModel.destroy({ where: { id: sipId }, transaction });
  await this.authModel.destroy({ where: { id: sipId }, transaction });
  await this.aorModel.destroy({ where: { id: sipId }, transaction });
}
```

Новые **публичные** методы на `EndpointsService` (RESEARCH.md Pattern 1): `createEphemeralGuestEndpoint({ sipId, password, context, vpbx, maxVideoStreams })` и `destroyEphemeralGuestEndpoint(sipId, vpbx)` — сигнатура шире (принимает `context`/`sipId` явно, не выводит их из `extension`), потому что гостевой `sipId` строится как `gst` + 8 hex (не `e{ext}`/`ew{ext}` — не проходит `SIP_ID_RE`/`PRIMARY_ID_RE` из `endpoint-ids.util.ts`, что нужно: `EndpointsService.remove` не должен пытаться его тронуть). `context` — **обязательно** `conferenceRoomContextName(room.uid)` (не `primary.context`/`from-internal{vpbx}` — Pitfall 2), `password` — из `generateSipPassword()` (уже публичный метод, `endpoints.service.ts:110-113`), `allow` — `CONFERENCE_PLATFORM_CODECS.join(',')` (не `primary.allow`, у гостя primary нет), `max_video_streams: maxVideoStreams` (не жёстко 16 — эффективный лимит комнаты, RESEARCH.md Pattern 1 пункт 4).

**Почему не переиспользовать `EndpointsService.remove`:** — [VERIFIED: `packages/backend/src/modules/endpoints/endpoints.service.ts:896-899`]:
```typescript
async remove(sipId: string, vpbxUserUid: number, userId?: number) {
  if (isWebrtcCompanion(sipId)) {
    throw new BadRequestException('Delete the primary endpoint; WebRTC companion is removed with it');
  }
  ...
}
```
`isWebrtcCompanion` матчит только `^ew.+_\d+$` (`gst*` не матчит), так что технически `remove()` не бросит на `gst*` — но он ищет `endpointModel.findOne({ where: { id: sipId, tenantid: String(vpbxUserUid) } })` и предполагает companion-паттерн (`companionIdOf`) — держать destroy отдельным явным `destroyEphemeralGuestEndpoint` безопаснее и однозначнее (Pitfall 7).

**2. Синхронный revoke = Kick + destroy** — `ConferenceModerationService.runAmi` (полностью прочитан, `conference-moderation.service.ts:104-121`):


Гостевой revoke копирует именно эту форму `AmiService.action({ action: 'ConfbridgeKick', conference, channel })` (не изобретать `AmiService.kick()` — метода такого нет, `action` — единственный низкоуровневый вызов). `conference` — снова `normalizeTarget('conference', { source: 'fixed', value: room.number }, vpbx)`, тот же паттерн, что у `runAmi` и у `ConferenceStaleChannelSweeperService.runOnce` (`conference-stale-channel-sweeper.service.ts:40-44`).

**Порядок операций revoke** (RESEARCH.md Pattern 2, Pitfall 4 — не только `revoked_at`):
```typescript

// 3. await this.endpointsService.destroyEphemeralGuestEndpoint(token.sip_id, vpbx);
```

```typescript
export const STREAM_KBPS = 800;
export function maxParticipantsForBudget(budgetStreams: number): number {
```

### `conference-capacity.service.ts` (service, `@Cron` пересчёт)

**Аналог:** `conference-stale-channel-sweeper.service.ts` (полностью прочитан, 64 строки, уже часть Phase 16) — **точный** прецедент `@Cron` + guard против накладывающихся прогонов + перебор активных комнат через `ConferenceStateService`:

```typescript
// packages/backend/src/modules/conferences/conference-stale-channel-sweeper.service.ts:9-30
@Injectable()
export class ConferenceStaleChannelSweeperService {
  private readonly logger = new Logger(ConferenceStaleChannelSweeperService.name);
  private running = false;

  constructor(

    private readonly amiService: AmiService,

  @Cron('*/1 * * * *')
  async tick(): Promise<void> {

    this.running = true;
    try {
      await this.runOnce();
    } catch (err: any) {
      this.logger.warn(`stale channel sweeper failed: ${err?.message || err}`);
    } finally {
      this.running = false;
    }
  }

  private async runOnce(): Promise<void> {
    const roomUids = this.stateService.getActiveRoomUids();
    if (roomUids.length === 0) return;
    if (!this.amiService.isConnected()) return;
    ...
  }
}
```

Копировать 1:1 структуру `@Cron('*/30 * * * * *')` (интервал 30 сек, RESEARCH.md Pattern 3), `if (this.running) return; ... finally { this.running = false; }`. Тело `runOnce()`:
1. `roomUids = this.stateService.getActiveRoomUids()` (тот же метод сортировки живых комнат).

## Shared Patterns

### Opaque-токен, `req.user` без `sub`/`level`, fire-and-forget `last_used_at`
**Источник:** `DisplayTokenGuard` (уже задокументирован в 16-PATTERNS.md, переиспользуется 16.1 буквально для `ConferenceGuestTokenGuard`) — три проверки в фиксированном порядке, поле-маркер (`isGuest`, не смысловое поле аналога), `row.update({ last_used_at: new Date() }).catch(() => undefined)`.

### `AmiService.action({ action, conference, channel })` — единственный низкоуровневый вызов на все ConfBridge-AMI-действия
**Источник:** `ConferenceModerationService.runAmi` + `ConferenceStaleChannelSweeperService.runOnce` — оба строят `conference` через `normalizeTarget('conference', { source: 'fixed', value: room.number }, vpbx)` и передают `channel` живого участника. `conference-invite.service.ts` использует смежный `AmiService.originate(...)`, тот же `AmiService`, тот же слой.

### Стабильные HTTP-коды ошибок через `conferenceRoomHttpError` builder
**Источник:** `conference-rooms.service.ts:44-55` — `{ code, message, params }` body, статус мапится на конкретный `HttpException` подкласс. Расширить `ConferenceRoomErrorCode` union новым значением, не заводить второй builder.

### `@Cron` с guard против накладывающихся прогонов
**Источник:** `ConferenceStaleChannelSweeperService` (уже в 16-PATTERNS.md, здесь — прямое переиспользование для `ConferenceCapacityService`): `if (this.running) return; this.running = true; try { ... } finally { this.running = false; }`.

### Best-effort dialplan apply после DB-мутации, best-effort AMI reapply после капасити-пересчёта
**Источник:** `conference-rooms.service.ts` (`create`/`update`, строки 154-160, 220-227) — `try { await this.applyRoom(...) } catch (e) { this.logger.error('...; DB saved — retry/re-save may be needed: ...') }`. `ConferenceCapacityService` копирует тот же контракт при периодическом reapply `max_members`.

### Чистая формула без I/O, отдельный `*-util.ts` файл
**Источник:** `conference-entry-policy.util.ts` — docstring «No I/O, no exceptions», один вход/один выход. `conference-capacity.util.ts` — тот же контракт для `maxParticipantsForBudget`/`streamsForParticipants`/`effectiveMax`.

### In-memory keyed Map + `Date.now()`-touch + threshold-проверка
**Источник:** `ConferenceStateService.lastSignalAt` / `isStale` / `touch` — прямой прецедент для `ConferenceTelemetryService`'s TTL store, ключ `${roomUid}:${ref}` вместо `channel`.

### `SkipThrottle({ default: true, global: true })` на высокочастотных не-CRUD эндпоинтах
**Источник:** `ai-chat.controller.ts` (10+ мест), `endpoints.controller.ts` (`bulk/active`, `bulk/status/:jobId`, `:sipId/credentials`) — применить на guest SSE, telemetry ingest, capacity poll (Pitfall 8, RESEARCH.md).

### `alterIdempotent` для добавления колонки без миграционного фреймворка
**Источник:** `setup-conferences-schema.ts:84-104`, уже используется для `conference_room_moderators.role` — перехватывает `Duplicate column name`/`already exists`, логирует «already applied / absent — ok», не бросает. Переиспользовать функцию как есть для `display_name`/`sip_id`.
