### Evidence (L1)

1. **T-16.2-01** — `safeConferenceRecordingPath` копирует voicemail-guards: `..`, `path.isAbsolute`, `/^[A-Za-z]:/`, `startsWith(prefix)`. Спеки отвергают `../secret.wav`, абсолютные POSIX/Windows пути и escape за `records_base_path`.
2. **T-16.2-02** — `startForMeeting` строит rel только из vpbx/room/meeting uid. `startByModerator` принимает `_body` и не читает путь. `streamMeeting` сравнивает stored rel с `conferenceRecordingRel` и стримит только совпадение.
3. **T-16.2-03** — CR-01: пустой список uniqueid / нет viewer / нет `CdrService` → 404, не стрим. Чужой `roomUid` падает на `findOne`.
4. **T-16.2-04** — `findRecordingsByUniqueids` пропускает id, на которых `findByUniqueid` бросает; модалка CDR играет уже отфильтрованный play path.
5. **T-16.2-05** — контроллер зовёт `assertLiveRoomAccess`; сервис — `assertCanModerate` и запрет, если `record_mode` не `button`/`both`.
6. **T-16.2-06** — `toConferenceRoomStateDto` не несёт filesystem path / `conf{number}_{vpbx}`. History/CDR AudioPlayer: `conferenceMeetingPlayUrl` + `?token=`.
7. **T-16.2-07** — `handleJoin` → `resolveRoom` / `hydrateRoom` → только тогда `persistJoin`. `parseConferenceName` требует префикс `conf` и суффикс `_{vpbx}`.
8. **T-16.2-08** — `listByRoom` не отдаёт `channel` / `uniqueid` в participants (uniqueid только во внутреннем `listParticipantUniqueids` для ACL).
9. **T-16.2-09** — accepted, см. лог ниже.
10. **T-16.2-SC** — 16.2-01…04 SUMMARY: `tech-stack.added: []`.

**Residual (non-blocking):** `ConferenceModerationService` и `CdrService` помечены `@Optional()`. Play уже fail-closed без CDR. Start/stop без moderation-бина пропустят role-check — в `ConferencesModule` бин есть; тесты инжектят мок.
