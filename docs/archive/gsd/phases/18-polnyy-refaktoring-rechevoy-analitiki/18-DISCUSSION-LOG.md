## Включение и маршрут

### Как включать автоматический анализ?

| Option | Description | Selected |
|--------|-------------|----------|
| Решает маршрут: селект проекта при включённой записи | | |
| Пустой селект означает проект компании | | |
| На усмотрение: решает маршрут | | |

**User's choice:** Решает маршрут, не проект и не default компании. Проект — перечень и редактор метрик. В RouteFormModal рядом с записью: если модуль аналитики включён и запись не «Не записывать», показывается селект проекта. Проект выбран — на маршрут вешается hangup_handler. После завершения звонка handler отдаёт уже закрытый файл в задание. Задание ждёт, пока файл есть и не пустой; пустую или не появившуюся запись не разбирает. Распознавание внутри handler не выполняется. Проект не выбран — автоматического разбора нет. Режимы inherit/off/on заменяются этим селектом.

| Старую версию не включать | | |
| Отметка только от метрик | | |

**User's choice:** Новая версия только на следующие разборы. Черновик, затем публикация. Подсказки у редактора, шаблонов, публикации и селекта маршрута. Проверка шлёт реальный запрос. Доставка идёт в очередь вебхуков кабинета, отказ виден в журнале событий. Удаление проекта оставляет разговоры и снимает проект с маршрутов.

## Дашборд

| Option | Description | Selected |
|--------|-------------|----------|
| Стандартный экран без конструктора | | |
| Сумма последних прогонов | | |
| Инсайты отдельно от суммы разговоров | | |
| Скил поставки и модель в настройках модуля | | |

**User's choice:** Конструктор из aiPBX не переносим. Стандартный экран: карточки, выводы-инсайты, настроение, успех, шкалы, свои метрики, динамика. Клик по сегменту открывает журнал. Модель инсайтов — настройка модуля из списка платформы; если не выбрана, берётся модель разбора. Системный промпт проекта добавляется как контекст.

Если модель проекта молчит, берётся умолчание модуля, если оно другое. Если молчит и оно — ошибка разбора, можно пересобрать. Запасной вне списка платформы нет.
