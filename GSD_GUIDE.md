# GSD в Krasterisk v4

Default — `codex-direct`: один координатор назначает ограниченную работу и один канонический PLAN. GSD workflow используется по явному запросу либо после передачи управления; наличие старой фазы не назначает её исполнение. [Правила координации](docs/development/HYBRID-WORKFLOW.md), [индекс](docs/CANONICAL_REFS.md), [реестр](docs/plans/EXECUTION-REGISTRY.md).

## Где хранить материалы

- Постоянные требования и принятые решения — `docs/`; планы и краткие итоги инициатив — `docs/plans/`.
- Исторические фазовые документы и прежний master roadmap — `docs/archive/gsd/`. Архив не является новым назначением; не дописывать в него новую инициативу.
- `.planning/` — локальная игнорируемая рабочая область runner: состояние сессии, черновые планы, research/intel snapshots, временные сценарии и приватные данные. В clone её нет; не коммитить через force-add.
- Поддерживаемые проверки — `tools/`/`harness/`, синтетические входы — `tests/fixtures/` или пакетные test fixtures.
- Сборки проверок, логи, скриншоты, записи и сырые результаты — внешний `ARTIFACTS_ROOT/runs/<initiative>/<run-id>/` через `tools/artifacts`.

Подробная [политика структуры](docs/development/REPOSITORY-LAYOUT.md). Не зеркалить рабочую область в Git: координатор выборочно переносит принятые требования, решения и краткие результаты.

## Явно назначенный GSD-run

1. Прочитать AGENTS, канонический индекс, архитектуры и актуальный EXECUTION. Сверить ветку, HEAD, dirty baseline и владельцев; не сбрасывать чужие изменения.
2. Зафиксировать передачу управления выбранному workflow, один PLAN/revision и scope. Проверить поддержку текущим runner: не считать названия моделей GSD настройками Codex.
3. Для установленного GSD использовать его help и существующие команды `discuss → plan → execute → verify` только в назначенной области. Локальный runner может требовать свои STATE/config под `.planning`; это не делает их каноническими общими документами.
4. После run сохранить принятые решения и результат в назначенном `docs/plans/<initiative>/`; обновить указатель в реестре. Локальный checkpoint может ссылаться на этот PLAN, но не становится вторым master. Не объявлять mock/unit доказательством live/release.
5. Перед завершением оставить handoff: выполненное, проверки, pending gates, owners, точное следующее действие. Не продолжать соседнюю инициативу автоматически.

## Локальная установка

Проектная установка Cursor находится в игнорируемой `.cursor/`; версия читается из `.cursor/gsd-core/VERSION` (на момент миграции 2026-10-21: 1.14.0). Переустановка или изменение vendor skills не входит в структурную миграцию. Команды и paths могут меняться — проверять фактический help перед использованием. Для Codex действует корневой AGENTS; Cursor slash-команды не являются обязательным интерфейсом Codex.

## Проверки перед готовностью

Обязательные проверки проекта: `npm run lint`, `npm run test:backend`, `npm run test:frontend`. Дополнительно запускать проверки назначенного scope. Live DB/SSH/LLM/calls/deploy не запускать лишь потому, что команда встретилась в историческом плане.
