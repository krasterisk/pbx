# DB-02-C — CDR query boundary

Статус: реализован. CDR API использует один контракт на MySQL 8.4 и PostgreSQL 17 без развилки на уровне контроллера.

- Выбор первого/последнего leg для `linkedid` выполняется оконной функцией с явным tie-break по `uniqueid`; порядок и число вызовов не зависят от плана БД. В выборке остаются legacy `calldate`-строки, включая некорректные; временные графики исключают значения, которые не проходят строгий parse/roundtrip. `NULL` в списке помещается после дат.
- Вынесен ограниченный dialect adapter для проверки строковой даты. Остальные фильтры используют bind/replacements; агрегации, разбивка по часам/дням и extension-поиск больше не зависят от MySQL-специфичных выражений.
- Формат `calldate VARCHAR(80)` пока сохраняется. Для текущих отчётов это legacy wall-clock string в `DB_TIMEZONE`; автоматической UTC/DST-нормализации нет. Date-only фильтры включают начало и конец указанного календарного дня; одинаковый локальный час во время DST объединяется в один bucket. Смена этого контракта требует отдельной версии данных и backfill.
- Версионированная миграция `0002-cdr-query-indexes.sql` добавляет tenant/date и tenant/linkedid/date индексы на обоих движках. Исходные файлы `0001` и их checksums не изменены.
- Golden fixture покрывает tenant 0/A/B, transfer, одинаковое время legs, Unicode, invalid/NULL дату, pagination, фильтры, CSV, статистику и графики. CDR JSON/CSV ответы на обеих БД совпали.

Срез D1 получает только reader/report scope КЦ; provision Asterisk queue_log/writer остаётся DB-03. Автообзвон передавать в D2 только после handoff его действующего владельца.
