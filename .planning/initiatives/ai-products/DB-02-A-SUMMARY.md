# DB-02-A — schema и versioned baseline

2026-09-18, `codex-direct`, назначение в [EXECUTION](EXECUTION.md); [DB-02 plan](DB-02-PLAN.md), slice A. PostgreSQL baseline добавлена как статический versioned artifact с тем же logical ID `0001-current-schema.sql`, что и существующая MySQL baseline. PostgreSQL selection открыт в manifest **только для clean schema install**. [Независимое ревью](DB-02-A-REVIEW.md) завершено без открытых P0/P1/P2. Это не означает готовность AppModule, seed, бизнес-запросов или Asterisk на PostgreSQL.

Машинный [schema inventory](evidence/db-02-a/schema-inventory.json) сравнивает явный список AppModule моделей с исходной MySQL baseline: 112 таблиц, 1447 колонок, без пропусков по именам, типам и NULL там, где это задано моделью. Замороженный hash декораторов/объявленных типов всех моделей обнаруживает изменения default, PK, identity, unique/index и FK/association options; отрицательные mutation tests проверяют default и unique. Единственное намеренное расхождение по типам — 99 `ps_endpoints` полей `VARCHAR(40)` представлены как `TEXT` из-за ограничения inline row InnoDB; PostgreSQL baseline сохраняет это расширение. Генератор inventory только читает исходники и SQL, не подключается к БД и не вызывает `sync`.

47 `DataType.NOW` в моделях — это Sequelize-side defaults, а не обязательные DB defaults; исходный MySQL DDL не задавал для них `DEFAULT CURRENT_TIMESTAMP`. PostgreSQL baseline сохраняет это различие. Прямые SQL/Asterisk writers должны передавать значения там, где колонка обязательна; введение server default потребует additive migration.

PostgreSQL DDL явно описывает 40 ENUM, `GENERATED BY DEFAULT AS IDENTITY`, JSON, DECIMAL/BIGINT, boolean, ограничения unsigned, UTC `TIMESTAMPTZ`, 12 FK после всех таблиц, отдельные индексы FK и проверку UTF8 encoding. Offline helper производит проверяемый draft из закреплённого source hash; production runner использует лишь статический artifact, не транслирует MySQL SQL на лету. Оригинальный MySQL 0001 остаётся byte-identical, SHA-256 `8c18e47d94da3c3aeca3807eb44dbd0280433c1dedf96bef36470203d699543d`. Новый PostgreSQL artifact SHA-256 `a7d418f512e6534c8d94bcf90fef4be28263634a5eb1c5774a787baa89d1720f`.

На текущем snapshot моделей новых таблиц/полей сверх MySQL 0001 нет, поэтому additive 0002 artifact не требуется. При следующем изменении моделей inventory test должен упасть; изменения после применённой 0001 оформляются новыми versioned migrations для обоих engines, без переписывания baseline. Все [46 legacy DB entry points](DB-02-A-LEGACY-MAPPING.md) классифицированы; они не входят в canonical install/upgrade. Невключённые historical constraints и непомеченные MySQL installations требуют отдельного data-aware upgrade review.

На выделенном тестовом сервере PostgreSQL 17.11 baseline прошла через открытый manifest и runner: чистая установка, 114 таблиц включая журнал/state, 1454 колонки включая metadata, type/FK/ENUM/index checks, no-op replay и общие failure/lock/history contracts — 9/9. MySQL 8.4.11 — 9/9; тест сохранил fixture-данные при replay и подтвердил исходный checksum. Логи — в [evidence/db-02-a](evidence/db-02-a/). Одноразовые контейнеры и remote temp dirs удалены, чужие контейнеры и БД не менялись. Локальный Docker не использовался.

`npm run test:db:schema` и новый шаг в `.github/workflows/database-contracts.yml` сохраняют schema drift gate в CI для обоих dialect jobs. Проверка не устанавливает БД и не использует локальный Docker.

Границы: existing unversioned schema/adoption не автоматизированы; полный MySQL legacy upgrade требует проверяемой стратегии для загрязнённых данных и отдельных historical constraints. `queue_log`/CEL и live Asterisk/ODBC принадлежат DB-03. Seed/readiness/auth/provider AppModule и business query parity принадлежат следующим срезам DB-02. Соседний autodial diff не редактировался.
