# AI-01-C1 — общий каталог AI-провайдеров

`AiConnectivityModule` owns the single `cc_ai_providers` model and provider service. The legacy `ai-agents` model, DTO, service and cipher paths are compatibility re-exports. `ai-chat` and `voicemail` import the neutral module directly; neither needs the robot management module to resolve providers. Existing provider UIDs and stored ciphertext are unchanged.

Provider management responses use an allowlist. They expose `secretConfigured` and the legacy `has_key` flag, but never ciphertext, arbitrary `defaults`/`pricing` properties, URL userinfo or query parameters. The stored endpoint remains unchanged for the actual connection. Operators should move credentials embedded in old endpoints to the dedicated `apiKey` field before editing such a provider.

`revisionForOperation(tenantUid, providerUid, capability)` returns a frozen, nonsecret admission snapshot and a server-only credential reference. `resolveCredential` re-queries the row with tenant, enabled and capability conditions immediately before provider I/O. Even `auth_type=none` must pass this check. C1 does not persist revisions; durable jobs and their policy belong to AI-02/D1. The operation may use its admitted endpoint/settings if an admin changes configuration concurrently; disabling or deleting the row prevents a later request from obtaining authorization.

Encryption writes `v2:<key-id>:<base64 AES-256-GCM envelope>` and never uses a development key outside Jest. Production/self-hosted installs using provider keys must set `CC_AI_KEY_SECRET` to at least 32 UTF-8 bytes; `CC_AI_KEY_ID` defaults to `primary`. A rotated key remains readable when its old ID and secret are present in `CC_AI_PREVIOUS_KEYS_JSON`, for example `{ "old": "the-previous-installation-secret" }`. Legacy unversioned rows use `CC_AI_LEGACY_KEY_SECRET` when it differs from the current installation key. Historical rows encrypted with the former unsafe development fallback require that exact old secret to be supplied deliberately as the legacy key for an operator-reviewed migration. Missing keys, malformed envelopes and bad authentication tags fail closed. C1 does not rewrite ciphertext at startup or provide an automatic rotation command.

`AiConnectivityModule` has no HTTP controllers, listeners or PBX dependencies. An independent provider management route for standalone product compositions and installation-level secret readiness checks are part of AI-01-C2/C3. Existing full-PBX CRUD URLs remain under `/ai-agents/providers` for compatibility.
