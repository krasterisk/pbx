# Spike Manifest

## Ideas

### tenant-teleconference-rooms

Модуль телеконференций Krasterisk (Phase 16): тенантные комнаты с настройками, живая веб-комната
с сеткой видео и ролевым управлением, вход гостя по внешней ссылке через браузер, приглашение
внутренних и внешних абонентов, запись. Спайки закрывают три ворот ресёрча, сознательно оставленных
открытыми на discuss: **R-ENGINE** (медиа-ядро — ConfBridge + AMI против собственного ARI-бриджа),
**R-VIDEO** (сетка видео нативным `video_mode=sfu` против внешнего SFU) и **R-CAPACITY** (метрики
живой ёмкости сервера и вес участника).

**Requirements:**

Зафиксировано на discuss (см. `.planning/phases/16-modul-telekonferentsiy-confbridge-webrtc/16-CONTEXT.md`):

- Видео обязательно в v1 — вплоть до внешнего SFU, если нативного режима не хватит (D-22)
- Раскладка — сетка всех участников, а не один говорящий (D-24)
- Веб-участники в приоритете; аппарат получает видео только при совпадении кодека, иначе звук (D-23)
- Настройки комнаты едут динамическим профилем `CONFBRIDGE()` из БД, а не файлом `confbridge.conf` (D-02)
- Тенантное имя комнаты — `conf{номер}_{uid}`, наружу никогда не отдаётся (D-06, D-36)
- Тенанту показывается только число «Максимальное число участников: N» (D-20)

Появившееся во время спайков:

- Эксперименты ставятся на `ipbx.krasterisk.ru` — это тестовый сервер, ломать можно что угодно
- Единый видеокодек платформы (D-25) выбирается из **VP8 или H.264** — только для них собраны модули
  атрибутов формата; `res_format_attr_vp9` в сборке отсутствует (спайк 001)
- Динамический профиль комнаты обязан задавать `video_mode` явно: стоковый `default_bridge` идёт
  с `no video` (спайк 001)
- Индикатор «говорит сейчас» (D-37) требует `talk_detection_events` в user-профиле — стоковый
  `default_user` идёт с выключенными событиями (спайк 001)
