# Phase 16.1: Code Review Report

**Reviewed:** 2026-09-16T08:15:00Z
**Depth:** standard
**Files Reviewed:** 24
**Status:** issues_found

## Summary

Phase 16.1 guest tokens, PIN-before-create, telemetry ingest, and staff display-name overlay are shaped correctly against D-10 / D-12 / D-40 / R-TELEMETRY: opaque 64-hex tokens, six-key `req.user` without `sub`/`level`, guest PJSIP context `krsk-conf-{uid}` (not `from-internal`), telemetry keyed by JWT path / guard room (never `body.roomUid`), staff rename writes only in-memory state. The blockers are on the revoke and capacity refuse paths: `join` does not re-read token liveness, `ConfbridgeKick` is skipped when the in-memory snapshot has no channel, and `max_members` is omitted when `effectiveMax <= 0` (Asterisk treats that as unlimited).

## Narrative Findings (AI reviewer)

## Critical Issues

### CR-01: `join` mints SIP after revoke/expire and is not serialized per token

**File:** `packages/backend/src/modules/conferences/conference-guest.service.ts:75-145`
**Issue:** `ConferenceGuestTokenGuard` is the only place that reads `revoked_at` / `expires_at`. `join` reloads the row by PK and then creates an ephemeral triple without re-checking liveness or locking the row. A revoke that stamps `revoked_at` between `canActivate` and `createEphemeralGuestEndpoint` still issues `{ sipId, password }` for `krsk-conf-{uid}`. The new HTTP surface 401s, but the PJSIP credentials remain valid. The same missing lock lets two parallel joins of one shared_link both see `sip_id = null` (or the same old id), both create `gst*` triples, and both enter the room — breaking D-10 (one token = one live endpoint) and D-21 (capacity refuse).
**Fix:** Re-validate and lock the token inside `join` before create; fail closed if it is no longer live; serialize replace:

```typescript
const token = await this.tokenModel.findByPk(user.guestTokenUid, { lock: transaction.LOCK.UPDATE, transaction });
if (!token || token.revoked_at != null || (token.expires_at != null && token.expires_at < new Date())) {
  throw conferenceRoomHttpError(HttpStatus.UNAUTHORIZED, 'CONFERENCE_GUEST_TOKEN_INVALID', 'Guest token invalid');
}
if (token.sip_id) {
  await this.endpointsService.destroyEphemeralGuestEndpoint(token.sip_id, user.guestVpbxUserUid);
}
// create triple, then token.update({ sip_id, display_name }, { transaction })
```

Refuse create when `revoked_at` is already set even if the guard previously passed.

### CR-02: Revoke skips `ConfbridgeKick` unless the in-memory snapshot already has the channel

**File:** `packages/backend/src/modules/conferences/conference-guest.service.ts:169-197`
**Issue:** After `revoked_at` is stamped, kick runs only when `findLiveParticipant(roomUid, sipId)` returns a channel and `amiService` is present. Destroying the PJSIP triple does not remove a channel already in ConfBridge. Snapshot miss is the common case after process restart (state is empty until AMI hydrate), when Join has not arrived yet but the guest is mid-INVITE, or when `CallerIDNum` ≠ `sip_id` (`callerid` is set `null` on create). Threat lock is revoke = stamp + kick + destroy. Today a live revoked guest can stay in the meeting with media until they hang up.
**Fix:** Do not key kick solely on `getSnapshot`. After stamp, resolve the channel via `ConfbridgeList` / `CoreShowChannels` for `PJSIP/${sipId}-*` (and `findLiveParticipant` as a fast path), then `ConfbridgeKick` or `Hangup`. If lookup finds nothing, still destroy; if a channel exists, kick must run before destroy. Treat “no snapshot” as “look up live channel”, not “skip kick”.

### CR-03: `effectiveMax <= 0` omits `max_members`, which Asterisk treats as unlimited

**File:** `packages/backend/src/modules/conferences/conference-dialplan.util.ts:94-97`
**Issue:** `emitFilledSettings` writes `CONFBRIDGE(bridge,max_members)` only when `maxMembers > 0`. ConfBridge documents `0` / unset as infinite. HTTP guest join correctly 409s when `capacityForRoom` is `0`, but the 30s cron calls `reapplyDialplan(room, 0)` and regenerates the category **without** a cap — lifting a previous tariff/budget limit. Internal SIP, mask-index, and AMI invite then enter with no member refuse. D-21 is “refuse, do not degrade-without-video”, for every entry path, not only `POST /guest/:token/join`.
**Fix:** When `effectiveMax <= 0`, do not emit `max_members=0`. Emit a refuse before `ConfBridge()` (Playback + Hangup, or Goto busy) so phone/invite paths match the HTTP 409. Keep `max_members=N` whenever `N >= 1`. Never replace a category that had a cap with one that has none because the budget went to zero.

### CR-04: AMI Originate `callerid` interpolates unsanitized `room.name`

**File:** `packages/backend/src/modules/conferences/conference-invite.service.ts:163-169`
**Issue:** `originate(channel, `"${room.name}" <${room.number}>`, ...)` passes the tenant-controlled name straight into an AMI header. `CreateConferenceRoomDto.name` is only `@Length(1, 255)` — CR/LF and extra quotes are legal. `asterisk-manager` serializes `callerid` as a raw AMI line. A tenant admin can inject additional AMI actions (originate/hangup/command) and break tenant isolation. Dialplan emission sanitizes the same name via `sanitizeDialplanInput`; originate does not.
**Fix:** Strip `\r\n` and quotes (or reuse `AsteriskDialplanUtils.sanitizeDialplanInput`) before building callerid; keep `room.number` as digits-only (already enforced). Prefer a fixed callerid such as `"Conference" <${room.number}>` if the display name is not required on the ringing leg.

## Warnings

### WR-01: `destroyEphemeralGuestEndpoint` deletes auth/aor by id with no `gst` prefix or tenant check

**File:** `packages/backend/src/modules/endpoints/endpoints.service.ts:155-160`
**Issue:** Endpoint delete is scoped `{ id, tenantid }`, but `ps_auths` / `ps_aors` are destroyed by `id` only. `join` / `revoke` / `leave` pass `token.sip_id` through unchecked. A poisoned or colliding `sip_id` (not `gst[0-9a-f]{8}`) would wipe a staff endpoint’s credentials while leaving or partially deleting the `ps_endpoints` row.
**Fix:** Fail closed unless `/^gst[0-9a-f]{8}$/.test(sipId)`; destroy auth/aor only after the tenant-scoped endpoint delete affected a row.

### WR-02: Ephemeral guest triple is created without a transaction

**File:** `packages/backend/src/modules/endpoints/endpoints.service.ts:127-152`
**Issue:** `auth` → `aor` → `endpoint` are three independent inserts. A failure after auth/aor leaves a registerable username without a matching endpoint (or the reverse). `join` then never writes `sip_id`, so revoke/leave cannot clean it up. Companion create in the same service already uses a transaction.
**Fix:** Wrap the three inserts (and destroy) in one Sequelize transaction, matching `createCompanionTriple`.

### WR-03: PIN compare is not constant-time; ValidationPipe can mask `CONFERENCE_PIN_*`

**File:** `packages/backend/src/modules/conferences/conference-guest.service.ts:81-96`
**Issue:** `pin !== policy.pin` leaks length/mismatch timing on a short shared secret. `@Matches(CONFERENCE_PIN_PATTERN)` on the DTO also turns a 3-digit or spaced attempt into a generic 400 before `CONFERENCE_PIN_REQUIRED` / `CONFERENCE_PIN_WRONG`. PIN-before-create itself is in the right place and `!requiresPin` ignores `dto.pin`.
**Fix:** Compare with `crypto.timingSafeEqual` on equal-length buffers (pad both sides); keep `@IsOptional() @IsString()` on `pin` and enforce the digit pattern in the service so error codes stay stable.

### WR-04: Admission and `max_members` cron do not cover the same moment

**File:** `packages/backend/src/modules/conferences/conference-guest.service.ts:98-107`
**File:** `packages/backend/src/modules/conferences/conference-capacity.service.ts:60-75`
**Issue:** `nThis + 1 > max` is a snapshot read with no lock. Two different tokens at `n === N - 1` both create endpoints. Cron only reapplies rooms already in `getActiveRoomUids()` (non-empty); a new/empty room keeps create/update tariff `max_members` until the first join + next 30s tick. D-21 can be raced on the HTTP path; the Asterisk cap lags the budget.
**Fix:** Re-read `capacityForRoom` under the same transaction/lock as token replace, or reserve the slot in state before create. Run the capacity tick for registered rooms with zero participants, not only live ones.

### WR-05: `leave` destroys the triple but does not kick the live ConfBridge channel

**File:** `packages/backend/src/modules/conferences/conference-guest.service.ts:200-218`
**Issue:** Guest `POST :token/leave` nulls `sip_id` and destroys PJSIP. An already-bridged WebRTC session keeps media. The token stays valid, so the client can `join` again and mint a second identity while the first channel is still counted in `nThis`.
**Fix:** Same channel lookup + `ConfbridgeKick`/`Hangup` as revoke, then destroy. Keep `revoked_at` null.

## Info

### IN-01: 64 graphemes can exceed `VARCHAR(64)` code points

**File:** `packages/backend/src/modules/conferences/dto/conference-participant.dto.ts:29-31`
**Issue:** `[...value].slice(0, 64)` keeps 64 JS code points. A ZWJ emoji sequence is many code points per glyph; MySQL `utf8mb4` `VARCHAR(64)` counts characters. `token.update({ display_name })` can 500 on an otherwise valid D-40 name.
**Fix:** Truncate to a conservative byte/char budget after grapheme slice, or store `VARCHAR(255)` and keep the 64-grapheme UI cap.

### IN-02: Opaque token lives in the URL path

**File:** `packages/backend/src/modules/conferences/conference-guest.controller.ts:44-86`
**Issue:** `:token` appears on GET/POST/SSE. Access logs, proxies, and `Referer` can retain the secret. Construction (`randomBytes(32)` hex + unique index + six-key `req.user`) is otherwise sound.
**Fix:** Prefer `Authorization: Bearer` or a query that is stripped from access logs; keep path tokens out of application `logger.log`.
