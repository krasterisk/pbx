## API error body contract

Источник формы: `conferenceRoomHttpError` в `conference-rooms.service.ts` —
тело **всегда** `{ code, message, params }`. `message` — английский, для логов.
Тенант видит только локаль по `code`. 16.3 **запрещено** рендерить `message` как есть.

Новые коды 16.1 (расширяют `ConferenceRoomErrorCode`, не заменяют уже отгруженные
`CONFERENCE_ROOM_NOT_FOUND` / `CONFERENCE_PIN_REQUIRED` / …):

| HTTP | `code` | `message` (API, EN) | Locale 16.3 | Когда |
|------|--------|---------------------|-------------|-------|
| 409 | `CONFERENCE_ROOM_FULL` | `Conference room is full` | `live.full` + `live.fullHint` | Web-join гостя или participant, если `n + 1 > effectiveMax`. Деградация «без видео» запрещена (D-21) |
| 401 | `CONFERENCE_GUEST_TOKEN_REVOKED` | `Guest token revoked` | `guest.linkInvalid` + `guest.linkInvalidHint` | `revoked_at != null` |
| 401 | `CONFERENCE_GUEST_TOKEN_EXPIRED` | `Guest token expired` | `guest.linkInvalid` + `guest.linkInvalidHint` | `expires_at < now` |
| 401 | `CONFERENCE_GUEST_TOKEN_INVALID` | `Guest token invalid` | `guest.linkInvalid` + `guest.linkInvalidHint` | Токен не найден или не hex |
| 400 | `CONFERENCE_PIN_REQUIRED` | существующий код Phase 16 | поле PIN + `guest.pinField` | Join без PIN, когда политика комнаты требует PIN |
| 400 | `CONFERENCE_PIN_WRONG` | `Conference PIN is incorrect` | `guest.pinWrong` | PIN передан и не совпал |
| 400 | `CONFERENCE_DISPLAY_NAME_REQUIRED` | `Display name is required` | `guest.nameRequired` | Гостевой join с пустым именем |
| 403 | `CONFERENCE_INVITE_EXTERNAL_FORBIDDEN` | `External invite is not allowed for this role` | `live.inviteExternalForbidden` | Внешний Originate при роли ниже `invite_external_scope` |
| 409 / 502 | `CONFERENCE_INVITE_FAILED` | `Failed to originate invite` | `live.inviteFailed` | AMI Originate отвергнут или канал не собрался |

Правила:

1. **Один экран на три 401 гостя.** Revoked / expired / invalid **не различаются** в UI.
   Нельзя писать «ссылка отозвана» отдельно от «истекла»: это палит, отозвана ли ссылка.
2. **Owner / moderator не получают `CONFERENCE_ROOM_FULL` на web-join** (admin-bypass
   `max_members` в ConfBridge, Pitfall 3 в `16.1-RESEARCH.md`). UI не обещает, что
   организатор увидит 409, если в комнате уже `n > N`.
3. **SIP сверх лимита:** 16.1 не кладёт новый Playback-файл. Трубка слышит штатную
   блокировку ConfBridge после `max_members`. Русский текст D-21 для веба — `live.full`.
4. Guard гостя **не кладёт** `sub` / `level` в `req.user`. Сообщение 401 никогда не
   выглядит как «недостаточно прав администратора».

### Ёмкость (D-18, D-19, D-20, D-21) — LOCKED

`GET /conferences/:uid/capacity` отвечает **ровно** `{ maxParticipants: number }`.
Ни `tariff`, ни `budget`, ни `source`, ни `remaining`.

| Ключ | ru |
|------|-----|
| `maxMembers` | `Максимальное число участников: {{count}}` |
| `maxMembersHint` | `Значение зависит от вашего тарифа и может отличаться при следующем открытии формы.` |
| `live.full` | `В комнате нет свободных мест` |
| `live.fullHint` | `Попробуйте подключиться позже или попросите организатора освободить место.` |

- Интерполяция только `{{count}}` = `maxParticipants`.
- `N = 0` всё равно рисуется этой строкой: `Максимальное число участников: 0`.
- Если в комнате уже больше людей, чем текущее `N` (admin-bypass, гонка), API
  **всё равно отдаёт N как есть**. Отрицательный остаток, «-3 места» и
  «превышен лимит» **запрещены**. Закрывает unresolved строки ёмкости из
  родительского UI-SPEC на стороне API.
- Число может измениться между двумя GET. Окружающий текст не обещает константу
  (`maxMembersHint` это и говорит).
