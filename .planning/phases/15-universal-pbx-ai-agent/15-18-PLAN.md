<objective>
Make a long turn legible and interruptible: a line per step, a stop button that works, and a conversation that follows the text without fighting the reader.

Purpose: D-09 exists because a turn that reads three tools and proposes a change takes tens of seconds, and a spinner for that long is indistinguishable from a hang. A line per step tells the user what is happening and, incidentally, tells them whether the agent understood the question — the progress line is the cheapest correctness signal in the product. The stop button is the other half: the server already aborts the model request and skips remaining tools on cancellation, and this plan gives that a control.

Output: the stream hook with cancellation and terminal outcomes, the panel's streaming behaviour, and the locale keys for all of it.
</objective>

<task type="auto" tdd="true">
  <name>Task 2: Stop, ceiling, disconnect (D-09)</name>
  <files>packages/frontend/src/features/ai-chat/model/useAgentStream.ts, packages/frontend/src/features/ai-chat/model/useAgentStream.test.ts, packages/frontend/src/widgets/AiChatWidget/AiChatWidget.tsx, packages/frontend/src/widgets/AiChatWidget/AiChatWidget.test.tsx</files>
  <behavior>
    - The stop control replaces the send control while a turn is in flight and returns to send when the turn ends
    - Pressing stop aborts the request, ends the in-flight state and marks the turn as stopped in the conversation
    - Nothing further renders after a stop, even if the fixture stream would have continued
    - A ceiling event renders its own outcome, worded differently from a stop and from an error
    - Losing the connection mid-turn renders a reconnect affordance and keeps the partial answer visible
    - Closing the panel mid-turn aborts the request
  </behavior>
  <action>
Wire the stop control to an abort controller on the stream request. The server turns a closed request into turn cancellation, aborting the in-flight model call and skipping remaining tool calls, so the whole feature on this side is one abort and honest state afterwards.

Ignore any events that arrive after a stop. Without that guard, buffered events already in flight keep rendering after the user pressed stop, which is the exact impression the button exists to prevent.

Distinguish the three terminal non-success outcomes in the copy: stopped by the user, stopped at the step ceiling, and failed. They mean different things to the user — one is their own action, one means the question needs narrowing, one means something broke — and collapsing them into a single failure message wastes the only diagnostic the user gets.

Handle disconnect by keeping the partial answer and offering to reconnect. The turn's messages are persisted as they are produced on the server, so the partial answer on screen corresponds to something real, and discarding it would throw away work that was actually done.

Abort on panel close as well as on stop, since a turn nobody is watching is spending tokens.
  </action>

  <behavior>
    - With the conversation scrolled to the bottom, new content keeps it at the bottom
    - After the user scrolls up, new content does not move the viewport and a jump-to-latest affordance appears
    - Returning to the bottom resumes following
    - A change card arriving mid-stream renders in place and the text continues below it
    - Progress, stop, ceiling, failure, reconnect and jump-to-latest strings all come from the locale files
  </behavior>
  <action>
Implement following as a state derived from the scroll position rather than an unconditional scroll on every update. Unconditional scrolling is why streaming panels yank the viewport away from someone reading an earlier paragraph, and the design contract calls for following only while the user is already at the bottom. Give the bottom detection a small tolerance so a pixel of momentum does not read as scrolling up.

Show a jump-to-latest affordance while not following, and resume following when the user returns to the bottom. Cover all three transitions in tests, because this behaviour breaks in one direction at a time and looks fine in the other.

Render a change card arriving mid-stream in place and continue the text below it, using the card from 15-14. The card is part of the transcript, so the stream must not treat its arrival as a terminal event.

Append the streaming keys inside the existing agent namespace. This plan is the fourth of five writers of these two locale files across the phase, each in its own wave, so append rather than restructure.
