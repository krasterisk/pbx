<objective>
Start the hard migration with the read-only tools and install the precedence rule that makes the migration safe to do in slices.

Purpose: D-27 moves all eighteen handwritten tools onto the adapter registry and deletes the old code. Doing that in one commit is the riskiest possible shape, and doing it in slices creates a window where the same tool name exists twice. The precedence rule closes that window: as soon as an adapter claims a name, the handwritten registration of that name is never registered, so the migration proceeds domain by domain with exactly one live implementation at every point. Read-only tools go first because they need none of the confirmation machinery and they prove the adapter shape cheaply. The state snapshot, which is the remaining read-only tool of the eighteen, is handled in 15-04 instead, because it duplicates the prompt builder's own snapshot and consolidating it belongs where that snapshot lives.

Output: the precedence rule, contexts and call-records adapters, two domain skills, and a registry-enumerated tenant-isolation suite that covers every tool the later slices add without being edited again.
</objective>
