<objective>
Persist agent conversations, their messages, and pending change proposals, with tenant and author in every scope.

Purpose: D-26 replaces in-memory chat history so a user can come back to a conversation and see what the agent did — that is also the forensic record. D-08 needs somewhere to accumulate token counts per tenant; the existing voice-agent call-detail table is unusable for chat because its non-null call identifier and its pipeline-mode enumeration have no chat-shaped values, so usage lands on the conversation rows instead. The proposal table created here is what 15-05 writes and the Apply endpoint reads.

Output: three Sequelize models, a tenant-scoped thread service, a standalone migration script with an npm entry point, and an audit column that links a tool call to its conversation.
</objective>

  <behavior>
    - Creating a thread then listing threads for the same tenant and author returns it, newest first
    - Appending a user message then reading messages returns them in insertion order
    - Listing or reading for a different tenant returns an empty list or not-found
    - Listing or reading for the same tenant but a different author returns not-found

  <action>
Create `AgentThread` on table `ai_agent_threads` and `AgentThreadMessage` on table `ai_agent_thread_messages`. Naming follows the existing chat settings table rather than the contact-centre voice-agent prefix, because these rows belong to the chat agent, not to voice agents; the AI design contract's placeholder names are superseded here and the choice is one-way once rows exist.

`ai_agent_threads` columns: auto-increment `uid` primary key; `vpbx_user_uid` and `user_uid` both non-null integers; `title` string defaulting to empty and auto-filled from the first user message; `status` string defaulting to active with archived as the other value; nullable `provider_uid`; `tokens_in` and `tokens_out` non-null integers defaulting to zero; nullable `last_message_at`; timestamps. Index on tenant, author and last-message time so newest-first listing needs no join.

`ai_agent_thread_messages` columns: big-integer auto-increment `uid`; non-null `thread_uid`; non-null `vpbx_user_uid` denormalized so every query filters by tenant without a join; `role` string over user, assistant, tool and system; nullable text `content`; nullable `tool_name`; nullable JSON `tool_calls`; nullable `proposal_id` char(36); per-message `tokens_in` and `tokens_out`; creation timestamp. Index on thread and message id.

Create `PbxAgentThreadService` with `createThread`, `listThreads`, `getThread`, `appendMessage`, `renameThreadFromFirstMessage`, `deleteThread` and `addUsage`. Every read and write puts `vpbx_user_uid` and `user_uid` into the where clause, and the service must not use primary-key lookup helpers anywhere — that shortcut is exactly how a conversation containing a full configuration dump leaks to another tenant. Deleting a thread removes its messages.

Register all three models in the Sequelize model list in `app.module.ts` — the connection is configured with automatic model loading and schema synchronization both off, so tables come from the migration in task 2. Provide and export the service from `ai-chat.module.ts` and add the models via the Sequelize feature import there.
