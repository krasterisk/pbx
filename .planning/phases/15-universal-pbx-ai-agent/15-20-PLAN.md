<objective>
Extend universal reading to voice robots and the speech engines behind them, resolving the dependency the model would otherwise have to guess at.

Purpose: D-15 makes reading universal, and this trio is a single diagnostic story: a voice robot that does not speak is almost always an engine that is not configured, and today the agent can see neither side. Resolving the engine state inside the robot read is what turns "the robot is broken" into "the speech engine it uses has no configuration", which is the answer.

Output: three read adapters, two grouped domain skills, and a batch spec proving read-only, credential-free and tenant-isolated.
</objective>

    - No returned field contains a provider key, an endpoint credential or an encrypted value
    - The output shape is built from an explicit field allow list
    - Neither adapter declares a tool that synthesises or transcribes audio
    - A call as one tenant returns none of another tenant's engines
  </behavior>
  <action>
Create both engine adapters returning name, vendor, enabled state, capabilities and configured state, built from an explicit field allow list. These entities store encrypted provider keys beside their harmless fields, so removing known-sensitive keys from a full entity is the approach that breaks silently the first time a column is added — and here the consequence is a provider credential in a persisted conversation.

Assert credential absence against the declared output shape rather than the fixtures, so a field the fixture never populates is still covered.

Declare no synthesis or transcription tools. Running a model-triggered synthesis costs money per call with no confirmable diff and no undo, which puts it outside this phase's write boundary; the assertion records the reasoning where the next contributor sees it.
