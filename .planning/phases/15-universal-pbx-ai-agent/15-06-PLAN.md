<objective>
Move the agent from a floating corner button that collides with the softphone into a first-class topbar control, and rebuild the panel wide enough that nothing overlaps.

Purpose: D-24 exists because the current trigger is pinned to the bottom-right at the same coordinates as the Phase 9 softphone chrome, and on mobile it lands on the Phase 8 bottom navigation. The corner stays with the softphone; the agent belongs next to the command palette, where a user already looks for "ask the product something". D-25 exists because the current panel is too narrow for its own contents — the model selector overlaps the composer. This plan delivers the shell and geometry; threads, diff cards and streaming land on top of it in later waves, so it ships as a working panel rather than a frame.

Output: topbar trigger, shortcut, rebuilt panel container with a thread rail slot, and the locale keys the later frontend plans extend.
</objective>

  <name>End-to-end "open the agent from the topbar" — trigger, shortcut, panel, close (D-23, D-24)</name>
  <files>packages/frontend/src/widgets/ModuleShell/ModuleShell.tsx, packages/frontend/src/widgets/ModuleShell/ModuleShell.module.scss, packages/frontend/src/widgets/ModuleShell/ModuleShell.test.tsx, packages/frontend/src/widgets/AiChatWidget/AiChatWidget.tsx, packages/frontend/src/widgets/AiChatWidget/AiChatWidget.test.tsx</files>
  <behavior>
    - The topbar renders the agent trigger as the sibling immediately preceding the command-palette trigger
    - No element with the former floating trigger class renders anywhere in the shell
    - The agent shortcut opens the panel; pressing it again closes it; the command-palette shortcut still opens the palette and not the panel
    - Escape closes an open panel and returns focus to the trigger
    - Tab from the last focusable element inside an open panel returns to the first, and never reaches the page behind
  </behavior>
  <action>
Add the agent trigger to the topbar as the element directly before the command-palette trigger, matching the palette trigger's own button styling and carrying an accessible label plus the shortcut hint from the design contract. Give it a stable identifier so later plans and tests target it without depending on label text. Hold the open state in the shell, not inside the widget, because the shortcut is registered at shell level and the panel must survive route changes per D-23.

Register the shortcut with the same raw keydown listener pattern the palette shortcut already uses in this file — a single effect adding and removing one window listener. Do not introduce a hotkey library; the existing pattern is the convention and mixing mechanisms makes the two shortcuts diverge in modifier handling. Guard the handler so it fires only with both the platform modifier and shift held, and let the event through untouched otherwise so the palette shortcut is unaffected.

Delete the floating trigger from the widget entirely, including its positioning rules in the widget stylesheet — the bottom-right corner is reserved for the softphone per D-24 and a leftover element with a high stacking value re-creates the collision even if it renders transparent. The panel receives its open state and a close callback as properties.

Implement close on Escape and a focus trap inside the panel: focus moves into the panel on open, cycles within it while open, and returns to the trigger on close. Cover both with tests rather than a manual note, since a trap that silently stops working is invisible until a keyboard user hits it.
  </action>
