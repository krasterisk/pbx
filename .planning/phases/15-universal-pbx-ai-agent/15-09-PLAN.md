<objective>
Migrate the five subscriber and trunk mutations onto adapters, and make each of them a proposal rather than a write.

Purpose: these are the first mutating tools to move, so this plan is where the confirmation gate stops being a mechanism and becomes the behaviour of real tools. The handwritten subscriber creation also carries a debt worth paying off in the move: it generates SIP credentials inside the tool layer, which means the only code path that can create a subscriber with a generated password is the one the agent uses. That belongs in the subscriber service where the interface path can share it. Trunks come along because they are the same shape with a smaller surface, and shipping them together proves the proposal pattern generalises before six more tools follow in 15-10.

Output: two adapters covering five tools, credential generation relocated, two domain skills.
</objective>
