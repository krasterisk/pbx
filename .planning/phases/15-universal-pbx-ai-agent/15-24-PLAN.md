<objective>
Put the model choice and the spend figures where they belong — with the platform administrator — and add the monitoring that would catch a write nobody confirmed.

Purpose: D-07 removes model selection from the tenant entirely, because a tenant choosing a model is a tenant choosing a cost and a capability they have no basis to reason about; the administrator configures providers and a default, and the tenant just gets an agent. D-08 asks for spend to be counted and shown without hard limits, which keeps this phase honest about scope: it reports, it does not police. The monitoring half comes from the approved contract's most consequential signal — a mutating tool result with no matching proposal means the confirmation gate leaked, and that is the one condition worth detecting continuously rather than reviewing weekly.

Output: the usage service with the silent-write detector, administrator-only endpoints, and the administrative card carrying the default model and the usage view.
</objective>

  <action>
Add the funnel and error-rate queries over the audit and proposal tables. These two are the offline signals the approved contract prioritises: a rejection rate that climbs means the agent is proposing the wrong changes, and an error rate concentrated on one tool means a handler is broken in a way no test caught.

Add the silent-write detector as a scheduled check using the in-process interval mechanism this codebase already uses for its scanners, rather than an operating-system scheduler — the project has no such component and introducing one would be untestable runtime state. Query mutating-tool audit rows that lack a matching applied proposal in the window, and log at error level with tenant, tool and row identified.

This detector is the highest-value alarm in the phase because it fails closed against the failure nobody sees: every other guarantee here is enforced by code that could be refactored around, and a mutation with no proposal trail is the observable consequence of any such refactor. Cover both the empty and the non-empty case, since a detector that never fires is indistinguishable from one that cannot.
