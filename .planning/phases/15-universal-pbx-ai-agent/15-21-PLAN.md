<objective>
Close the coverage gap: the last four tenant-facing domains become readable, so the completeness rule in 15-23 has a full set to check rather than a list of exceptions.

Purpose: D-15 says the agent reads everything, and "everything" is only meaningful once no tenant-facing module is left out. These four are the remainder — notifications, audio prompts, service requests and claims. They are small individually and share one property that shapes the plan: all four hold free-text content written by people, so the interesting design work is bounding what a single tool call can pull into a conversation.

</objective>

Clamp the count to a documented ceiling and truncate bodies to a documented preview length, both as named constants asserted in the spec. Declare no mutating tools and assert their absence. Sending a notification is an outward action with no undo, so it sits outside the write boundary this phase opened, for the same reason the messaging channels do.

Establish the bounding pattern here as constants the other three adapters in this plan reuse, so all four have the same ceiling rather than four independently chosen ones.

Create the request and claim adapters as bounded listings reusing the shared ceiling and preview length. These hold customer-written text, so the preview is the mechanism keeping a single call from pulling a quarter's worth of correspondence into a conversation.

Declare no mutating tools across all three. Creating a service request or changing a claim through the agent would place a record into a human workflow with no confirmable diff that means anything to the people working that queue.
