## Summary

Phase 16 already shipped the **schema and room settings** for recording (`record_mode`, `notify_recording`, `conference_meetings`, `conference_meeting_participants`) and a **broken dialplan stub** that sets `CONFBRIDGE(bridge,record_conference)`. It did **not** persist meetings, start/stop recording, stream files, or expose a CDR surface. ConferenceStateService is in-memory only. There is no `/conferences` page and no `ConferenceMeetings` RTK tag.

D-30 means reuse **storage root, access-scope, and Range headers** — not MixMonitor and not the CDR `.mp3` resolver. Official ConfBridge recording is an internal MixMonitor on `ConfBridgeRecorder` started by `record_conference=yes` or AMI `ConfbridgeStartRecord`. Conversation recordings convert WAV→MP3 and store a path without extension; ConfBridge writes **WAV** (8 kHz slin). Playback must follow `safeVoicemailFilePath` + `audio/wav`, or the player 404s.

**Primary recommendation:** One AMI path for auto and button. On first `ConfbridgeJoin`, create a meeting row, `mkdir` the tenant directory, then `ConfbridgeStartRecord` with an explicit `RecordFile` under `records_base_path`. Do not emit `record_conference=yes` (it races AMI and lands files in the monitor directory). Persist participants with AMI `Uniqueid` so CDR can join like voicemail. Ship backend + CDR UI + RTK + a mountable History tab; live-room record chrome stays Phase 16.3.

```88:98:packages/backend/src/modules/voicemail/voicemail.service.ts
export function safeVoicemailFilePath(base: string, rel: string): string | null {
  const cleaned = String(rel ?? '').replace(/^\/+/, '').replace(/\\/g, '/');
  if (!cleaned || cleaned.includes('..') || path.isAbsolute(cleaned) || /^[A-Za-z]:/.test(cleaned)) {
    return null;
  }
  const baseResolved = path.resolve(base);
  const fileResolved = path.resolve(baseResolved, cleaned);
  const prefix = baseResolved.endsWith(path.sep) ? baseResolved : baseResolved + path.sep;
  if (fileResolved !== baseResolved && !fileResolved.startsWith(prefix)) return null;
  return fs.existsSync(fileResolved) ? fileResolved : null;
}
```

**Steel man for `record_conference=yes`:** fewer moving parts; Asterisk stops on last exit. Rejected because (a) path is not under `records_base_path` unless `record_file` is set before `ConfBridge()`, (b) `meeting_uid` does not exist yet, (c) D-05 forbids CURL in the room/mask-index, (d) a second AMI start errors.

## Common Pitfalls

### Pitfall 1: `.mp3` resolver on a `.wav` file
**What goes wrong:** Play 404s; CDR "has recording" is true in DB but silent.
**Why:** `safeRecordFilePath` always adds `.mp3`.
**How to avoid:** Voicemail-style resolver; `Content-Type: audio/wav`.
**Warning signs:** Tests that stub `safeRecordFilePath` for conference rows.

### Pitfall 2: Monitor-directory files
**What goes wrong:** Asterisk writes `confbridge-{name}-{time}.wav` under `astspooldir/monitor`; `recording_file_rel` never matches.
**Why:** `record_conference=yes` without dynamic `record_file`, or AMI without `RecordFile`.
**How to avoid:** Always pass `RecordFile` = absolute `{records_base_path}/{rel}`.
**Warning signs:** Files appearing under `/var/spool/asterisk/monitor`.

### Pitfall 3: `record_file_timestamp=yes`
**What goes wrong:** Stored `{meeting_uid}.wav` is not the file on disk.
**Why:** Official default appends start time [CITED: app_confbridge `record_file_timestamp`].
**How to avoid:** If using `CONFBRIDGE(bridge,record_file)`, set `record_file_timestamp=no`. Prefer AMI `RecordFile` only.
**Warning signs:** `has_recording=1` but `safeVoicemailFilePath` returns null.

### Pitfall 4: Missing mkdir
**What goes wrong:** StartRecord "succeeds" or errors; no file.
**Why:** Asterisk does not create `{vpbx}/conferences/{room_uid}`.
**How to avoid:** `mkdir` recursive as `UsersService.getAvatarsDir` does [VERIFIED: packages/backend/src/modules/users/users.service.ts:144-166].
**Warning signs:** AMI Success + empty directory.

### Pitfall 5: Double start
**What goes wrong:** Button start fails after auto start.
**Why:** Official: already recording ⇒ error.
**How to avoid:** One owner (`ConferenceRecordingService`); snapshot.recording short-circuits.
**Warning signs:** 500 on POST start when badge already shows recording.

### Pitfall 6: Meetings never written
**What goes wrong:** History empty; CDR cannot join.
**Why:** State service is memory-only [VERIFIED: packages/backend/src/modules/conferences/conference-state.service.ts:85-93].
**How to avoid:** Persist on join/leave in the same service that starts recording.
**Warning signs:** Live SSE works, `conference_meetings` row count stays 0.

### Pitfall 7: No uniqueid on participants
**What goes wrong:** Cannot attach a meeting WAV to a CDR journal row.
**Why:** Current participant model has no `uniqueid`.
**How to avoid:** ALTER + persist AMI Uniqueid / fallback time+caller join.
**Warning signs:** Badge never lights on journal rows.

### Pitfall 8: Frontend History with no host page
**What goes wrong:** 16.2 builds a tab nobody mounts.
**Why:** No `ConferencesPage` / form yet.
**How to avoid:** Ship HistoryTab + CDR modal in 16.2; 16.3 mounts the tab. CDR surface is the 16.2 user-visible gate.
**Warning signs:** Only backend tests, no CDR UI change.
