## Summary

Phase 16.3 is a **brownfield UI + AI-registration** phase. Backend REST/SSE for rooms, guests, moderation, capacity, telemetry, invites and recording already exist from 16 / 16.1 / 16.2. The live room page, guest shell, Hub entry and `conferences` AI adapter do **not**. `conferenceRoomApi.ts` is catalog-only; `ConferenceHistoryTab` is a mountable fragment; `MODULE_COVERAGE.conferences` is still `excluded` so the 15-23 completeness suite stays green until this phase flips it to `covered`.

The planner-blocking media fact is no longer a hypothesis: stock `sip.js@0.21.2` `SessionDescriptionHandler.setRemoteTrack` **stops every previous remote video track** before adding the new one, and `peerConnection.ontrack` calls that method **before** `peerConnectionDelegate.ontrack`. A product grid that only listens to the delegate will paint dead tracks. The spike-002 factory that replaces `setRemoteTrack` with add-only and paints tiles from `e.transceiver.mid` is the implementation recipe. Do not pre-allocate six recvonly video m-lines (37 KB INVITE, PJSIP drop) and do not fork `useWebRTCPhone.ts`.

**Primary recommendation:** one `useConferenceRoom` hook with a conference-owned `UserAgent` + custom SDH factory; staff INVITE the short room number, guests REGISTER `gst*` from `POST /conferences/guest/:token/join`; session state lives above the route so the mini-panel survives navigation; flip `MODULE_COVERAGE.conferences` to `{ kind: 'covered', capability: 'configure' }` in the same wave as the adapter and `src/skills/conferences/SKILL.md`.

```
    this.logger.debug(`SessionDescriptionHandler.setRemoteTrack - adding remote ${track.kind} track`);

        SessionDescriptionHandler.dispatchRemoveTrackEvent(remoteStream, track);

```

Delegate runs **after** that stop [VERIFIED: :881-889]:


**How to replace without forking Phase 10:**

2. New hook `useConferenceRoom.ts` constructs `UserAgent({ sessionDescriptionHandlerFactory: conferenceSdhFactory, sessionDescriptionHandlerFactoryOptions: { peerConnectionConfiguration: { bundlePolicy: 'max-bundle', iceServers } } })`.
3. **Do not edit** `useWebRTCPhone.ts`. Softphone stays `video: false` [VERIFIED: useWebRTCPhone.ts:463-467] `constraints: { audio: audioConstraint, video: false }`.
4. Neutralizer from the spike (product recipe) [VERIFIED: spike app.js:194-196]:

```

  if (!this._remoteMediaStream.getTrackById(track.id)) this._remoteMediaStream.addTrack(track);
};
```

## Common Pitfalls

### Pitfall 1: Stock sip.js kills every previous remote video track (R-SDH)
**What goes wrong:** Grid shows one live tile; others are black / `readyState === 'ended'`.
**Why:** `setRemoteTrack` `track.stop()` on all existing video tracks, **before** the app delegate.
**How to avoid:** Replace `setRemoteTrack` on a conference-only factory; render from `mid`.
**Warning signs:** `inbound-rtp` packets grow, `videoWidth === 0`, `track.readyState === 'ended'`.

### Pitfall 2: Missing renegotiation (R-RENEG)
**What goes wrong:** ~1/12 joins hear audio and never see video.
**Why:** SFU allocation race (spike 004).
**How to avoid:** 3–5s watchdog + `session.invite()` ≤2 times + `live.videoRetry`.
**Warning signs:** Established session, one-way audio, empty remote video transceivers.

### Pitfall 3: Pre-allocated recvonly video m-lines
**What goes wrong:** INVITE ~37 KB, PJSIP drops with no response.
**Why:** Early spike-002 hypothesis; later disproved — Asterisk adds m-lines itself.
**How to avoid:** One camera offer + `max-bundle` + codec trim to VP8 if SDP grows.

### Pitfall 4: Guest shell leaks PBX chrome (D-28)
**What goes wrong:** Guest sees sidebar, ⌘K, AI panel, softphone, `/modules` links.
**Why:** Page mounted under `AppLayout` / `ModuleShell`.
**How to avoid:** `/conf/:token` next to wallboard; `ConferenceGuestShell` only. Tests: assert absence of `#shell-cmdk-trigger`, `#shell-agent-trigger`, `data-testid="module-shell"`.

### Pitfall 5: Module Hub `market` vs `apps` (D-27)
**What goes wrong:** Conferences appear as a paid marketplace card and block launch.
**Why:** Copying a `kind: market` seed row.
**How to avoid:** Only `hub_code: 'apps'`, `sort_order: 65`. No price.

### Pitfall 6: Completeness 15-23 half-flip (D-41)
**What goes wrong:** CI red: `covered domain missing adapter: conferences` or `covered domain missing skill`.
**Why:** Registry flipped without adapter/skill, or adapter `domain` ≠ `conferences`.
**How to avoid:** One commit: registry + `conferences-ai.adapter.ts` with `readonly domain = 'conferences'` + `skills/conferences/SKILL.md` + module provider. Verify `npm run test:ai`.

### Pitfall 7: Second REGISTER steals the softphone (max_contacts: 1)
**What goes wrong:** Entering the room drops the operator's WebRTC registration.
**Why:** AOR `max_contacts: 1` + `remove_existing: 'yes'` [VERIFIED: endpoints.service.ts:133-137] on guest **and** [VERIFIED: :815-816] on normal endpoints.
**How to avoid:** Conference UA is separate, but staff must not REGISTER the same `ew*` AOR as a live softphone. See Q1.

### Pitfall 8: Double-fetch / wrong RTK tags
**What goes wrong:** SSE snapshot and REST list diverge; record button does not refresh meetings.
**Why:** New cache tags that SSE does not patch.
**How to avoid:** Patch the same `ConferenceRooms` / participants entry the GET uses (callcenter SSE pattern).

### Pitfall 9: Showing Asterisk names
**What goes wrong:** UI prints `conf6007_42` or `PJSIP/gst…`.
**Why:** Using raw AMI/channel fields.
**How to avoid:** Only DTO `ref` / `displayName` / short `number`. Copy contract forbids the word «Asterisk».
