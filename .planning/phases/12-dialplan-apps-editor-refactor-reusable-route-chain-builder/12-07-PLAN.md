**Дизайн механизма без прецедента — история.** Полноценный undo/redo всего состояния в этой фазе не нужен и не
заказан: D-13 требует ровно «undo удаления». Поэтому вместо снапшотов всего состояния — **стек удалённых шагов**
`removedStack: Array<{ action: DialplanAction; index: number }>`. `undoRemove` снимает верхний элемент и
вставляет `action` по сохранённому `index` (с нормализацией, если массив стал короче). Это дешевле снапшотов,
не растёт по памяти с числом правок и **отвечает ровно на заказанный вопрос**. Ограничение стека — 20 элементов
(старые вытесняются), чтобы длинная сессия не держала весь мусор.
Failure modes, которые обязаны быть обработаны: удаление последнего шага и undo в пустое состояние; undo после
того, как позиция уехала из-за перестановки; undo дважды при одном удалении (второй раз — no-op, не исключение).

**Дизайн механизма без прецедента — буфер.** `clipboard.ts` — модуль-синглтон в памяти модуля (не `navigator.clipboard`:
шаг это структура, а не текст, и системный буфер потребовал бы сериализации и разрешений). Экспортирует
`copyStep(action)`, `peekStep()`, `hasStep()`. Копия делается через `structuredClone`; при вставке генерируется
новый `id` — вставка шага с тем же `id` даёт два элемента с одинаковым ключом React и молча ломает DnD.
Буфер живёт между экземплярами редактора в пределах сессии (копировать в одном маршруте, вставить в другом) —
это и есть переиспользуемость из D-13.

`editorReducer.ts`: `EditorState = { actions: DialplanAction[]; removedStack: [...]; selectedStepId: string | null }`,
`EditorAction` — union перечисленных выше операций плюс `patchParams` (D-02: правка из Sheet попадает в состояние
немедленно, без промежуточного «применить»). Reducer чистый, без обращений к API и без `Date.now()` в теле
(генерация `id` — через переданный `makeId`, иначе тесты нестабильны).
