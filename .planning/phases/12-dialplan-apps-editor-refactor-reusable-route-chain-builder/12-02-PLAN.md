**Tracer-срез фазы 12: «звонок в очередь по маске маршрута», один путь, сквозь все слои, production-качества.**

Это ровно тот сценарий, которым пользователь обосновал фазу («сейчас нет возможности вызвать очередь по маске
маршрута (exten), хотелось бы чтобы была такая возможность»), и одновременно самая опасная ветвь генератора:
сегодня при пустом `params.queue` эмитится `Queue(${EXTEN},…)`, то есть обращение к несуществующей очереди,
потому что `queues.service.ts` § `buildQueueName` называет очередь `q{exten}_{vpbxUserUid}`.

Ordering фазы: **Wave 0 (12-01, характеризация) → tracer (этот план) → expansion (12-03 и далее).**
Характеризация — предусловие (без неё 22 ветви меняются слепо), tracer — первая реальная сквозная возможность,
всё последующее — горизонтальное расширение от проверенного среза. Причина именно такого порядка: архитектурный
тупик (структура `ValueSource`, форма per-type DTO, форма схемы полей, стек оверлеев) выявляется после одного
коммита, а не после десяти уже закоммиченных слоёв.

Что даёт срез:

- D-21: `normalizeTarget` создаётся как единственная точка тенант-скоупинга и **сразу** подключается к `toqueue`.
- D-20: структурный «источник значения» (`fixed` / `route_pattern` / `variable` / `phonebook`) заменяет частный
  механизм флагов на tracer-пути.
- D-09 / D-10: per-type DTO появляется реально работающим на одном типе, вместе с проекцией ошибки на шаг.
  Нумерация ссылок вперёд в этом плане: 12-03 (остальные 28 DTO), 12-05 (обёртка условий и остальные call-site),
  12-07 (перевод 14 app-компонентов), 12-08 (группы «Опции»/«Условия» в Sheet, `side="bottom"`),
  12-12 (миграция данных `params`), 12-13 (`QUEUE_PRIO` / `announceoverride`), 12-17 (M8 — 3 уровня оверлеев).
- D-01 / D-03 / D-06 / D-07: `Sheet` + декларативная схема поля + контракт `{ params, onChange }` появляются
  на одном приложении, а не «сначала каркас для всех».
- D-04: summary строки питается из реестра.
- D-32: очередь переезжает на схему параметров; `QUEUE_PRIO` и `announceoverride` — расширение в 12-13.

**Заглушки допустимы только там, где их можно заполнить без смены архитектуры.** `normalizeTarget` объявляет
все четыре `TargetKind`, но tracer подключает только `queue` — остальные подключаются в 12-05 без изменения
подписи. Per-type DTO существует для одного типа, остальные 28 добавляются в 12-03 в тот же реестр подтипов.
Функциональные пробелы допустимы, архитектурные — нет.

`<verify>`») здесь важнее числа файлов, поэтому задача остаётся атомарной; половина из 20 файлов — парные

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| браузер → `PUT /routes/:uid` | недоверенный `params` действия пересекает границу и попадает в DTO-валидацию |
| DTO → `actionToDialplan` | валидированное, но всё ещё пользовательское значение попадает в конфиг Asterisk |
| `actionToDialplan` → хост Asterisk | сгенерированный текст становится исполняемым dialplan |
| тенант A → объекты тенанта B | имя очереди без суффикса тенанта адресует чужой объект |
