# Phase 12 — UI Design Contract

> Визуальный и интеракционный контракт для переиспользуемого конструктора цепочек маршрутов
> (`DialplanAppsEditor`) и сопутствующих поверхностей фазы: строка шага, Sheet параметров,
> schema-driven поля, редактор опций, редактор условий, состояния валидации, три host-а,
> настройки видимости + подсистема тенантных настроек, и вкладка голосовых сообщений в CDR.
>
> Сгенерирован `gsd-ui-researcher` из зафиксированных решений `12-CONTEXT.md` (D-01…D-59, все LOCKED).
> `RESEARCH.md` для фазы не существует — стек взят из `packages/frontend/.idea/ARCHITECTURE.md`
> и `12-CONTEXT.md`. Отдельной `/gsd-sketch`-сессии по этой области нет:
> `sketch-findings-krasterisk-v4` покрывает Phase 2 (MohPage) и Phase 8 (Module Hub / shell)
> и даёт только общий визуальный язык (dark admin, indigo accent, плотность важнее декора).
> Прямые прецеденты, которые этот документ продолжает, а не переписывает: `09-UI-SPEC.md`,
> `10-UI-SPEC.md` (те же токены, та же шкала типографики, тот же набор `shared/ui`).

### shadcn gate — resolved, not asked

Гейт инициализации shadcn выполнен и разрешён **без вопроса пользователю**: `components.json` отсутствует,
но `ARCHITECTURE.md` (MUST READ) прямо запрещает Tailwind-классы выше `shared/ui` и предписывает
SCSS-модули с `var(--color-*)`. Инициализация shadcn CLI противоречила бы канону проекта
и трём уже одобренным UI-SPEC (Phase 8/9/10, все с `Tool: none`). Переспрашивать зафиксированное
на уровне проекта решение — вне мандата этого агента.

## Spacing Scale

Кратные 4, набор идентичен `09-UI-SPEC.md` / `10-UI-SPEC.md`:

| Token | Value | Использование в Phase 12 |
|-------|-------|--------------------------|
| xs | 4px | Зазор иконка↔текст в бейджах условий, отступ `InfoTooltip` от лейбла, внутренний зазор чипа флага опции |
| sm | 8px | Вертикальный зазор между строками шагов, зазор Label↔контрол в поле схемы, зазор между бейджами условий, зазор между кнопками действий строки |
| md | 16px | Горизонтальный padding строки шага (`comfortable`), padding секций внутри Sheet, зазор между группами полей |
| lg | 24px | Вертикальный зазор между секциями Sheet (Тип / Параметры / Опции / Условия), между карточками секций настроек, padding пустого состояния |
| xl | 32px | Вертикальный зазор между блоками страницы настроек (существующий `gap="32"` на `SettingsPage`) |
| 2xl | 48px | Минимальная высота пустого состояния списка шагов до иконки |
| 3xl | 64px | Не используется в этой фазе (зарезервировано) |

Exceptions (перечислены явно, новых «магических чисел» вводить нельзя):

- **44px** — минимальный touch-target для каждой icon-only кнопки на телефоне: действия строки шага,
  кнопка «вставить между», handle перетаскивания, кнопки в Sheet, кнопка удаления условия,
  «Детали сообщения» в таблице CDR. WCAG 2.5.5,
  то же правило, что в Phase 9/10.
- **56px / 44px** — минимальная высота строки шага в `density="comfortable"` / `density="compact"` (D-14).
  Это высоты компонента, не шкала отступов.
- **480px** — ширина `SheetContent` на десктопе (существующее значение `w-[480px]`), не менять под эту фазу.
- **85dvh** — максимальная высота Sheet в мобильном (`side="bottom"`) варианте.
- **24px / 32px** — фиксированная ширина колонки номера шага и колонки drag-handle в grid строки.
  Обе кратны 4 и участвуют в `grid-template-columns`, а не в `gap`.
- **12px** — плотность строки списка и вложенного контейнера, а не отступ между блоками:
  вертикальный padding строки шага в `density="comfortable"` (`12px 16px`),
  горизонтальный padding строки в `density="compact"` (`8px 12px`),
  внутренний padding inset-контейнера вложенного редактора (Surface J).
  Кратно 4 и потому не нарушает сетку, но в базовую шкалу не входит намеренно: между `sm` (8px)
  и `md` (16px) нужен ровно один промежуточный шаг, и он существует только для плотности строк.
  Применять 12px где-либо ещё запрещено.
- **1px / 2px** — толщины границ: 1px — граница строки/карточки (`var(--color-border)`),
  2px — левая маркерная полоса состояния строки (выбран / ошибка / неизвестный тип / выключен).
- **320px** — максимальная высота блока расшифровки в модалке «Детали сообщения» до внутреннего скролла.

## Typography

| Role | Size | Weight | Line Height | Использование в Phase 12 |
|------|------|--------|-------------|--------------------------|
| Body | 14px | 400 | 1.5 | Summary шага одним предложением (D-04), описания флагов опций, текст подсказок и ошибок под полем, расшифровка голосового сообщения, тело пустого состояния |
| Label | 12px | 600 | 1.4 | Бейджи условий и терминальности, лейблы полей схемы, номер шага, заголовки секций внутри Sheet, счётчик `{n} / {max}` |
| Heading | 16px | 600 | 1.3 | Название типа действия в строке шага, заголовок Sheet, заголовки секций настроек, заголовок пустого состояния |
| Display | 28px | 600 | 1.2 | `Text variant="h1"` на страницах настроек и CDR (существующее), больше нигде |

Ровно 4 размера (14 / 12 / 16 / 28), ровно 2 начертания (400 и 600) — тот же набор, что в Phase 9/10.
Пятого размера и третьего веса фаза не вводит.

**Документированное исключение — моноширинный текст.** Строка опций (`tThH`), сырые params неизвестного шага,
expert-выражение условия, raw dialplan и токены нормализации (`q{номер}_{тенант}`) рендерятся
моноширинным семейством. Это **смена `font-family`, а не новая роль типографики**: размер и вес остаются
Body (14 / 400), только `font-family: ui-monospace, SFMono-Regular, Menlo, monospace`.
Прецедент — класс `.mono` в `RouteFormModal.module.scss`, уже применённый к полю «Предварительная команда».
Моно **запрещён** для summary шага, лейблов и любого человекочитаемого текста: summary существует
именно затем, чтобы читаться как предложение, а не как код.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-background)` `#09090b` | Фон страницы и фон `SheetContent` (существующий `bg-background`) |
| Secondary (30%) | `var(--color-card)` `#0a0a0f` + `var(--color-border)` `#27272a` | Поверхность строки шага, карточки секций настроек, инсет-контейнер вложенного редактора, фон группы опций (`color-mix(in srgb, var(--color-muted) 35%, transparent)`) |
| Accent (10%) | `var(--color-primary)` `#6366f1` | **Зарезервирован ровно для:** primary-CTA «Добавить действие» (в пустом состоянии и в футере списка), активный сегмент `SegmentedControl`, левая 2px-полоса + тинт `color-mix(in srgb, var(--color-primary) 6%, transparent)` у строки, чей Sheet сейчас открыт, focus-ring (`--color-ring`, тот же hex), включённый `Switch` в настройках, активная кнопка-вкладка в шапке CDR |
| Destructive | `var(--color-destructive)` `#ef4444` | Действие «Удалить» (иконка + подтверждение), 2px-полоса и текст ошибки у невалидного шага, текст ошибки поля, состояние «расшифровка не удалась», строка-сводка «Не удалось сохранить» |
| Warning | `var(--color-warning)` `#f59e0b` | Неизвестный тип действия (2px-полоса + бейдж), бейджи «Завершает цепочку» / «Может выйти из цепочки», полоса-предупреждение о недостижимых шагах, чипы параметризованных/неизвестных флагов опций, бейдж условия по расписанию |
| Info | `var(--color-info)` `#3b82f6` | Бейджи условий семейства `QUEUESTATUS` / `DEVICE_STATE`, иконка голосового сообщения в таблице CDR (отличает его от записи разговора) |
| Success | `var(--color-success)` `#22c55e` | Ровно одно применение: чип «Расшифровка готова» в модалке «Детали сообщения». Больше нигде |

Accent **не должен** протекать в: обычные строки шагов, drag-handle, иконки действий строки, бейджи условий,
кнопку «вставить между», заголовки секций. Строка шага в покое — `--color-card` + `--color-border`, и только
открытый Sheet делает одну строку акцентной.

**Правило состояний строки — цвет плюс форма, не только цвет.** Каждое состояние строки несёт
2px левую маркерную полосу **и** текстовый/иконочный признак:
выключен — пунктирная полоса `--color-muted-foreground` + бейдж «Выключен»,
невалиден — сплошная `--color-destructive` + иконка `AlertCircle` + строка ошибки,
неизвестный тип — сплошная `--color-warning` + иконка `FileQuestion` + подпись,
выбран — сплошная `--color-primary` + тинт фона.
Полагаться на один только цвет запрещено (дальтонизм + светлая тема).

**Выключенный шаг не гасится `opacity`.** Текст переводится на `--color-muted-foreground`,
фон и границы остаются штатными. `opacity < 1` ломает контраст и делает выключенный шаг
нечитаемым в светлой теме — а его всё ещё нужно прочитать, чтобы решить, включать ли обратно.

**Светлая тема:** каждая новая карточка/строка обязана нести `box-shadow: 0 1px 4px rgba(0,0,0,0.06)`
поверх 1px-границы (ARCHITECTURE: `--color-border` в светлой теме `#e4e4e7` почти невидим).

## Surface Specifications

Раздел разворачивает контракт по каждой поверхности фазы. Для планировщика и исполнителя он
так же обязателен, как таблицы выше. Все 12 поверхностей из scope перечислены явно, потому что
в `12-CONTEXT.md` они распределены по разным блокам решений.

### A. Строка шага цепочки (D-04, D-05, D-13, W3, W4, W7)

**Grid десктопа (≥768px):** `grid-template-columns: 24px 32px minmax(0, 1fr) auto auto`
→ `[номер] [handle] [тип + summary] [бейджи условий] [действия]`.
`minmax(0, 1fr)` обязателен: без него длинный summary раздувает grid и возвращает горизонтальный скролл.

**Мобильная раскладка (<768px):** две строки.
Строка 1: `[номер] [handle] [тип] [действия]`. Строка 2: `[summary]` на всю ширину + бейджи с переносом.
Никакого `overflow-x-auto`: обёртка редактора теряет этот класс, вместо него `min-width: 0` на всех
flex/grid-детях (ARCHITECTURE, правило 5).

**Содержимое зоны «тип + summary»:**
`Heading 16/600` - человекочитаемое название типа; под ним `Body 14/400` `--color-muted-foreground` -
одно предложение summary из реестра (`summarize(action)`, i18n). Пример: «Звонок в очередь Продажи,
до 60 секунд, с приоритетом VIP». Не список полей, не `key=value`.

**Клик по зоне «тип + summary» открывает Sheet.** Зона имеет `role="button"`, `tabIndex={0}`,
обрабатывает Enter/Space. Конфликта с DnD нет: слушатели `useSortable` вешаются только на handle.
Дублирующая явная кнопка «Настроить шаг» остаётся в наборе действий - зона-кнопка не обнаруживаема сама по себе.

**Действия строки** - `TableRowActions` + `TableRowAction` (ARCHITECTURE MUST, не нативные кнопки):
`Настроить` (`SlidersHorizontal`), `Дублировать` (`Copy`), `Включить/Выключить` (`Power`/`PowerOff`),
`Удалить` (`Trash2`, `danger`). Копирование в буфер и «вставить между» живут в `DropdownMenu` (`MoreVertical`).
На <768px инлайн остаются только `Настроить` и `MoreVertical`. У каждой обязательны `title` и `aria-label`.

**Вставка между шагами (D-13):** в зазоре 8px между строками - линия 1px с центральной кнопкой `Plus` 24px.
На указательных устройствах появляется по hover зоны зазора; при `@media (hover: none)` **всегда видима**,
иначе на тач-устройствах функция недостижима в принципе.

**Undo удаления (D-13):** инлайн-полоса **над списком**, не toast: `Body 14/400` «Действие удалено»
+ текстовая кнопка «Вернуть шаг», автоскрытие через 10 секунд. Обоснование: редактор живёт внутри
модалок, глобальный toast поверх стека из трёх оверлеев пользователь не увидит.

**Буфер копирования** живёт в памяти вкладки, не в системном clipboard: шаг - это объект, а не текст.
Кнопка «Вставить скопированный шаг» рядом с «Добавить действие», `disabled` при пустом буфере, с Tooltip-объяснением.

**Семантика списка:** `role="list"` на контейнере, `role="listitem"` на строках. Номер шага декоративен
(`aria-hidden`) - позицию сообщает сам список.

### B. Sheet параметров шага (D-01, D-02, D-03, D-05)

**Позиция:** `side="right"`, 480px на ≥768px; `side="bottom"`, `max-height: 85dvh` на <768px.
Вариант `bottom` - **единственная правка `shared/ui` в фазе**: в `SheetContent` добавляется prop `side`
с классами `inset-x-0 bottom-0 h-auto max-h-[85dvh] border-t rounded-t-[var(--radius-xl)]`
и анимацией `slide-in-from-bottom`. Tailwind внутри `shared/ui` разрешён.

**Стек оверлеев.** Sheet обязан рисоваться поверх host-модалки. z-index не хардкодится:
опора на порядок монтирования порталов Radix (см. `## UI Considerations`, строка ⚠ unresolved).
Оверлей вложенного Sheet затемняет слабее host-модалки (`bg-black/40` вместо `bg-black/80`) -
иначе три наложенных затемнения дают почти чёрный экран.

**Структура (сверху вниз, порядок фиксирован):**
1. `SheetHeader`: `Heading 16/600` - название типа действия; `Label 12/600` `muted` - «Шаг {n}».
2. Тип действия - `ActionTypeSelect`, редактируемый на месте. Смена типа с заполненными params
   требует подтверждения (копия в контракте).
3. **Параметры** - schema-driven поля (Surface C).
4. **Опции** - сворачиваемая группа (Surface D), по умолчанию свёрнута.
5. **Условия** - сворачиваемая группа (Surface E), по умолчанию свёрнута; счётчик заданных условий
   в заголовке появляется только при `count > 0`.
6. Футер: единственная кнопка «Закрыть параметры» (`SheetClose`) + `Body 14/400` `muted` подсказка о live-режиме.
   Глагол + существительное намеренно: односложное «Готово» рядом с формой читается как «Сохранить»,
   а сохранения здесь не происходит (D-02).
   **Пары «OK / Отмена» внутри Sheet нет** (D-02): изменения летят в черновик мгновенно, сохранение
   и отмена принадлежат host-форме.

**Скролл:** единственная зона со скроллом - тело между header и футером
(`flex: 1; min-height: 0; overflow-y: auto; overscroll-behavior: contain`), по паттерну `formBody`
из ARCHITECTURE. Футер и заголовок не уезжают.

**Авто-открытие (D-03):** «Добавить действие» добавляет строку с пустым типом, где вместо summary
рендерится `ActionTypeSelect` с автофокусом. Выбор типа немедленно открывает Sheet для этого шага -
пустой шаг не остаётся висеть в списке. Это единственный случай, когда в строке живёт контрол ввода.

**Фокус:** при открытии фокус уходит на первое невалидное поле, иначе на первое редактируемое -
**не** на кнопку закрытия. При закрытии фокус возвращается на действие «Настроить» исходной строки.

**Одновременность:** в приложении может быть открыт только один Sheet шага. Он монтируется **один раз
на экземпляр редактора** и параметризуется id выбранного шага. Рендерить Sheet внутри каждой строки запрещено.

**Sheet не открывает Sheet и не открывает Dialog.** Любой вложенный выбор (промпт, транк, очередь,
интеграция уведомлений) реализуется через `Popover` / `DropdownMenu` / инлайн-раскрытие. Это прямое
следствие D-01: Sheet выбран именно ради ограничения глубины стека.

### C. Schema-driven поля параметров (D-07)

**Раскладка поля:** `VStack gap="8"` → `HStack gap="4"` (Label + `InfoTooltip`) → контрол → текст ошибки.
Обязательное поле - суффикс ` *` в лейбле. Подсказка - **только `InfoTooltip`**, длинный текст под полем
запрещён (ARCHITECTURE MUST).

**Маппинг типов схемы на компоненты (новых примитивов не создаётся):**

| Тип поля схемы | Компонент `shared/ui` |
|----------------|----------------------|
| `text`, `number`, `duration` | `Input` (для `number` - `type="number"` + `inputMode="numeric"`) |
| `textarea` | `Textarea` |
| `select` | `Select` |
| `multiselect` | `MultiSelect` |
| `toggle` | `Switch` |
| `checkbox` | `Checkbox` |
| `tags`, `multi-file` | `TagInput` |
| `choice-cards` (2-4 взаимоисключающих режима с описанием) | `RadioCards` |
| `mode` (2-3 коротких режима) | `SegmentedControl` |
| `secret` | `PasswordInput` |
| `custom` | компонент из реестра, обязан использовать ту же обёртку поля |

**Колоночность:** одна колонка по умолчанию (Sheet 480px). Две колонки допустимы только для пары
коротких числовых полей и только при ≥640px, с обязательным `@media (max-width: 640px) { grid-template-columns: 1fr }`.

**Escape hatch:** `render: 'custom'` получает тот же контракт `{ params, onChange(patch) }`, что и
декларативные поля (D-06), и **обязан** рендерить лейбл, подсказку и ошибку через ту же обёртку -
иначе кастомные приложения визуально расслаиваются с декларативными.

**Единый «источник значения» (D-20)** - переиспользуемая обёртка поля, а не отдельный компонент на приложение:
`SegmentedControl` [Фиксированное значение | По маске маршрута | Из переменной | Из справочника],
под ним - контрол значения. В режиме «По маске маршрута» контрол значения заменяется read-only
моно-чипом с результатом нормализации (`q{номер}_{тенант}`) и `InfoTooltip` с объяснением тенант-скоупинга.
Пользователь должен **видеть**, во что превратится маска, иначе D-21 остаётся невидимой магией.

### D. Редактор опций приложения (D-27)

Сворачиваемая группа «Опции» внутри Sheet, фон `color-mix(in srgb, var(--color-muted) 35%, transparent)`,
заголовок - toggle-кнопка + `ChevronDown` (поворот при раскрытии) + `InfoTooltip` **снаружи** toggle,
`aria-expanded` / `aria-controls` (паттерн вторичной группы полей из ARCHITECTURE).

**Структурированная часть:** список `Checkbox`; лейбл каждого - моно-чип с буквой флага +
человекочитаемое описание на `Body 14/400` («t - абонент может перевести звонок»).
Буква флага никогда не остаётся без описания.

**Expert-часть:** один `Input` с моно-шрифтом, содержащий сырую строку опций.
Синхронизация двусторонняя и немедленная: правка строки перерисовывает чекбоксы, клик по чекбоксу
переписывает строку **с сохранением порядка и позиций неизвестных флагов**.

**Неизвестные и параметризованные флаги** (`U(...)`, `M(...)`, `L(x:y:z)`) выводятся **над** списком
чекбоксов read-only чипами с warning-тинтом и `InfoTooltip` «Флаг с параметром сохраняется как есть и
меняется только в строке». Они никогда не исчезают при переключении режимов - это условие корректности, не удобство.

**Правило показа expert-строки:** свёрнута за toggle «Показать строку опций», если известных флагов ≤6
и параметризованных нет; раскрыта автоматически в противном случае.

**Приложение без опций.** Если схема действия не объявляет ни одного флага и в сохранённых params
нет непустой строки опций, группа «Опции» **не рендерится вовсе** — ни свёрнутой, ни пустой.
Пустая сворачиваемая группа обещает содержимое, которого нет, и заставляет пользователя раскрывать её,
чтобы это выяснить. Если строка опций непуста, но ни один флаг реестру не известен, группа рендерится
и показывает только чипы неизвестных флагов и expert-строку — сохранённые данные обязаны остаться видимыми.

### E. Редактор условий (D-05, D-22, D-23)

Сворачиваемая группа «Условия» в том же Sheet. Переключатель `SegmentedControl` [Простой | Эксперт].

**Все пользовательские строки этой поверхности** (CTA, плейсхолдер, zero state, заголовки `optgroup`
и формулировки пресетов D-23) объявлены с локалями `ru` и `en` в `## Copywriting Contract`, блок «Условия».
Прозой здесь описана только структура: изобретать строки на месте нельзя.

**Zero state - первое и нормальное состояние.** Условия по умолчанию пусты, поэтому пустой список -
не исключение, а то, что пользователь видит первым. Развёрнутая группа без условий показывает
zero-state копию (заголовок + тело «действие выполнится всегда») и **единственную** CTA «Добавить условие».
Свёрнутая группа в этом состоянии не показывает счётчик вовсе - `Условий: 0` шумит, ничего не сообщая;
счётчик появляется только при `count > 0`.

**Простой режим:** список строк-условий. Каждая строка - `Select` с плейсхолдером «Выберите условие»
(незаполненная строка валидна и просто не участвует в выражении) + icon-only кнопка удаления строки
(`X`, `title` и `aria-label` = «Удалить условие», 44px touch-target). Под списком - CTA «Добавить условие».

Опции `Select` сгруппированы через `optgroup` по источнику: результат набора, результат очереди,
состояние устройства, запись сообщения, переменные и запросы. Расписание (`TimeGroupSelect`) -
отдельная строка списка с собственным лейблом, а не пункт общего `Select`: у него другой контрол значения.

Несколько условий соединяются по «и», и соединитель рендерится **явной строкой «и»** между условиями,
а не подразумевается.

**Expert-режим:** моно-`Textarea` со свободным выражением + `InfoTooltip` с примерами синтаксиса.
Если выражение не раскладывается обратно в пресеты, сегмент «Простой» становится `disabled`
с Tooltip-объяснением (копия в контракте) - переключение молча не теряет выражение.

**Бейджи в строке (D-05):** каждое условие - один `Badge variant="outline"` с семантическим тинтом:
DIALSTATUS - `muted`, QUEUESTATUS / DEVICE_STATE - `info`, расписание - `warning`,
переменная / HTTP / RECORD_STATUS - `secondary`. Максимум 2 бейджа + «ещё {{count}}» с Tooltip.

### F. Валидация и состояния ошибок шага (D-10, D-11)

Три уровня, каждый со своим местом:

1. **Поле** - текст ошибки под контролом (`Body 14/400`, `--color-destructive`),
   `aria-invalid` + `aria-describedby` на контроле.
2. **Шаг** - в строке: 2px destructive-полоса слева, иконка `AlertCircle` перед названием типа,
   одна строка ошибки под summary. `aria-invalid="true"` на элементе строки.
3. **Host** - блокировка сохранения.

**Блокировка сохранения не равна `disabled` на кнопке «Сохранить».** Кнопка остаётся активной;
при попытке сохранить submit прерывается, над списком появляется destructive-полоса-сводка
(копия в контракте), фокус и скролл уходят на первый невалидный шаг. Отключённая кнопка
не объясняет причину и оставляет пользователя в тупике - особенно когда невалидный шаг
находится на другой вкладке модалки.

**Ошибки с бэкенда (D-11)** после ответа DTO-валидации проецируются по `action.id` и рендерятся
тем же строчным состоянием, но с префиксом «Сервер отклонил параметры: …», чтобы источник был очевиден.
Ошибки, которые не удалось спроецировать на шаг, показываются в host-сводке дословно - **молча теряться они не должны**.

### G. Неизвестный тип действия (W5, D-12)

Fallback `registry[type] || registry.hangup` удаляется. Неизвестный тип получает собственное состояние:

- Строка: иконка `FileQuestion`, 2px **warning**-полоса (не destructive - данные целы, ошибки пользователя нет),
  название типа - сырая строка в моно, summary - копия «Неизвестный тип действия. Параметры сохранены…».
- Sheet: read-only таблица `ключ / значение` сырых params моноширинным шрифтом + единственное
  действие «Заменить тип» через `ActionTypeSelect` с **необратимым** подтверждением (копия в контракте).
- Действия строки: доступны «Настроить» (просмотр) и «Удалить». «Дублировать» и «Включить/Выключить»
  `disabled` с Tooltip-объяснением.

Мигрированные legacy-действия (D-12, D-29, D-54) после миграции **не** попадают в это состояние -
unknown остаётся только для типов, которых реестр действительно не знает.

### H. Терминальные и недостижимые шаги (D-24, D-53)

Два **разных** уровня определённости, и они не сливаются в одну формулировку:

- **Безусловный терминал** (`hangup`, `toroute`/`toivr` через `Goto`): бейдж «Завершает цепочку»
  (warning, `outline`). Полоса-предупреждение над первым недостижимым шагом:
  `AlertTriangle` + «Шаги ниже не выполнятся» + тело с номером шага + кнопка быстрого исправления «Перенести вниз».
  Сами недостижимые шаги переводятся в `--color-muted-foreground`.
- **Условный выход** (режим «выход по цифре» единого приложения «Воспроизведение», D-53;
  а также терминальный шаг, на котором висит условие): бейдж «Может выйти из цепочки»,
  полоса «Шаги ниже могут не выполниться», пунктирная warning-граница вместо сплошной.
  Условный терминал завершает цепочку не всегда, и утверждать обратное - врать пользователю.

Оба состояния - предупреждения, а не ошибки: они **не** блокируют сохранение (D-10 блокирует
только пустой тип и незаполненные обязательные params).

### I. Empty / readOnly / maxSteps / density (D-14)

- **Empty:** `VStack align="center"` с `ListPlus` 28px `muted`, Heading, Body и primary-CTA.
  Тело копируется из prop `labels` - три варианта в контракте (маршрут / справочник / IVR).
- **readOnly:** строки без handle и без действий, кнопка добавления не рендерится (не `disabled`),
  над списком - muted-полоса «Просмотр без изменений». Клик по строке всё ещё открывает Sheet,
  но поля в нём `disabled`, **не скрыты**: значения нужно видеть.
- **maxSteps:** кнопка добавления `disabled` + Tooltip с копией лимита; счётчик `{n} / {max}`
  (`Label 12/600`) в шапке списка появляется **только** когда host передал `maxSteps`.
- **density:**
  `comfortable` - min-height 56px, padding `12px 16px`, summary до 2 строк (host: `RouteActionsTab`);
  `compact` - min-height 44px, padding `8px 12px`, summary в одну строку с Tooltip
  (hosts: `RoutePhonebooksTab`, `IvrMenuItemsEditor`).
  44px в `compact` - это пол по touch-target, ниже опускаться нельзя даже ради плотности.

### J. Три host-embedding-а (D-14, D-15)

| Host | density | allowedTypes | maxSteps | Глубина стека для Sheet | Визуальная обёртка |
|------|---------|--------------|----------|--------------------------|--------------------|
| `RouteActionsTab` | `comfortable` | полный набор | не задан | 2 уровня (Sheet над `RouteFormModal`) | Редактор - тело вкладки, без дополнительной рамки |
| `RoutePhonebooksTab` | `compact` | сокращённый (действия политики справочника) | 10 | 3 уровня (Sheet над `RouteFormModal`, редактор вложен в строку биндинга) | Inset-контейнер: 1px граница `--color-border`, `border-radius: var(--radius-md)`, padding 12px, левая 2px полоса `--color-muted` - вложенность должна читаться визуально |
| `IvrMenuItemsEditor` | `compact` | сокращённый (что может делать кнопка DTMF) | 10 | 3 уровня (Sheet над модалкой IVR, редактор внутри сворачиваемого пункта меню) | Тот же inset-контейнер |

**Правило монтирования:** редактор внутри свёрнутого пункта IVR-меню **не монтируется**.
Иначе страница держит N DnD-контекстов и N подписок на справочники за раз.

**Правило `allowedTypes`:** сокращённый набор фильтрует и `ActionTypeSelect`, и реестр целиком.
Если в существующих данных лежит шаг типа вне `allowedTypes`, он рендерится нормально (не как unknown),
но с `Badge` «Недоступно в этом контексте» - удалять пользовательские данные из-за конфигурации host-а нельзя.

### K. Настройки: два флага видимости + подсистема тенантных настроек (D-16, D-17, D-19)

**Флаги (D-17)** живут на **тенантных** настройках, оба по умолчанию включены:
«Показывать dialplan в маршруте» и «Показывать блок-схему маршрута».
Оба - `Switch`, оба **обязаны** быть Optimistic toggles по ARCHITECTURE MUST:
`onQueryStarted` → `updateQueryData` (мгновенный патч) → при ошибке `patchResult.undo()`
**и** видимая пользователю ошибка (копия в контракте). Полагаться на `invalidatesTags` + refetch запрещено.

**Разделение уровней (D-19):** существующая `SettingsPage` (`/settings`) остаётся глобальной, ADMIN-guard.
Тенантные настройки получают соседнюю поверхность с **идентичным** визуальным языком секций
(иконка + `Heading` + описание + тело в карточке) - чтобы две страницы читались как одна система.
Переключение между ними - `SegmentedControl` [Система | Мой тенант] в шапке, и он рендерится
**только** если у пользователя есть доступ к обоим уровням. Один доступный уровень - контрола нет:
disabled-вкладка, дразнящая недоступной страницей, хуже её отсутствия.

**Следствие непересекаемости ключей:** так как глобальные и тенантные настройки по D-19 не пересекаются,
UI **не нуждается** в бейджах «унаследовано» / «переопределено» и в UI разрешения конфликтов.
Это стоит зафиксировать явно, иначе планировщик заложит merge-UI, которому нечего сливать.

**Влияние флага на `RouteActionsTab`:** при выключенном «Показывать dialplan» переключатель
[Таблица | Dialplan] **не рендерится вовсе** (не `disabled`). Сохранённый `raw_dialplan` при этом
не трогается и уходит на сервер как есть - выключенная видимость не должна стирать данные.

Новая секция в списке секций настроек: ключ `routes`, иконка `Route`, заголовок и описание - через i18n.

### L. Голосовая почта: вкладка в CDR + «Детали сообщения» (D-58, D-59)

**Вкладка.** `CdrReportPage` сегодня переключает [Журнал | Аналитика] кнопками-вкладками
(`Button variant="default"/"outline"`). Добавляется третья кнопка того же паттерна -
«Голосовые сообщения», иконка `Voicemail`. Миграция страницы на `shared/ui/Tabs` - вне scope этой фазы;
смешивать два паттерна вкладок на одной странице нельзя.

**Вкладка и фильтр - одно состояние, не два.** В `CdrFilter` добавляется чекбокс
«Только с голосовым сообщением»; выбор вкладки выставляет тот же фильтр. Один источник истины,
иначе появятся взаимно противоречащие состояния (вкладка «Голосовые», фильтр выключен).

**Колонки вкладки:** дата/время, кто звонил, куда, длительность сообщения, расшифровка (1 строка, обрезка),
статус обработки, действие «Детали сообщения». Пагинация и скролл - как в существующем `CdrTable`.

**Разделение записи разговора и голосового сообщения:** у одной CDR-строки может быть и то, и другое.
Две **разные** иконки: `Mic` (`muted`) - запись разговора, `Voicemail` (`info`) - голосовое сообщение.
Один и тот же значок для двух сущностей - прямой путь к тому, что оператор откроет не тот файл.

**Модалка «Детали сообщения».** `Dialog` (не Sheet: у этой страницы нет host-модалки, а контент широкий),
shell по паттерну form-modal из ARCHITECTURE (header `shrink-0` / `scrollBody` / footer `shrink-0`).
Содержимое сверху вниз:
1. Шапка: звонивший → назначение, дата, длительность сообщения.
2. `AudioPlayer` (не `compact`) + действие скачивания.
3. «Краткое содержание» - LLM-саммари в тинтованной карточке.
4. «Расшифровка» - полный текст STT, выделяемый, `max-height: 320px` + скролл.
5. Мета-строка: `RECORD_STATUS`, движок STT, модель LLM (`Label 12/600`, `muted`).

**Четыре состояния обработки, все обязательны:** `pending` (`SkeletonText` + «Расшифровка готовится»),
`done`, `failed` (destructive-текст + «Повторить расшифровку»), `not-configured`
(muted-текст + ссылка на настройки STT-движков, **без** кнопки повтора - повторять нечем).
Смешивать `failed` и `not-configured` нельзя: у них разные действия пользователя.

**Безопасность ссылки (D-59) как UI-требование.** Воспроизведение в интерфейсе идёт через
существующий JWT-аутентифицированный стрим. Ссылка с истекающим токеном генерируется **только**
для исходящих уведомлений и **никогда не рендерится видимым копируемым текстом** в UI -
показанный на экране URL с валидным токеном утекает через скриншот, шаринг экрана и историю буфера.
Если affordance «скопировать ссылку» вообще появляется, она чеканит свежий короткоживущий токен
по клику и несёт Tooltip-предупреждение об ограниченном сроке действия (копия в контракте).

## Motion & Accessibility

- **DnD (закрывает W10):** `DragOverlay` для перетаскиваемой строки + `restrictToVerticalAxis`
  (цепочка одномерна, горизонтальный дрейф - только шум). `KeyboardSensor` уже подключён;
  добавляются русские и английские `announcements` dnd-kit (поднят / перемещён на позицию N / отпущен / отменён)
  и `aria-roledescription="sortable"` на handle. Идентификаторы шагов - `crypto.randomUUID()`,
  а не `Date.now() + Math.random()`.
- **Фокус:** открытие Sheet - на первое невалидное или первое редактируемое поле; закрытие - возврат
  на действие «Настроить» исходной строки. Focus-ring везде через `--color-ring`, ad hoc outline запрещён.
- **Touch:** 44px минимум для каждой новой icon-only кнопки на телефоне без исключений,
  включая кнопку «вставить между» и действия внутри мобильного `Sheet`.
- **`prefers-reduced-motion: reduce`:** отключает slide-анимацию Sheet (остаётся мгновенное появление),
  анимацию появления кнопки «вставить между» и `motion`-анимации секций настроек.
  Существующие правила `SoftphoneWidget.module.scss` - образец.
- **Icon-only контролы:** `title` **и** `aria-label` обязательны (ARCHITECTURE MUST для `TableRowAction`).
