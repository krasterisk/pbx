D-17: `updateTenantSettings.onQueryStarted` — **строго по образцу** `callCenterApi.ts:527-550`: три шага в
указанном порядке — (1) `dispatch(api.util.updateQueryData('getTenantSettings', undefined, draft => Object.assign(draft, patch)))`,
(2) `const { data } = await queryFulfilled` и повторный `updateQueryData` с ответом сервера, (3) `catch` →
`patchResult.undo()`. Пропуск шага (2) оставляет оптимистичное значение вместо серверного и создаёт
расхождение, которое видно только после перезагрузки; пропуск шага (3) оставляет переключатель во
«включённом» состоянии после провала записи — то есть UI врёт о состоянии системы.

плюс индексная подпись для ключей, добавляемых позже. Публичный API — только через `index.ts` (правило FSD:
импорт из внутренних путей entity запрещён).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| браузер → `PUT /tenant-settings` | непривилегированный пользователь пишет настройки |
| кэш RTK Query → UI | оптимистичное значение может расходиться с сервером |
| флаг видимости → данные маршрута | скрытие поля может привести к его обнулению при сохранении |
