<objective>
Собрать UI wallboard'а (Wave 4, D-29 + D-27) поверх backend'а из 07-10 и сущностей настроек из 07-05.

Реализуется три вещи:
1. **TV-страница wallboard (D-29):** новая публичная страница `/callcenter/wallboard` с ФИКСИРОВАННЫМ layout по концепции и UI-SPEC §3 — KPI-строка (гигантские числа), live-график calls/hour (текущий час подсвечен), полоса агентов по статусам, список очередей с SLA progress-барами. Конфигуратора виджетов НЕТ (D-29 out-of-scope). Страница работает без логина: display-token берётся из query-параметра URL и передаётся в отдельный SSE-хук `useWallboardSSE`, который подключается к read-only топику `/callcenter/wallboard/events?token=` (guard из 07-10). Тёмный фон форсируется, навигационный chrome отсутствует, единственный контрол — fullscreen (автоскрытие через 3с).
2. **Управление display-ссылками (D-26 UI поверх 07-10):** таб «Display-токены» на `/callcenter/settings` (shell из 07-02) — супервизор создаёт долгоживущую ссылку для TV, копирует URL, отзывает; supervisor-only (level>=3) в UI и на backend (assertSupervisor в 07-10).
3. **Конфигурация алертов wallboard (D-27):** пороги алертов (`cc_settings.alert_thresholds`) уже редактируются формой `AlertThresholdsForm` из 07-05; этот план ДОБАВЛЯЕТ форму маршрута доставки `AlertRoutingForm` (какой `notification_integration`, адресат, включение, cooldown) на тот же таб «Пороги алертов», вызывая эндпоинты alert-config из 07-10. Так D-27 «пороги настраиваются через UI» замыкается end-to-end: пороги (07-05) + доставка (07-13 → 07-10 → Phase 6).

Purpose: D-29 требует готового фиксированного экрана для TV; D-27 требует, чтобы пороги алертов настраивались через UI и приводили к реальной рассылке. Security-фокус: TV-экран публичен, поэтому wallboard обязан потреблять ТОЛЬКО read-only display-token SSE и не раскрывать привилегированных/tenant-идентифицирующих данных.
Output: рабочая TV-страница wallboard + UI управления display-токенами + UI маршрута алертов, без изменения контракта backend'а 07-10/07-05.
</objective>
