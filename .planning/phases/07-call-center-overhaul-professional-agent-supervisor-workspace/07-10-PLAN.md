<objective>
Построить backend wallboard'а (Wave 3, D-26 + D-28) — то, что потребляет UI wallboard (07-13) и TV-режим без логина.

Реализуется три вещи:
1. **Display-токен для TV (D-26):** модель `cc_display_tokens` (долгоживущий opaque-токен) + миграция; отдельный `DisplayTokenGuard` (НЕ `JwtAuthGuard`), дающий доступ ТОЛЬКО к read-only wallboard SSE-топику конкретного тенанта; `CallCenterWallboardController` с `@Sse('events')` под этим guard'ом и supervisor-эндпоинтами генерации/списка/отзыва токенов (под `JwtAuthGuard` + `assertSupervisor`).
2. **Маршрутизация алертов (D-28):** модель `cc_alert_config` (per-tenant singleton: какой `notification_integration` использовать, target, enabled, cooldown) + supervisor CRUD.
3. **Оценщик порогов (D-28):** `CallCenterAlertService` — периодический `@Interval`, который сравнивает live-метрики (`CallCenterMetricsService` из 07-03) + снимок state с порогами из `cc_settings.alert_thresholds` (07-05) и при превышении отправляет алерт супервизору (Telegram/email) через Phase 6 `NotificationDispatcherService`, с cooldown против флуда.

Purpose: D-26 требует, чтобы TV показывал wallboard без логина и без риска эскалации привилегий при утечке токена — отсюда отдельная, изолированная auth-ветка. D-28 требует алертов сверх визуала/звука через уже существующий канал уведомлений Phase 6 — не дублировать credential store.
Output: рабочий, протестированный backend wallboard'а (SSE + токены + алерты), готовый к потреблению UI 07-13, без изменения контракта `CallCenterStateService`.
</objective>

| TV (без логина, ?token=) → wallboard SSE | Полностью недоверенная среда (публичный экран); display-токен даёт ТОЛЬКО read-only поток одного тенанта |
