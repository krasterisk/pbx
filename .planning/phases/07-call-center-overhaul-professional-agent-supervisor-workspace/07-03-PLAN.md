<objective>
Построить движок метрик колл-центра (Wave 2, D-03) — то, что читают wallboard (07-13), supervisor sparklines (07-09) и отчёты (07-12).

Реализуется три вещи:
1. `CallCenterMetricsService` — держит per-queue и per-agent аккумуляторы «за сегодня» в памяти и вычисляет SLA/ASR/AHT/ASA/Occupancy/Abandon по **точным формулам** из `CALLCENTER_MODULE_PLAN.md §4.6`. SLA-порог резолвится per-queue из `queue.servicelevel` с fallback на tenant-level default-константу (D-07).
2. Восстановление аккумуляторов «за сегодня» из `cc_queue_calls` при старте модуля (`onModuleInit` → `restoreToday()`), чтобы real-time метрики были точны сразу после рестарта backend (D-06).
3. Живая интеграция: AMI-хендлеры `handleAgentComplete`/`handleCallerAbandon` инкрементируют аккумуляторы синхронно (без БД в hot path), метрики публикуются в SSE (`queueMetrics`) и отдаются через GET-эндпоинт `/callcenter/metrics/queues` (tenant-scoped).

Purpose: без движка метрик wallboard/supervisor/отчёты нечем наполнять; аккумуляторы в памяти дают zero-latency real-time (принцип «real-time НЕ из БД»), а restore из `cc_queue_calls` закрывает разрыв точности при рестарте.
Output: рабочий, протестированный `CallCenterMetricsService` поверх слоя истории `cc_queue_calls` (07-01), без изменения контракта `CallCenterStateService`.
</objective>
