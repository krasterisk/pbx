## UserLevel enum inversion (READ BEFORE CODING)

`packages/shared/src/enums/index.ts` defines: `ADMIN = 1, OPERATOR = 2, SUPERVISOR = 3, READONLY = 5`.

The lowest number is the HIGHEST privilege. Therefore D-38's "супервизор (3+)" wording MUST be encoded as explicit set-membership predicates, NOT a numeric `level >= 3` comparison (that would wrongly EXCLUDE `ADMIN = 1` and INCLUDE `READONLY = 5`). Use the exact enum members:
- Operator tier = `UserLevel.OPERATOR` (2)
- Supervisor tools tier = `UserLevel.SUPERVISOR` (3) OR `UserLevel.ADMIN` (1)
- Settings tier = `UserLevel.ADMIN` (1) only
- `UserLevel.READONLY` (5) = no Колл-центр items in this plan.

Import `UserLevel` from `@krasterisk/shared` (re-exported via `@/entities/User`). Read the current user level with `selectUserLevel` from `@/entities/User` (already exists, returns `state.auth.user?.level`).
</critical_context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser client → backend API | The React app runs fully under user control; route config, Redux `auth.user.level`, and rendered menus are all client-side and tamper-able. Authorization decisions cross this boundary and MUST be enforced server-side. |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Elevation of Privilege | `/callcenter/supervisor`, `/callcenter/wallboard`, `/callcenter/reports`, `/callcenter/settings` routes | mitigate | Client `RequireRole` gate redirects non-authorized levels to `/`. Explicitly documented as UX/defense-in-depth ONLY: the authoritative control is the backend `JwtAuthGuard` + `assertSupervisor` (level check) on every CC data/mutation endpoint (existing pattern, 07-PATTERNS §9). No sensitive data is fetched purely client-side by these shells; placeholder panels render nothing tenant-sensitive. |
| T-07-02-02 | Information Disclosure | Sidebar role-filtered menu | accept | Hiding nav items is not a security control; it reduces attack surface and confusion only. Any data behind a link is independently protected server-side (T-07-02-01). Menu hiding removes discovery, not access. |
| T-07-02-03 | Tampering | Redux `auth.user.level` mutated via devtools to reveal guarded routes/menu | accept | A tampered client level can reveal the menu item and pass `RequireRole`, but every backend CC endpoint re-derives level from the verified JWT and rejects unauthorized calls (`assertSupervisor` / `JwtAuthGuard`). Client state cannot grant real access; no server trust is placed in client-reported level. |

**Supply chain:** This plan adds NO new npm dependencies (routing, i18n, Redux selectors, lucide icons all already present). No `T-07-*-SC` entry required.

High-severity check: no un-mitigated Elevation-of-Privilege threat remains — T-07-02-01 is mitigated client-side and enforced server-side by existing guards.
