<objective>
Полный drag-and-drop конструктор шаблонов Call Card с живым предпросмотром и runtime-карточка оператора. Это фронтенд-слой Call Cards (Wave 3), потребляющий backend-схему и API из 07-06 (`cc_card_templates` / `cc_card_fields` / `cc_card_data`, endpoints `/callcenter/card-templates` и `/callcenter/cards`), и монтируемый в таб «Шаблоны карточек» страницы `/callcenter/settings` из 07-02.

Реализуется:
1. **DnD-конструктор (D-10):** `TemplateBuilder` на `@dnd-kit` по паттерну `DialplanAppsEditor`/`SortableActionItem` — БЕЗ промежуточной «формы-списка»: поле добавляется из палитры и сразу попадает в сортируемый список, drag меняет `sort_order`. Правая панель — живой предпросмотр, рендерящий тот же `FieldRenderer`, что и runtime-карточка (единый источник истины, не отдельная preview-разметка).
2. **Набор типов полей v1 (D-11):** `FieldRenderer` покрывает 14 типов из 07-06 (`text`, `textarea`, `phone`, `email`, `select`, `multi_select`, `date`, `datetime`, `number`, `checkbox`, `phonebook_lookup`, `divider`, `heading`, `readonly`); тип `file` намеренно отсутствует (отложен в 07-06 по D-11).
3. **Runtime-карточка (D-12):** `CallCardPopup` — правый `Sheet` 480px (новый `shared/ui/Sheet`), рендерит шаблон, обрабатывает зависимые поля (`depends_on`/`depends_values`), сохраняет через `POST /callcenter/cards` с привязкой к `call_uniqueid` (CDR). `useCallCardPopup` открывает карточку по `auto_open_on` (`answer` / `ring` / `manual`), резолвит шаблон по очереди звонка, выполняет auto-populate из phonebook (`GET /callcenter/client-lookup` → `PhonebooksService.lookupNumber`).
4. **Привязка шаблон↔очереди:** аддитивная колонка `queue_names` (JSON) на `cc_card_templates` (одна миграция + расширение DTO/сервиса 07-06) — runtime выбирает активный шаблон по очереди текущего звонка. CDR-привязка уже обеспечена полем `call_uniqueid` в `cc_card_data` (07-06).

Purpose: закрыть D-10/D-11/D-12 на фронте — превратить настраиваемую backend-схему 07-06 в рабочий визуальный конструктор и авто-всплывающую карточку у оператора, устранив захардкоженную форму v3 (проблема из CC_CALL_CARD_CONCEPT.md).
Output: `shared/ui/Sheet` примитив; RTK-эндпоинты и типы карточек; `FieldRenderer` (single source of truth); `TemplateBuilder` + `FieldRow` + `FieldConfig`; `CallCardPopup` + `useCallCardPopup`; таб «Шаблоны карточек» в `/callcenter/settings`; смонтированная карточка в АРМ оператора; i18n ru/en.

Distinct from `ClientCard`: существующий read-only виджет `features/callcenter/ui/ClientCard` НЕ трогается (Pitfall 4). Call Card — новая, настраиваемая сущность.
</objective>
