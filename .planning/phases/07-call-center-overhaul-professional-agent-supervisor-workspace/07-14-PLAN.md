<objective>
Реализовать WebRTC-софтфон оператора в полном объёме (D-14…D-17) на `sip.js@0.21.2` поверх уже готового NAT-профиля `webrtc` (`endpoints.service.ts`) и существующего эндпоинта SIP-кредов `GET /endpoints/:sipId/credentials`.

Реализуется:
1. **WebRTC-звонок в браузере (D-14):** register/answer/hangup + hold/mute/DTMF + перевод слепой/с консультацией + выбор аудио-устройств (микрофон/динамик через `setSinkId`) + индикатор качества (из `RTCPeerConnection.getStats`). Медиа-слой полностью в браузере; backend CC API (REST + SSE) не меняется, WebRTC добавляет только медиа поверх существующих state/SSE (принцип концепции §5).
2. **Модалка выбора режима при старте смены (D-15):** «SIP-устройство» / «Браузер (WebRTC)» + выбор добавочного; для WebRTC-режима — выбор микрофона/динамика с полосой уровня микрофона. SIP-креды выбранного добавочного тянутся через `GET /endpoints/:sipId/credentials`.
3. **Авто-ответ + zip-tone per-operator (D-16):** auto-answer и звуковой сигнал перед соединением берутся из `cc_operator_settings` (сущность из 07-05), не хардкодятся.
4. **NAT traversal (D-17):** STUN всегда, TURN опционально через env на бэкенде; конфигурация (WSS URL + ICE servers) отдаётся рантайм-эндпоинтом `GET /callcenter/webrtc/config`, TURN-креды не попадают в бандл фронтенда.

Purpose: закрывает единственный полностью отсутствующий слой АРМ оператора (research §Gap Analysis: «WebRTC отсутствует полностью, `sip.js` не в зависимостях») — оператор может работать без внешнего SIP-телефона, полностью в браузере.
Output: рабочий двойной режим (SIP-телефон / браузер) на странице `/callcenter/agent`, hook `useWebRTCPhone`, модалка старта смены, DTMF keypad, индикатор качества, backend-эндпоинт ICE-конфигурации.
