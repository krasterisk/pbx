<objective>
Wave 5 — автоматическая рассылка отчётов колл-центра (D-35). Строится поверх **backend** отчётности 07-12 (`CallCenterReportsService.runReport` + exporters `buildReportCsv`/`buildReportXlsx`). UI страницы `/callcenter/reports` и `callCenterReportsApi.ts` создаются в **07-18** (Wave 4, выполняется до 07-15 по порядку волн). Переиспользует канал доставки Phase 6 `notification_integration`.

Реализуется:
1. **Конфигурация расписания** — модель `cc_report_schedules` + standalone-миграция + регистрация в `app.module.ts`. Хранит: какой из 7 отчётов (`report_id` — белый список `CcReportId` из 07-12), формат доставки (`csv`/`xlsx`), скользящий период (`period_preset`: today/yesterday/last-7-days/last-30-days/previous-month), фильтры (queueName/agentInterface), частоту (`frequency` enum daily/weekly/monthly + hour/minute/day_of_week/day_of_month), канал (`integration_uid` → `notification_integration`), получателя-override (`target`), шаблоны темы/сообщения, `enabled`, `last_run_at`/`last_status`/`last_error`/`next_run_at`, `user_uid`.
2. **Генерация + доставка** — `CallCenterReportDeliveryService`: генерирует отчёт через `runReport(schedule.user_uid, report_id, resolvedDto)` (tenant-scoped), сериализует через exporter 07-12, доставляет через канал интеграции — email вложением (расширенный `MailerService`), messenger — текстовым summary через `NotificationDispatcherService`.
3. **Планировщик** — `CallCenterReportSchedulerService` с одним `@Cron`-tick: находит `enabled` расписания c `next_run_at <= now`, обрабатывает с ресурсными лимитами, пересчитывает `next_run_at` по `frequency`.
4. **API + UI** — supervisor-gated CRUD-контроллер расписаний + run-now; RTK-эндпоинты; таб управления расписаниями на `/callcenter/settings`.

Purpose: автоматическая рассылка — прямое требование D-35 и типовая корпоративная фича КЦ (ежедневная сводка руководителю на почту, недельная статистика операторов в мессенджер). Переиспользует и генерацию отчётов (07-12), и credential store каналов (Phase 6) — без дублирования.

Output: backend модель + миграция + delivery-сервис + scheduler + CRUD-сервис/контроллер/DTO, frontend RTK-эндпоинты + компонент управления расписаниями на странице настроек.

**Формат доставки:** backend-доставка поддерживает `csv`/`xlsx` (серверно-генерируемые exporter'ами 07-12). PDF в 07-12 рендерится ТОЛЬКО на клиенте (`@react-pdf/renderer`, backend export-endpoint возвращает 400 для pdf) — поэтому scheduled backend-доставка предлагает CSV/XLSX; это документированное архитектурное следствие 07-12, а не сокрытие функциональности. `messenger`-каналы получают текстовый summary (полноценная доставка «через notification_integration»), email — файл вложением.

**Пакеты:** новые npm-пакеты НЕ ставятся (autonomous). `@nestjs/schedule` уже в зависимостях backend (используется billing-scheduler + 07-01/07-04); `ScheduleModule.forRoot()` уже зарегистрирован app-wide (`cloud-admin/billing/billing.module.ts`) — `@Cron` работает без повторной регистрации, `forRoot()` вызывать ПОВТОРНО нельзя. `exceljs` установлен в 07-12. Supply-chain checkpoint не требуется.
