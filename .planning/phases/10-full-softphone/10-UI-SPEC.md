# Phase 10 — UI Design Contract

> Visual and interaction contract for the Full Softphone (WebRTC + SIP/AMI dual-mode): chrome shell states (collapsed trigger / expanded panel / mobile sticky+sheet), Dial (dialpad, DTMF, redial, quality, devices), Journal (personal call log), Contacts (TransferDirectory + shared book), and registration/recovery UX. Generated by `gsd-ui-researcher` from locked `10-CONTEXT.md` decisions (D-01…D-35). No dedicated `/gsd-sketch` session exists for this phase — this is a brownfield extension of the `SoftphoneWidget` `variant="chrome"` shell shipped in Phase 9 (09-06/09-08); `sketch-findings-krasterisk-v4` supplies only the shared dark-admin/indigo visual language, Phase 9's own `09-UI-SPEC.md` is the direct precedent and is extended (not contradicted) here except where `10-CONTEXT.md` explicitly supersedes it (FAB variant removal, D-26).

## Spacing Scale

Declared values (multiples of 4, project-standard — identical to `09-UI-SPEC.md`, extended with Phase 10 usage):

| Token | Value | Usage in Phase 10 |
|-------|-------|-------------------|
| xs | 4px | Icon-to-label gap in directory/journal row type icons, dial input backspace gap |
| sm | 8px | Journal/Contacts row internal gaps, section-header top padding, tab row gap |
| md | 16px | Chrome expanded panel padding (existing `.panel`/`.chromePanel`), Contacts search row padding |
| lg | 24px | Vertical gap between Contacts sections (Recent / Endpoints / Queues / Groups / Book) |
| xl | 32px | — (reserved, no Phase 10 usage) |
| 2xl | 48px | — (reserved, no Phase 10 usage) |
| 3xl | 64px | — (reserved, no Phase 10 usage) |

Exceptions (all pre-existing, reused as-is — do not introduce new magic numbers):

- **44px** — minimum touch target for every icon-only control: DTMF keys, mute/hold/hangup/transfer/conference (existing `.controlsRow button { min-height: 44px }`), device-picker row buttons, Recover button, Journal/Contacts row action buttons, redial button. WCAG 2.5.5, matches Phase 9's rule exactly.
- **56px** — chrome trigger min-height/width baseline (existing `.chromeTrigger { min-width: 44px; min-height: 44px }` already satisfies this at 44px minimum; the FAB-equivalent circular affordance stays 56px only if a circular trigger variant is ever reintroduced — for chrome it is the pill trigger, 44px min is the binding rule, not 56px).
- **320px** — chrome expanded panel width (existing `.chromePanel { width: min(320px, calc(100vw - 32px)) }`) — keep this width when adding Journal/Contacts tab content; do not grow the panel to accommodate longer lists, use internal scroll instead (`max-height` + `overflow-y: auto`, see Contacts/Journal specs).
- **28px** — `CallQualityIndicator` bar height budget (existing, `10 + bar*4` per bar) — unchanged, reused identically in both the compact trigger placement and the Dial-tab detail placement (see Quality spec below).
- **12px** — `Flex`/`HStack` `gap="12"` where a KPI-style two-value pair needs breathing room (none new in Phase 10 — noted for consistency only).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-background)` `#09090b` | Chrome panel content background is inherited from `--color-card` per existing pattern (see Secondary below) — dominant applies to the page behind the panel |
| Secondary (30%) | `var(--color-card)` `#0a0a0f` + `var(--color-border)` `#27272a` | Chrome expanded panel surface (existing `.chromePanel`/`.panel`), Journal/Contacts row backgrounds, device-picker rows, section-header sticky background |
| Accent (10%) | `var(--color-primary)` `#6366f1` | **Reserved for:** chrome trigger idle/registered state (existing `.chromeTrigger`), active Tabs underline (Dial/Journal/Contacts), primary CTA buttons (Call/Позвонить, Redial/Повторить, Recover/Восстановить once registration succeeds), focused Input border in Contacts search, queue chip background tint (existing `.queueTag`) |
| Destructive | `var(--color-destructive)` `#ef4444` | Hangup, reject, offline registration state (trigger + badge), delete-contact (shared book) button, "0 free" queue/group indicator inside Contacts (reused from `TransferDirectory` `.freeDanger`), poor call quality bars |
| Warning (locked semantic) | `var(--color-warning)` `#f59e0b` (`#eab308` in existing `CallQualityIndicator` — both resolve to the warning token family; keep the existing `--color-warning` reference exactly, do not fork a second warning hex) | Registering/reconnecting state (trigger badge pulse + Dial-tab banner), degraded call quality bars, "<50% free" queue/group indicator (reused `.freeWarning`) |
| Success (existing) | `var(--color-success)` `#22c55e` | Online/registered presence dot (chrome trigger badge, endpoint BLF dot in Contacts — reused `.dotOnline`), good call quality bars, "called back successfully" tag (Journal, reused from Phase 9 History pattern) |
| Info (existing) | `var(--color-info)` `#3b82f6` | Parked-call indicator tint (unchanged from Phase 9), no new Phase 10 usage beyond consistency |

Accent must **not** bleed into: idle/offline registration states (those are destructive/muted, never accent), disabled device-picker rows, or the queue/group free-count warning/danger colors above. Registration trigger is the one new three-state color system this phase introduces, and it must reuse the exact same three tokens as the rest of the app's presence system (success/warning/destructive) — no fourth "connecting" hue.

**SIP-mode color note (D-34):** when the operator's endpoint is SIP/AMI-backed, the quality indicator and device picker are not rendered at all (not merely disabled/greyed) — there is no "SIP quality unavailable" grey state to design, the DOM nodes simply do not mount. The registration trigger for SIP mode uses the identical online=success / offline=destructive two-state mapping as WebRTC (D-35), just without the intermediate "registering" (warning) state, since AMI DeviceState/ExtensionState is binary.

## Surface Specifications

These extend the base template with the concrete, locked layout contracts per surface, derived from `10-CONTEXT.md` D-01…D-35. Executor and planner should treat this section as equally binding as the tables above. Numbering continues from `09-UI-SPEC.md`'s Surface 1-13 for cross-reference convenience but is independently scoped to Phase 10 surfaces.

### A. Softphone chrome shell states (D-26)

- **`fab` variant removed entirely** from `SoftphoneWidget` - the component's `variant` prop becomes `'chrome'`-only (delete the `'fab'` branch, `SoftphonePlacement` narrows to `'bottom-right' | 'bottom-left' | 'hidden'` used only for the deprecated placement setting's remaining chrome-adjacent meaning, or is removed if no longer referenced). No visual regression tests should reference `.fab`/`.fabWrap`/`.fabRinging` after this phase.
- **Collapsed trigger** (existing `.chromeTrigger`): add a small registration-state badge overlay (8-10px dot, absolute-positioned top-right corner of the trigger, using the three-state color system from the Color contract - success/warning/destructive). This badge is the *only* new visual element on the collapsed trigger; the existing ringing/dialing pulse behavior (`.chromeTriggerRinging`) takes visual priority over the registration badge when both would otherwise show (an active ring is always more urgent than a registration hiccup).
- **Expanded panel** (existing `.chromePanel`, 320px): gains the registration banner (Copywriting Contract) as a dismissible-on-recovery strip at the top of the panel, above the Tabs row, only rendered when status is `registering` or `offline` - never rendered when `online`/`registered` (no permanent "you are online" chrome, per Phase 7/9 precedent of only surfacing negative/transitional states).
- **Mobile sticky + sheet** (existing `.stickyBar` + `Sheet`): the sticky dot (`.stickyDot`) gains the same three-state color mapping (currently only idle/in-call/ringing) - extend with a 4th visual state for `offline`/`registering` using warning/destructive per the Color contract, reusing the existing `softphonePulse` keyframe (already respects `prefers-reduced-motion`).

### B. Dial tab (D-24, D-20, D-22, D-23)

- **Redial last number**: new button (outline, "Redial" copy above) alongside the existing dial input, enabled only when `isIdle && canDial` and a `lastNumber` exists in `sessionStorage` (D-19) - placed to the left of the existing Call button, same 44px+ height row.
- **DTMF in-call**: unchanged, existing `DtmfKeypad` component already wired into `.controlsRow`.
- **Call quality (D-20)**: compact indicator (existing `CallQualityIndicator`, 4-bar) renders inside the chrome trigger badge area *only while in a call* (small, ~16px height variant reusing the same component with a `size="compact"`-equivalent style override, not a new component) - full detail (existing tooltip content: MOS/jitter/RTT/loss) is available via the same component's existing `Tooltip`, additionally surfaced as a persistent inline row (not tooltip-only) inside the expanded Dial tab's in-call summary (`.callSummary`), directly under the caller number, at Body size (14px/400).
- **Device picker (D-22/D-23)**: new row inside the expanded Dial tab, visible whenever the panel is open (not gated to in-call state, since mid-shift switching without an active call is also in scope) - two `Select`-style rows (microphone, speaker) sourced from `useAudioDevices`. Switching while `isInCall` applies immediately (D-23); switching while idle just updates the preferred device for the next call. Failure surfaces the "Could not switch device" error copy as an inline `Text` below the picker, not a toast (keeps the error scoped to the panel that caused it).
- **SIP mode (D-34)**: both the compact quality badge and the device-picker row are omitted entirely (not rendered, not disabled) when the operator's endpoint is SIP-backed - the Dial tab in SIP mode shows only the dialpad, DTMF, redial, and call-control set (mute/hold/hangup/transfer/conference/park all routed through AMI per D-32/D-33 instead of `useWebRTCPhone`, but the *visual* row layout is byte-for-byte identical to WebRTC mode minus the two omitted rows - "same full UI" per D-31 is a hard visual requirement, not just a functional one).

### C. Journal tab (D-01…D-10)

- Replaces the current placeholder (`t('callcenter.softphone.journalSoon')`) with a live list, reusing the row visual language of `CallHistoryPanel` (direction icon + color, primary name/number at Heading, secondary timestamp/duration/tag at Body) but capped to the last N=50 (default, CC-setting-configurable) and blended (no shift/outbound/personal segment tabs - D-02 "одной лентой", one continuous feed, most-recent-first).
- Row actions (D-03, exactly two, no more): callback (reuses `PhoneCall` icon button pattern from `CallHistoryPanel`) and open-card (reuses `IdCard` icon button, same `CallCardPopup` component) - do not add a third action (no delete/archive/export in Journal, those stay in ARM History if ever needed).
- Live update (D-05): new rows prepend via SSE invalidate/patch (reuse the existing RTK Query cache-patch pattern already established for `presenceUpdate`/`agentKpiUpdate` in this codebase - `updateQueryData` prepend, not a full refetch, to avoid list-position jank).
- Footnote link (new, UX bridge): when the list is exactly at the N-row cap, render the "More in History" footnote (Copywriting Contract) as a `Text`-as-link row at the bottom, linking/scrolling to the ARM History panel tab if visible, or simply informational if History isn't reachable from the current viewport - this is the one deliberate visual seam between the two "different products" (D-01) so operators discover the fuller tool without conflating the two.

### D. Contacts tab (D-11…D-14, D-25)

- Replaces the current placeholder with a **sectioned scrollable list** inside the same 320px panel width, sections in this fixed order, each with a sticky Label-styled header (12px/600, muted-foreground, `color-mix` tinted background matching the panel surface so it stays legible while scrolling): **Недавние (Recent) → Абоненты (Endpoints) → Очереди (Queues) → Группы (Groups) → Книга (Book)**.
- A single search `Input` (reused from `TransferDirectory`'s `.searchRow`) sits above all sections and filters across all five simultaneously (D-14 "единый поиск") - matching rows stay in their section with the header retained (so operators keep spatial orientation), sections with zero matches after filtering collapse entirely (no empty "Queues (0)" header left dangling).
- **Recent** section: derived from the operator's own Journal feed (last ~5-8 distinct numbers/contacts, most-recent-first) - not a separate backend concept, purely a client-side slice of the same data source as the Journal tab, deduplicated by number.
- **Endpoints / Queues / Groups** sections: directly reuse `TransferDirectory`'s existing row rendering (presence dot / free-count chip, type icon) in `mode="call"` (D-25 - Contacts is click-to-call only, never a transfer-target picker; transfer/conference-add keep using the existing modal/Sheet entry points from the call-control row, not this tab).
- **Книга (Book)** section: new - list of shared contact-book entries (name + number + optional note), each row's CTA is click-to-call (same mechanism as the other sections). Add-contact affordance is a small "+" icon-button in the Book section header opening an inline `Sheet` form (name, number, optional note) rather than a full-page modal, matching the "compact panel" spirit of the chrome shell. Edit/delete icon-buttons appear per-row, gated by D-13 ownership (operator sees them only on rows they own; supervisor/admin see them on every row) - delete uses the destructive confirmation copy above (two variants: own contact vs. another operator's, per role).
- Click-to-call target (D-25 "≤1 клик"): the entire row is not the hit target (avoids accidental dials while scrolling) - only the existing compact CTA button pattern (`.ctaBtn`, reused from `TransferDirectory`) is clickable, exactly one tap/click from a visible row to a placed call, satisfying the ≤1-click success criterion without making the whole row a dial trigger.

### E. Registration / Recover UX (D-16…D-19, D-35)

- **WebRTC mode**: three states (online/registering/offline) map 1:1 to the Color contract's success/warning/destructive. The transition from `offline` to `registering` is automatic and silent (D-16 "тихий auto-reconnect") - no toast, no modal, only the trigger badge and (if the panel happens to be open) the banner change color/copy. The Recover button only appears in the expanded-panel banner once the auto-reconnect has been retried and failed past a timeout (research/plan owns the exact seconds value; UI contract only requires the button to be absent during the silent auto-retry window and present after it lapses).
- **SIP mode (D-35)**: two states only (online/offline, sourced from AMI DeviceState/ExtensionState) - the same badge/banner components render, simply never entering the `registering` (warning) visual state. Recover in SIP mode re-requests AMI state (labeled identically "Восстановить"/"Recover" - the operator does not need to know the transport difference, the copy is transport-agnostic by design).
- **F5 / tab-return restore (D-17)**: no dedicated loading UI is required beyond the existing `registering` state - restoring from `sessionStorage` and re-registering is visually indistinguishable from a normal reconnect, which is the intended simplicity (no special "restoring session..." copy, reuse "Registering...").

## Motion & Accessibility

- Registration badge/banner transitions and the sticky-bar 4th color state reuse the existing `softphonePulse` `@keyframes` and short (≤250ms) transitions already present in `SoftphoneWidget.module.scss` - no new easing curves or animation primitives.
- Respect `prefers-reduced-motion: reduce` for every new pulsing/animated element introduced in this phase (registration badge pulse, offline banner entrance) exactly as the existing `.fabRinging`/`.chromeTriggerRinging`/`.stickyDot` rules already do.
- All new interactive rows (Journal rows, Contacts rows, device-picker rows, Recover button, redial button) use the existing `--color-ring` focus-ring convention - no ad hoc outline colors.
- 44px minimum touch target applies without exception to every new Phase 10 control on phone, including inside the mobile `Sheet` dial/journal/contacts panel.
- Keyboard dial (existing hardware-keydown handler in `SoftphoneWidget.tsx`) must remain functional when the Journal/Contacts tab is active and the user tabs back into the Dial tab - no regression to the existing `DIALPAD_KEYS` handling when Tabs is swapped in for the tab row.
- ARIA tabs: the `shared/ui/Tabs` component (reused per Design System above) already implements the Radix `Tabs` accessibility contract (roving tabindex, `aria-selected`, `role="tablist"`/`role="tab"`) - this satisfies the phase's "ARIA tabs" success criterion without additional bespoke ARIA wiring.
