# Phase 9 — UI Design Contract

> Visual and interaction contract for the reworked Call Center Agent Panel (`CallCenterAgentPage`): softphone widget, status bar, Coworkers/Queues/Waiting tabs, smart missed-calls tool, call history, transfer directory, permissions/notifications settings, and the mobile-first rework. Generated by `gsd-ui-researcher` from locked `09-CONTEXT.md` decisions (D-01…D-46). No dedicated `/gsd-sketch` session exists for this phase — `sketch-findings-krasterisk-v4` winners (Phase 2/8) supply the **shared visual language only** (dark admin, indigo `--color-primary` accents, glass-card list pages, mobile bottom-bar pattern); this phase's own layout/IA decisions are locked in `09-CONTEXT.md`, not re-litigated here.

## Spacing Scale

Declared values (multiples of 4, project-standard):

| Token | Value | Usage in Phase 9 |
|-------|-------|-------------------|
| xs | 4px | Icon-to-label gap in chips/badges/pills, KPI counter digit-to-label gap |
| sm | 8px | Compact row gaps (coworker list row, missed-call attempt row), tab underline offset |
| md | 16px | Card padding (status bar, panel cards, softphone widget body), tab row horizontal padding |
| lg | 24px | Section spacing between stacked panels on desktop (Coworkers / Queues / Waiting when shown side-by-side) |
| xl | 32px | Page-level top margin under the status bar on desktop |
| 2xl | 48px | — (reserved, no Phase 9 usage) |
| 3xl | 64px | — (reserved, no Phase 9 usage) |

Exceptions:
- **56px** — softphone widget FAB expanded-panel width baseline and status-bar minimum height (matches existing `.statusBar { min-height: 56px }` from Phase 7/8 — keep this value, do not shrink it).
- **44px** — minimum touch target for all icon-only call-control buttons (hangup/mute/hold/DTMF/transfer/spy/park/conference/zombie-reset), FAB itself, and every row action button on phone (WCAG 2.5.5). Reuse the existing `.callActions button { min-height: 44px }` pattern.
- **60px** — mobile bottom nav height + softphone sticky bar budget is structural chrome (Phase 8 precedent `$bottom-nav-height`/`$softphone-bar-height` in `CallCenterAgentPage.module.scss`) — not a spacing token, hardcode per-component as already done.
- **12px** — allowed for `HStack`/`Flex` `gap="12"` inside status bar rows and KPI counter groups (existing `Flex` `FlexGap` enum).

## Surface Specifications

These extend the base template with the concrete, locked layout contracts per surface, derived from `09-CONTEXT.md` D-01…D-46. Executor and planner should treat this section as equally binding as the tables above.

### 1. Status bar (redesigned, replaces current `.statusBar`)

- Height: **56px minimum**, same shell as today (`--color-card`, `1px` border, `--radius-xl`).
- Left-to-right order: status pill (dot + label, D-13 full status set) → agent name + extension → live status timer (D-14, `mm:ss` since last status change, tabular-nums) → queue chips (desktop only, hidden on phone per existing `!isMobile` guard).
- Right side: KPI counter group (D-11/D-12) - three Label-sized counters **принял / совершил / пропустил** ("Answered / Made / Missed"), each showing **two numbers** "shift · day" (D-11) e.g. `12 · 34`, separated by `·` not `/`. Session timer and connection dot remain where they are today.
- Active-call indicator (D-14 "максимально информативный"): when in a call, the status pill area is replaced by a compact inline summary - `queue name` (if from queue) or `Личный`/`Исходящий` (personal/outbound) + caller number/name. This is the *compact* version; the full version lives in the call window (Surface 2).
- Call controls in the bar (D-03): only the 3-4 most-used actions render inline in the status bar during an active call - Mute, Hold, Transfer, Hangup (icon+label ≥ 768px, icon-only with tooltip < 768px, 44px touch target). Everything else (DTMF, conference, park, zombie-reset, warm-transfer-to-queue) lives in the call window/widget only, not duplicated in the bar.

### 2. Softphone widget (D-01) - floating FAB, not a dominant card

- Collapsed state: circular **56px FAB**, fixed bottom-right, `--color-primary` background when idle/ready, switches to destructive-tinted pulse when ringing (reuse `@keyframes pulse` from existing `.connectionOffline`/`.statusDot`), z-index uses `var(--z-index-toast)` tier (100) so it always sits above content but the incoming-call toast (Surface 3) sits at the same or higher layer, not blocked by it.
- Expanded state: FAB click opens a `Sheet` (phone) or anchored `Popover`-style panel (desktop, ~320px wide) containing dialpad (reuse existing `DtmfKeypad`), current call summary if any, and the full call-control set from Surface 2 when in a call.
- Per-operator placement setting (D-01/D-05): position choices are **bottom-right** (default) and **bottom-left** only for MVP - do not build a full drag-to-reposition system (that is the deferred drag/resize dashboard). Persist as a simple enum in `operator_settings`.
- Visibility toggle: operator/admin can hide the widget entirely if the operator prefers status-bar-only controls (D-01) - when hidden, all call-control actions still surface via the status bar (Surface 1) and call window (Surface 3), never orphaned.
- On phone, the widget collapses into the existing sticky softphone bar pattern from Phase 8 (`.softphoneSticky`, pinned above the bottom nav) rather than floating independently - do not stack two floating elements on small screens.

### 3. Incoming call window (D-02) - slide-in toast, non-blocking

- Presentation: slide-in from top-right (desktop) / top (phone), non-modal - underlying tabs/lists remain fully interactive and visible, no backdrop/overlay.
- Content: caller number/name (Display-adjacent size, ~20-24px, one step below the in-call Display token since this is a preview not the main focus yet) + queue/personal/outbound context tag + Answer (accent, primary) / Reject (destructive, secondary) buttons, both ≥44px touch target.
- Auto-dismiss: only on answer, reject, or the call ending upstream (abandoned/timeout) - never a fixed auto-hide timer that could hide an unanswered ring.
- Once answered, the toast promotes into the full call window/widget state (Surface 2) - it does not stay as a second parallel surface.

### 4. Layout / IA - hybrid tabs and panels (D-04)

- Breakpoint: reuse the existing `useIsMobile(768)` hook, consistent with Phase 7/8.
- **Wide (≥1024px):** Coworkers / Queues / Waiting render as **panels side-by-side** (3-column grid, each panel independently scrollable, min column width ~280px, `gap: 16px`) with per-panel visibility toggle (D-05) - a hidden panel simply collapses its column, remaining panels reflow to fill the space (do not leave empty gutters).
- **Narrow (1024px down to 768px):** panels stack into a single scrollable column (existing `zoneMain` single-column fallback at `max-width: 1024px` is the right base to extend, not replace).
- **Phone (<768px):** panels become the new **Tabs** component (Surface spec above) with three tabs - Коллеги / Очереди / Текущие (labels: "Coworkers" / "Queues" / "Waiting"). This replaces today's ad hoc `mobileSection` button row 1:1, same three destinations, just backed by the shared Tabs primitive.
- Default tab on entry (D-07, Claude's discretion locked here): **Waiting** - it is the most actionable "what needs me right now" view and matches the existing default (`mobileSection === 'call'` today maps conceptually to "what's happening now"). Do not persist "remember last tab" for MVP - that adds state-sync complexity for a first pass; static default is the locked answer.
- Call window/widget (Surfaces 2-3) is layered above/alongside the tabs on every breakpoint, never one of the three tabs itself - it is not tab content, it is persistent chrome.

### 5. Coworkers tab

- Row: presence dot (success=online/READY, warning=paused, destructive-tint=in-call/busy, muted=offline - reuse `.transferItemOnline/.transferItemBusy/.transferItemOffline` dot pattern) + name (Heading 16/600) + extension (Body 14/400 muted) + status label (Label 12/600).
- Actions per row (only when relevant/permitted, D-21…D-24): click-to-transfer during an active call (drag or click, reuse existing `DragTransfer`), ChanSpy trigger (icon button, only if `can_spy` true and target `spyable` true) opening a small mode picker (`SegmentedControl`: Listen / Whisper / Barge - Whisper/Barge dimmed/disabled with tooltip if the operator's `spy_modes` right doesn't include them), hangup icon (destructive, only for supervisor+ scope, D-25/D-26).
- ChanSpy privacy (D-24): starting Listen mode shows no visible indicator to the target agent's row for other viewers (quiet by design) - only an audit-log entry is written server-side, not a UI toast to bystanders.

### 6. Queues tab

- Row/card per queue (D-31): queue name (Heading) + aggregate line (waiting / talking / SLA%, Body 14/400) + free-operators count with **warning if <50% free, danger(destructive) if 0 free** (locked thresholds from Specific Ideas) + personal per-queue answered/missed counters (shift · day, same `12 · 34` format as the status bar).
- Actions row per queue: pause/unpause this queue only, join/leave (if permitted), "go to Waiting for this queue" (deep-link into the Waiting tab pre-filtered), and - only visible during an active call - "transfer active call to this queue" (D-33, warm-transfer-to-queue, uses the Primary CTA copy above).

### 7. Waiting tab

- Table/list of queue-waiting calls (reuse existing `queueTable` visual pattern - status badge, caller, queue, wait timer with warning/danger thresholds already implemented at 30s/60s) filtered to the operator's queues.
- Pick action (D-18/D-19 precedent, existing `pickup_enabled`): "Подобрать"/"Pick" button, disabled with the locked error-state copy above when the operator isn't READY in that specific queue.
- No separate empty state per queue - a single tab-level empty state (Copywriting Contract) when zero rows across all queues.

### 8. Smart missed-calls module (D-16…D-20)

- Grouped-by-number row (D-16): one row per distinct number - attempt count badge (Label, muted background) + time of most recent attempt (Body, relative e.g. "5 мин назад"/"5 min ago") + expandable attempt history (click row → inline list of individual attempt timestamps, no separate modal needed for MVP).
- Ownership tag (D-19): **Личный/Personal** tag (Label, primary-tint background) on personal/internal-direct entries; queue-missed entries show the queue name chip instead and a **claim** action button (first operator to claim removes it from the shared pool - optimistic UI, server is source of truth on conflict).
- Auto-resolved entries (D-17): when a number calls back and is answered, the row auto-removes from the active list but is retained in a "resolved" sub-view/filter with the **"Клиент перезвонил сам"/"Client called back"** tag (Success-tinted, not a plain muted tag - this is a positive outcome, visually distinct from "called back by operator").
- Callback action (D-18): "Перезвонить"/"Call back" button per row - success (>5s connected) marks the row `called_back` (Success tag, distinct copy from the auto-resolved tag: e.g. "Дозвонились" vs "Клиент перезвонил сам"); failure/<5s leaves the row in the active list with an incremented "attempt" count and a small inline error using the locked error-state copy.
- Exclusion (D-20): in-queue ring-no-answer never appears in this module - this is enforced by data scope (`cc_call_history`/`missed-call` model filtering), not a UI filter toggle, so there is nothing to visually hide/show for it.
- Badge on the tool's entry point (status bar or nav icon): warning-tinted count badge that includes unclaimed queue-missed count > 0 (per Color contract above); personal-missed count alone does not need the warning tint if zero queue-missed exist - only escalate the badge color when the *shared-pool* count is non-zero, since that's the "someone needs to act" signal.

### 9. Call-control set additions (D-28/D-29)

- **Zombie-call reset**: destructive-styled button, always requires the "reset zombie call" confirmation dialog above (D-27 lets the operator self-serve this, no supervisor gate) - only rendered when a call is detected as stuck (no channel activity beyond a defined threshold; exact detection heuristic is a backend/research concern, not this spec's).
- **Warm transfer to queue**: lives in both the call window/widget call-control row and the Queues tab (Surface 6) - same action, two entry points, must produce identical confirmation-free behavior (it's non-destructive, just a routing change).
- **Conference (3-way, ConfBridge)**: "Add to conference" call-control button opens the existing transfer-directory pattern (Surface 10) in "add" mode instead of "replace" mode - reuse the directory UI, just change the resulting action and the button's contextual label to "Добавить в конференцию"/"Add to conference".
- **Park/retrieve**: "Park" button (call-control row) + a small "Parked calls" indicator/list (badge with count, similar treatment to the missed-calls badge but using `--color-info` tint since parking is a neutral/informational state, not a warning) with a "Retrieve" action per parked entry.
- **Client-aware click-to-call** (D-29): entry points are the transfer directory (Surface 10, click a number/contact) and the call history panel (Surface 11, click-to-callback) - both route through the same Primary CTA copy ("Позвонить"/"Call") and the same WebRTC-direct-vs-PJSIP-originate branching already used for missed-call callback (D-18), no separate visual treatment needed since the underlying mechanism is identical.

### 10. Transfer directory (D-36/D-37)

- Unified searchable list (reuse `shared/ui/Input` + filtered list pattern, not a new search component) mixing three entity types in one scrollable list, each visually distinguished only by a small type icon (Users icon = internal endpoint, List icon = queue, UsersRound icon = call group - all `lucide-react`, no new icon set): name, extension/identifier, and a presence indicator.
- Presence (D-37): endpoints show a BLF dot (success=idle/available, destructive-tint=busy, muted=offline/unknown) sourced from AMI DeviceState/ExtensionState via SSE; queues/groups show "N свободно"/"N free" text instead of a dot (matches the Queues tab's free-operator convention, including the same warning/danger thresholds).
- Used both as the transfer target picker (existing transfer-modal pattern, kept) and as the conference "add" picker (Surface 9) and the click-to-call entry point (Surface 9) - one component, three call sites, avoid three bespoke pickers.

### 11. Call history panel (D-34/D-35)

- Chronological list (reverse order, most recent first) scoped to the operator's current shift by default with a day-filter toggle (`SegmentedControl`: "Смена"/"Shift" vs "День"/"Day", matching the shift-vs-day period convention used everywhere else in this phase per D-32).
- Row: direction icon (inbound/outbound/personal/missed - four distinct `lucide-react` icons, e.g. `PhoneIncoming`/`PhoneOutgoing`/`Phone`/`PhoneMissed`, colored via existing success/muted/destructive-tint per outcome, not a 5th palette color) + number/name + queue tag (if applicable) + timestamp + duration.
- Row actions: click-to-callback (Surface 9 mechanism) and "open call card" (reuses existing `CallCardPopup` open-manually pattern already in the codebase) - no new card viewer needed.

### 12. UI customization + permissions + notifications settings

- **Visibility/placement settings** (D-05/D-06): two entry points - a per-operator "My panel" settings section (simple toggle list: show/hide Coworkers panel, Queues panel, Waiting panel, softphone widget position) and an admin/supervisor "role defaults" screen (same toggle list, applied as the default + an optional lock-per-item so operators can't override that specific one). Reuse `shared/ui/Switch` rows, not a drag/resize builder (explicitly out of scope).
- **Granular permissions** (D-38/D-39/D-40): both UI shapes required - (a) a bulk matrix table (operators × rights: `can_spy`, `spyable`, `spy_modes`, `click_to_call`, `customize_ui`, etc. - reuse `shared/ui/DataTable` with `Switch`/`Select` cells) and (b) a per-operator modal (reuse the existing `AgentDetailModal`/`OperatorSettingsForm` visual pattern - card sections with the same rights as switches/selects). Any right revocation that could interrupt an in-progress capability (e.g. revoking `can_spy` while mid-session) uses the destructive confirmation copy above.
- **Notification matrix** (D-41/D-42/D-43): table with events as rows (incoming call, missed call, new pool missed call, chat message, "connected to your call"/whisper-barge, optional SLA/threshold alert) and three channel columns - Чат/Chat, Звук/Sound, Всплывающее окно/Popup (column headers from Copywriting Contract) - each cell a `Switch`. Config surfaces both per-operator (own settings) and role-default/lock, same pattern as visibility settings above - do not build two different table shapes for these two settings screens, reuse one row/column/lock pattern for both.

### 13. Mobile-first rework (D-46)

- Base shell: reuse Phase 8's sticky-softphone-above-bottom-nav budget (`$bottom-nav-height` + `$softphone-bar-height`) as the starting point, do not redesign the bottom-chrome stacking math from scratch.
- Tabs (Surface 4) are the primary phone navigation within the page; the page-level bottom nav (Hub/PBX/Apps/System/More, Phase 8) remains untouched below them - two navigation layers (page tabs above, app bottom-nav below) is the accepted pattern, already proven by Phase 8's own CC-agent flag ("stacked tabs/sections with a sticky softphone control bar").
- Every table-like surface (Waiting, Queues aggregate rows, Call history, Transfer directory) uses the existing responsive convention from ARCHITECTURE - card rows on phone for primary data, `overflow-x-auto` horizontal scroll only for secondary/detail tables (attempt-history expansion, permissions matrix) that don't have a natural card form.
- All call-control buttons maintain the 44px touch target rule on phone without exception, including inside the softphone widget's expanded `Sheet` state.

## Motion & Accessibility

- Incoming-call toast slide-in and FAB ring-pulse: short transitions (≤250ms), reuse the existing `motion`/CSS-keyframe conventions already in `CallCenterAgentPage.module.scss` (`@keyframes pulse`, `fadeIn`, `modalIn`) rather than inventing new easing curves.
