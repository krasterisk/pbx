## Исправления

- **P1 / подтверждение AI:** атомарное владение pending-предложением. Конкурентное подтверждение/отклонение не забирает активный claim. После записи сохраняется серверный checkpoint; повтор после ошибки reload выполняет только reload. Payload модели не может подделать checkpoint. Неопределённый результат записи блокирует автоматический повтор до сверки оператором.
- **P1 / JWT:** удалён известный fallback; явный JWT_SECRET минимум 32 символа обязателен для выдачи и проверки токенов.

- **Найдено живым прогоном:** сборщик LLM-stream терял повторяющиеся JSON-токены/вложенные скобки. Исправлено; регрессия проверяет передачу вложенного workflow по одному символу.
- Актуализированы устаревшие тестовые контракты, переводы справочников, ошибки TypeScript и RTK mutation isLoading. Vitest использует threads и два worker, тестовый запуск явно выбирает vite.config.ts.

## Оставшиеся границы и эксплуатация

- Перед обычным запуском обновлённого backend задать случайный JWT_SECRET минимум 32 символа. Смена секрета инвалидирует старые токены.
- При write_failed с сохранённым claim **не очищать applied_at вслепую**. Сверить domain-запись и аудит. Если запись выполнена — восстановить её серверный checkpoint/reload target; если доказано отсутствие записи — отдельно разрешить повтор. Это сознательная блокировка неоднозначного побочного эффекта, а не автоматическое exactly-once для всех доменов.
- Baseline предназначен для пустой БД. Существующая неверсионированная схема отказана runner; перенос legacy требует отдельного сравнения схемы. DDL MySQL не транзакционен.
- UAT phase 11: восемь старых live-проверок пропущены; phase 16.3: staff WebRTC/microphone остаётся blocked. Эти сценарии не закрываются тестами маршрута/Local.
- Phase 17.x: код присутствует, но полнота требований и live acceptance не подтверждены полным комплектом планов/summary/verification. Roadmap отражает этот разрыв.
